Phạm vi tài liệu

  1. Mixin tạo thêm lớp nào trong chuỗi kế thừa?
  2. Nếu hai mixin cùng có một method, super quyết định thứ tự chạy ra sao?
  3. Khi chuyển từ Polymer sang Lit, phần nào giữ nguyên và phần nào phải kiểm tra lại?

Không cần nhớ nhiều cú pháp. Cần hiểu rõ lớp nào đang chạy và framework cập nhật state vào lúc nào.

Bài toán: nhiều element cần cùng một khả năng

my-panel

Hiển thị hoặc ẩn nội dung.

opened, open(), close(), toggle()

my-dropdown

Hiển thị hoặc ẩn danh sách lựa chọn.

opened, open(), close(), toggle()

Không nên sao chép toàn bộ logic mở/đóng vào từng component. Mixin đóng gói khả năng dùng chung này thành một lớp tái sử dụng.

Mixin là gì?

Một hàm nhận lớp cơ sở và trả về lớp con đã được bổ sung chức năng.

const OpenableMixin = (Base) => class extends Base {
  open()   { this.opened = true; }
  close()  { this.opened = false; }
  toggle() { this.opened = !this.opened; }
};

Mixin tạo một lớp trung gian

class MyPanel extends OpenableMixin(HTMLElement) {}

Không có method nào được sao chép vào MyPanel. JavaScript tạo một lớp con tạm thời rồi cho MyPanel kế thừa từ lớp đó.

MyPanel → OpenableMixinImpl → HTMLElement

Hệ quả: đây là quan hệ kế thừa thật, nên super hoạt động bình thường.

Xếp chồng nhiều mixin

class MyPanel extends DisableableMixin(
  OpenableMixin(HTMLElement)
) {}

MyPanel → DisableableMixinImpl → OpenableMixinImpl → HTMLElement

Lời gọi được đọc từ trong ra ngoài: OpenableMixin áp dụng trước, sau đó tới DisableableMixin. Khi trùng tên method, lớp gần MyPanel hơn được tìm thấy trước.

super cho phép mở rộng thay vì thay thế

const DisableableMixin = (Base) => class extends Base {
  toggle() {
    if (this.disabled) return;
    super.toggle();
  }
};
  1. DisableableMixin.toggle() chạy trước.
  2. Nếu element đang disabled, method kết thúc.
  3. Nếu không, super.toggle() gọi OpenableMixin.toggle().

Mixin này có một hợp đồng: lớp phía dưới phải cung cấp toggle().

Hai loại thứ tự cần phân biệt

Constructor

class X extends A(B(Base)) {}

Base → B → A → X

Luôn chạy từ lớp cơ sở lên lớp cuối vì constructor phải gọi super() trước khi dùng this.

Method thông thường

action() {
  // code trước super
  super.action();
  // code sau super
}

Thứ tự do vị trí của super quyết định.

Override lifecycle: luôn kiểm tra super

connectedCallback() {
  super.connectedCallback();
  // phần việc của mixin
}

Nếu quên super, implementation của các lớp phía dưới không chạy. Với Polymer hoặc Lit, lỗi này thường khó truy nguyên vì nguyên nhân nằm ở một lớp trung gian.

Polymer yêu cầu gọi lifecycle của lớp cha ở đầu callback. Với Lit, callback chuẩn của custom element cũng phải gọi super; vị trí lời gọi quyết định thứ tự các lớp trong chain.

Khi nào cần deduping?

class Parent extends LoggerMixin(HTMLElement) {}
class Child extends LoggerMixin(Parent) {}

Chuỗi của Child có thể chứa hai lớp do LoggerMixin tạo ra. Nếu mixin đăng ký listener hoặc override lifecycle, logic có thể chạy hai lần.

POLYMER

Dùng helper có sẵn dedupingMixin khi mixin có thể đi vào chain qua nhiều đường.

LIT

Không có helper tích hợp. Chỉ tự thiết kế dedupe khi kiến trúc thực sự có nguy cơ áp dụng lặp.

Mixin trong Polymer

POLYMER 3 
export const OpenableMixin = dedupingMixin((Base) => {
  class OpenableMixinImpl extends Base {
    static get properties() {
      return {
        opened: {
          type: Boolean,
          value: false,
          reflectToAttribute: true,
        },
      };
    }
    toggle() { this.opened = !this.opened; }
  }
  return OpenableMixinImpl;
});

Property khai báo trong mixin được Polymer xử lý như property của element. Template và CSS của lớp cuối vẫn dùng được opened, ví dụ :host([opened]).

Lifecycle trong Polymer

HookÝ nghĩa
connectedCallback()Có thể chạy nhiều lần; đăng ký tài nguyên gắn với document.
disconnectedCallback()Có thể chạy nhiều lần; gỡ tài nguyên đã tạo lúc connect.
ready()Chạy một lần khi Polymer khởi tạo element lần đầu; sau super.ready(), template và data system sẵn sàng.

Không dùng ready() cho listener trên document. Listener kiểu này cần cặp connectedCallback() và disconnectedCallback().

Behavior legacy: chỉ cần nhận diện

const OpenableBehavior = {
  properties: {opened: {type: Boolean, value: false}},
  toggle() { this.opened = !this.opened; },
};

Behavior là object cấu hình. Polymer có thể gộp properties và một số lifecycle callback, nhưng Behavior không phải lớp trong chuỗi kế thừa.

Nếu hai Behavior có cùng method thông thường, không có super để nối hai implementation. Đọc để bảo trì mã cũ; ưu tiên class mixin cho mã mới.

Mixin trong Lit

LIT 
const OpenableMixin = (Base) => class extends Base {
  static properties = {
    opened: {type: Boolean, reflect: true},
  };

  constructor() {
    super();
    this.opened = false;
  }

  toggle() { this.opened = !this.opened; }
};

Lit kế thừa cấu hình reactive property từ lớp cha. Giá trị mặc định thường được gán trong constructor sau super().

Lit cập nhật theo chu kỳ bất đồng bộ

property thay đổi → willUpdate → render → updated → updateComplete

  • Lit gom các thay đổi trước khi update bắt đầu.
  • willUpdate() phù hợp để tính dữ liệu cho lần render sắp tới.
  • updated() phù hợp khi cần DOM sau render.
  • Gán reactive property trong updated() sẽ tạo một vòng update tiếp theo.
async openAndFocus() {
  this.opened = true;
  await this.updateComplete;
  this.renderRoot.querySelector('button')?.focus();
}

ReactiveController: composition thay vì inheritance

Mixin

Trở thành một phần của prototype chain.

Phù hợp khi feature cần API công khai hoặc cần kiểm soát thứ tự super.

ReactiveController

Là object được host sở hữu qua addController().

Phù hợp cho listener, timer, observer và state nội bộ.

class ClickOutsideController {
  constructor(host, onOutsideClick) {
    this.host = host;
    this.onOutsideClick = onOutsideClick;
    host.addController(this);
  }
  // hostConnected / hostDisconnected ...
}

Chọn mixin hay controller?

Nhu cầuLựa chọn thường phù hợp

Chỉ có listener, timer, ResizeObserver, state nội bộReactiveController
Cần nhiều instance độc lập trong một elementReactiveController

Checklist khi chuyển một mixin

  1. Liệt kê API công khai: property, method, event, attribute và CSS contract.
  2. Chuyển property, giá trị mặc định và attribute reflection.
  3. Phân loại computed và observer theo getter, willUpdate hoặc updated.
  4. Rà cập nhật object/array và đoạn code đọc DOM sau khi set property.
  5. Rà lifecycle, super và khả năng mixin xuất hiện hai lần trong chain.
  6. Viết test cho hành vi công khai, connect/disconnect và thứ tự override.

Ba ý cần nhớ

1. Mixin là lớp trung gian trong prototype chain; vì vậy super quyết định cách các lớp phối hợp.

2. Polymer và Lit dùng cùng cơ chế mixin JavaScript, nhưng khác reactive system và thời điểm DOM cập nhật.

3. Với Lit, ưu tiên controller cho logic nội bộ; dùng mixin khi cần API công khai hoặc kiểm soát inheritance chain.

Bài toán gốc

Hai component WebUI khác nhau, cùng cần khả năng mở/đóng.

class MyPanel extends PolymerElement {
  static get properties() {
    return {

Behaviors hỏng ở đâu

Polymer 1 gom method vào một object thường. Nghe hợp lý, cho tới lúc trùng tên.

const OpenableBehavior   = { toggle() { /* mở/đóng */ } };
const DisableableBehavior = { toggle() { /* kiểm tra disabled rồi mở/đóng */ } };

Polymer({
  is: 'my-panel',
  behaviors: [OpenableBehavior, DisableableBehavior],
});

// panel.toggle() → chỉ chạy bản của DisableableBehavior.
// Bản của OpenableBehavior BIẾN MẤT. Không một lời cảnh báo.

Vấn đề gốc

DisableableBehavior muốn "kiểm tra disabled rồi gọi tiếp bản gốc" — nhưng nó là object thường, không nằm trong chuỗi kế thừa nào, nên không có super để gọi.

Cùng vấn đề với…

Object.assign(MyPanel.prototype, behavior) — cách "mixin cổ điển" thời jQuery. Đó là ghi đè phẳng: không có khái niệm "chạy tiếp cái trước đó".

Định nghĩa

Mixin là một hàm nhận vào một class và trả về một class con mới của nó, đã được bổ sung tính năng.

export const OpenableMixin = dedupingMixin((superClass) => {
  class OpenableMixinImpl extends superClass {
    static get properties() {
      return {opened: {type: Boolean, value: false,
                       reflectToAttribute: true}};
    }
    toggle() { this.opened = !this.opened; }
    open()   { this.opened = true; }
    close()  { this.opened = false; }
  }
  return OpenableMixinImpl;
});

class MyPanel extends OpenableMixin(PolymerElement) { }

Bug tốn thời gian nhất: quên super

const M = (Base) => class extends Base {
  connectedCallback() {
    console.log('M chạy');
    // quên super.connectedCallback()
  }
};

Mọi thứ nằm dưới M trong chuỗi đều không chạy.

Với Lit: element không bao giờ render. Màn hình trắng. Không có lỗi nào được ném ra.

Thói quen: viết super.x() trước khi viết thân hàm. Luôn luôn, mọi lifecycle method.

Bài toán kim cương

Nhớ lại: mỗi lần gọi mixin sinh ra một class mới. M(Base) !== M(Base)

class Parent extends LoggerMixin(Base) { }
class Child  extends LoggerMixin(Parent) { }
                     ↑ áp lần 2

Child → Logger#2 → Parent → Logger#1 → Base
         ▲                    ▲
         └── cùng 1 mixin, 2 bản ──┘

Số liệu đo thật

áp 1 lần → ctor chạy 1 lần
áp 2 lần → ctor chạy 2 lần

Listener đăng ký 2 lần. Handler chạy 2 lần. Counter tăng gấp đôi.

Code trông hoàn toàn hợp lý → rất khó lần ra.

Chữa deduping — cần hai phần

function dedupeMixin(mixin) {
  const cache  = new WeakMap();
  const marker = Symbol('mixin-applied');

  return (Base) => {
    if (Base[marker]) return Base;                 // (2) chuỗi đã có → không bọc thêm
    if (cache.has(Base)) return cache.get(Base);   // (1) đã áp lên Base này → dùng lại

    const Klass = mixin(Base);
    Object.defineProperty(Klass, marker, {value: true}); // static → class con kế thừa dấu
    cache.set(Base, Klass);
    return Klass;
  };
}

ReactiveController — cách làm "đúng Lit"

class ClickOutsideController {
  constructor(host, khiRaNgoai) {
    this.host = host;
    this.khiRaNgoai = khiRaNgoai;
    host.addController(this);
  }
  hostConnected() {
    this.xuLy_ = (e) => {
      if (!e.composedPath().includes(this.host))
        this.khiRaNgoai();
    };
    document.addEventListener('click', this.xuLy_);
  }
  hostDisconnected() {
    document.removeEventListener('click', this.xuLy_);
  }
}

class MyPanel extends OpenableMixin(LitElement) {
  ngoai = new ClickOutsideController(this, () => this.close());
}

Mixin cho opened, toggle(), close() — thứ phải nằm trên chính element, vì template và component cha gọi panel.close().

Migrate: 7 bước

1. dedupingMixin của Polymer      →  dedupeMixin tự viết (WeakMap + dấu)
2. static get properties()        →  static properties = {...}
3. value: X                       →  gán this.x = X trong constructor
4. reflectToAttribute             →  reflect
5. readOnly + this._setX()        →  getter + #private + requestUpdate()
6. ready()                        →  connectedCallback()  (thường đúng hơn firstUpdated)
7. computed / observers           →  getter / willUpdate() / updated()

Rồi rà 3 bẫy

☐ Đọc DOM ngay sau khi set property? → thêm await this.updateComplete

☐ Dùng this.set('a.b', v)? → gán object mới: this.a = {...this.a, b: v}

☐ Property nào notify: true? → thêm dispatchEvent thủ công

Mang về ba điều

1. Mixin không copy method — nó chèn một mắt xích vào prototype chain.

Mọi hành vi, mọi bug, mọi khác biệt giữa hai framework đều suy ra được từ câu này.

2. Khái niệm mixin không đổi khi lên Lit. Chỉ đổi 3 thứ.

Khai báo property · tên hook lifecycle · tự lo deduping. Phần khó thật sự là đồng bộ → bất đồng bộ.

3. Ở Lit, hỏi trước: cái này có nên là ReactiveController không?

Thường là có. Chỉ dùng mixin khi cần thêm API lên chính element.

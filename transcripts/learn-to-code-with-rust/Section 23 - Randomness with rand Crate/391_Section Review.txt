Congratulations on reaching the end of another course section. As always, let's take a few moments to review everything that we learned. This section focused on randomness using the Rand Crate. The Rand Library crate generates random values. It is one of more than 180,000 available crates that you can find on Crates.io, and is the community standard in rust for randomness. So first step, we open up our cargo.toml file within our project, and we add Rand as the dependency with the version number just like any other crate. And then the very first time you compile your program, rust is going to download the specified crates and compile them with your source code. And then the Rand crates code is available locally and then doesn't need to be downloaded again unless you clear all the content with something like a cargo clean command. Otherwise, it's just going to remain locally and compile alongside your code. So first step we introduced the random function, which is your basic bread and butter function for generating a random value. You do need to provide it with a type annotation that dictates the type of the data that you're going to generate. You can generate floating point values. You can generate integers. In fact, all of the available types for those categories of floats and integers will also influence the kind of value you're going to get, because you're going to add constraints to the lower and upper bounds of what the value could be. So a U8, for example, has a much smaller range of possible values than a u32. So the type that you provide, either using the variable annotation or the turbo operator, will influence the kind of data the random function is going to give you. All right. So that random function is great when you just want a single one off random value. Whenever you want to create multiple random values in sequence. It's ideal for efficiency to use a random number generator or an RNG. For that, you can bring in the RNG function from the rand crate, and that will return a thread rng struct, which is that random number generator. Now that RNG must be declared as mutable, because each time it's going to be generating some random value, it's going to be updating some part of its internal state. We don't have to worry about that complexity, but it is a requirement in order to use that random number generator. So don't forget to do that. So once you have that RNG, you can invoke a whole bunch of methods on it. In fact, the random function that we just talked about creates that RNG behind the scenes automatically, implicitly. Now, many of those rngs methods are going to depend on the RNG trait being in the module scope. It's a little bit confusing because we have the all lowercase rng function, which returns the actual random number generator. And then we have the complementary RNG trait starting with the capital R. Remember, if you are invoking a method on a type and that method is the result of that type implementing a given trait, that trait must be within the file scope in order to utilize that method. And the reason that is the case is just for efficiency, so that the compiler does not have to include all that extra functionality within the bundle within the executable until we explicitly declare that it is needed both with the actual invocation of the method and with the trait that kind of made it so, or that made that method a required thing, or enabled it to exist on that given type. All right. So here is a bunch of methods that are available on the actual RNG struct. We have the random method itself which is equivalent to the random function. That is just your basic random integer or floating point value. We have the random range method which allows us to return a random value that falls within a given range or interval. We pass in a range type into that method. We get back a random number from that interval. We also took a look at the random bool method, which returns a random boolean either true or false, and the method accepts a floating point argument that represents the percentage chance of getting a true. So if you pass in 0.5 or equivalently 50%, then you have a 5050 chance of getting a true or a false. If you pass in 0.9, then you have a 90% chance of getting a true from that method. And then we have the complementary random ratio method, which also returns a random boolean, but that accepts two arguments both integers representing the proportional rate or probability of something happening. So if you want to model, for example, a 18 and 29 chance, you can pass in those two arguments 18 and 29 as the two consecutive arguments to random ratio. It's going to give you back a boolean based on those probabilities. Finally, we talked about randomizing the order of elements within a collection type, like a vector or an array. That is accomplished with the shuffle method. And to that method you need to pass a mutable reference to a random number generator. So first you can generate that RNG using something like the rng function. Then you declare it as mutable, and then you pass in the mutable reference to that RNG, to the shuffle method that's going to mutate the underlying collection type, which must also be marked as mutable. And then all of the elements within it are going to be again distributed in a random order. Now, in order for this behavior to be possible, you need to bring in another trait, which is the slice random trait, and that is found a little bit deeper within the rand trait inside the seq submodule. All right. That's all there is to cover in this lesson and in this section. Hope you had fun and I will see you in the next one.

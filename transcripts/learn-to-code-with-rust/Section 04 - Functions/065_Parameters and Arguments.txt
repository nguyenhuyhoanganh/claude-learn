# Parameters and Arguments

In this lesson, we'll learn how to define function parameters. A parameter is a name for an expected input to a function. An input represents some data that is going to be flowing into the function when the function is invoked. The caller, which is the point in the code that is invoking the function, that caller is required to pass in a concrete value for the parameter, for that expected input. Now, the technical term for the concrete value passed in at invocation is the argument. So the parameter is the name of an expected input, and the argument is the concrete value that is actually being utilized. Now, we've previously explored these ideas with methods that we invoked on Rust types. When we pass in values inside parentheses, when we invoke a method, we are providing arguments. We are passing in concrete values for that method's defined parameters. So let's take a look at how we can define our own parameters. Let's begin with our open_store function. Right now there are no parameters, and thus the function operates the exact same way each time. We can add some custom behavior to this function. Let's say that we want to be able to provide a string to the open_store function, representing the neighborhood in which we are opening our pizza store. That way, we can keep invoking open_store with different neighborhoods to represent the opening of different stores. So here, within my parentheses, this is where I declare all of my parameters. To declare a parameter, we need to choose a name, and then we need to provide an associated type. So these names are up to me. I'm going to choose a parameter name of 'neighborhood' after my name. I'll provide a colon and a space. And now I have to provide the type. What kind of data will 'neighborhood' be? I want 'neighborhood' to be a string and remember the type for that in Rust is this syntax. It's the &str Once again we're going to cover this in greater depth later. But this means we are expecting a string literal in double quotes. So now we have one parameter called 'neighborhood'. And we can treat that like a variable that now belongs to the function that can be used within the function's body. So anywhere between the opening and closing brace, I'm welcome to use neighborhood how I want to. So right here, within our string, let's interpolate the value of my 'neighborhood' parameter. So we'll add in and then interpolate 'neighborhood' right here. You'll notice, as soon as I save my file, we're going to get this violation right here. open_store says "You are missing the required argument". You declared that the open_store function accepts one parameter called neighborhood. It needs one piece of data in order to be able to do its job, and that is missing at the caller, at the point where the open_store function is being invoked. So of course we can provide our argument right here. The parameter is neighborhood. What we provide right here as the concrete value is our argument. For example, if I provide "Brooklyn", the Brooklyn string is now the argument for the 'neighborhood' parameter. So when open_store runs, you can imagine 'neighborhood' as a variable that has been assigned the value of "Brooklyn". 'neighborhood' is a parameter, but it operates very much like a variable. The name 'neighborhood' will mean "Brooklyn" in this invocation, but it could represent a totally different string for another invocation of the open_store function. So now when this code runs, you're going to see "Opening my pizza store in Brooklyn". The beautiful part about this design is that the function can capture some kind of repetitive logic, but now also offer the ability to customize that behavior ever so slightly. For example, right here, I can copy and paste this invocation and decide that I want to open a store in another neighborhood of Queens. So notice that this type is still the same. I'm providing a string, but it is varying. So now open_store will run one more time on line #7. And notice we're going to get opening my pizza store in Queens. Notice the versatility of my open_store function. It has expanded compared to the previous lesson where it was just hard coded. It was always going to output the same text. Now we can customize the actual neighborhood while retaining the common elements of the open_store function. All right, let's try one more example. Let's expand the bake_pizza function to accept 2 parameters. The first one is going to be the number of pizzas I want to bake, and the second will be the topping on the pizzas. So once again we declare our parameters within these parentheses. When we have multiple parameters, we're going to separate every two with a comma and a space. Remember, each parameter needs both a name of our choosing and then the type declaration. So I'll choose a parameter name of number. Then the colon. And I'll designate the type of this to be an i32. Then, a comma and a space so that Rust can distinguish between the two parameters and then I'll choose my 'topping' parameter. That name is up to me. Colon to designate the type. and this will also be a string. So &str And here I can interpolate both of those values and say something like "Baking number" And then I'll interpolate topping. And then let's make pizza plural here. So notice, as soon as I save, once again we have an issue. Because now we told Rust that bake_pizza must accept 2 parameters or 2 arguments, and currently it accepts none. So the compiler will validate 1) that you provide the right number of arguments, and 2) that those arguments are of the correct type. So the first argument must be a integer. So if I, for example, provide a value like true we're going to see that is a violation right? It is the wrong type. Let's say I provide a correct type for my topping parameter something like "pepperoni". Notice that the red squiggly appears under true. "Expected a type of i32 for your number parameter, but your argument is of type bool." That is a mismatch, so the code does not compile. So let's provide a number here. Now like let's say 20. And now you can see we're going to get "Baking 20 pepperoni pizzas". Now there are multiple elements of this function that are customizable. For example, after I have baked my pizza and made a lot of profit and opened another store, I can now bake something like 15 mushroom pizzas. It's the same bake_pizza function, but now it's expanded through the use of parameters to be a lot more versatile. So now we can bake 15 mushroom pizzas. So now we are capturing some procedural logic, some step by step lines of code to run. But we can also customize elements of that execution through the use of parameters. Parameters are just names or expected inputs to a function. Then, when we invoke it, the concrete values we pass in are the arguments. So 15 is the argument for the 'number' parameter, and mushroom is the argument for the 'topping' parameter. Hopefully that makes sense and I will see you in the next lesson.

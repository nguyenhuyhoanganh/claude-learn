# Intro to Functions

Welcome to the next section of the course, which is all about functions. A function is a sequence of steps to be executed in order. It's a procedure that encapsulates some logic. The power of functions lies in their ability to capture a reusable collection of instructions. We can define a function once, and then we can run it over and over again without having to rewrite the code each time. Now the 'main' function is an example of a function. It tells Rust what to execute when the program starts. It's a bit of an exception though, because the main function only runs once and we do not run it ourselves, that is handled by Rust. However, we can declare custom functions besides main and those we can invoke as many times as we'd like. The word invoke or call mean the same thing: it means to execute or run that function. All of our functions will follow the exact same syntax as main. They're going to begin with the 'fn' keyword. Then a function name in snake_case, then the parentheses where we're going to declare our inputs. We'll talk more about that in a follow up lesson. Then we'll provide the curly braces. And in there within the block we'll write the function's logic: what it should do whenever it is invoked. Now, as far as declaring functions besides main, Rust doesn't care whether we define our functions before, main, after main, or both. The function just needs to be defined in the same scope or a scope that the 'main' function can see. Basically, defining functions in the exact same file satisfies this condition, in that the main function can identify all of the other functions that we declare here, and then invoke them very easily. So with that said, let's say that we're going to model the opening of a pizza store in our Rust program. So I want to begin by declaring a function. I'm going to utilize the exact same syntax: 'fn'. And for my first function name, I'm going to choose 'open_store'. Now, unlike main, these function names are up to us and the convention is to follow snale_case naming, which means all lowercase with underscores separating every subsequent word after the name of the function. I'll again provide my parentheses, and then after that I'll provide my curly braces. This works the exact same way as main does. This declares the logic or the sequence of instructions that will run whenever the open store function runs. So let's begin with a println! in here, and I'll output some text like "Opening my pizza store". Now you'll notice if I run my main function, which kicks off the program, we're not going to see any output. And that is because we are not actually running the 'open_store' function yet. Here, we have just declared the procedure. We've declared the recipe, but we haven't actually cooked it yet. We have not invoked the 'open_store' function so it doesn't run. The way we do so is we refer to the function's name. For example, in main, I'll write open_store and then to actually invoke it or to run it I need to provide a pair of parentheses. So now, within the main function, we are running the open_store function once. And you can see right here. Now we get that output. So let's practice this syntax a couple more times by declaring two more functions. My next function will be called bake_pizza. So once again my 'fn' keyword and a space. Then my function name is 'bake_pizza'. I'll separate those two words with an underscore, then parentheses, then a space, then my curly braces. And in here I declare my function body. This can be as many lines as I want. For now, let's just do a println! again and output some text, like "Baking a pizza one more time". Below, I'll use my 'fn' keyword to declare a function, I'll call this one 'swim_in_profit', parentheses, space and curly braces. And for this function's body we'll println! something like "So much $$$, so little time". So now, the beautiful part about this design is I've isolated these small responsibilities or delegated these smaller actions to these functions. Ideally, each function should be small and it should have a single responsibility, a single reason for existing. Now we can break up the complexity of opening a pizza store into several actions. So now in main, I can invoke these 3 functions in whatever order I want, and also I can invoke them as many times as I want. So, for example here, after I open my pizza store, I can bake a pizza and then I can swim in profit. And you'll notice we're going to run these functions in order. We're invoking all three of them, and we're going to get their respective output. But the beautiful part about functions is their reusability. For example, let's say I start making a lot of money. I can now copy and paste that invocation code a couple of times below, and now I am invoking or running the swim_in_profit function three times, which repeats the logic from its body right here three times. And that is the beautiful part about functions. I no longer have to copy and paste this code. I have it isolated and abstracted away to this helper function called 'swim_in_profit'. Now, right now, this is one line of code. But you can imagine if a function captures some amount of complexity, if it's 5 or 10 steps that are repeated, and then you want to do that over and over again. Well, it's nice because you can now isolate that logic to this named procedure, call the function, and then rerun it over and over again without needing to copy and paste. So functions help with the organization of your program into these little chunks of reusable logic. All right. More on this in the follow up lessons. I'll see you there.

# The Unit as a Return Type

In this lesson I want to introduce a special type called the unit. A unit is an empty tuple, a tuple without values. As a reminder, a tuple is a collection type that is capable of storing data of different types in sequence. It is declared with a pair of parentheses. For example, earlier on in the course, we declared a tuple like this. A pair of empty parentheses containing some values in order. For example, it can store an integer followed by a Boolean followed by a string. And if I assign this to a variable like 'result', we can see the type of the tuple is inferred to be a three element tuple containing these respective data types. Now, a unit is just an empty tuple that holds no values at all. So for example, if I just declare the parentheses with nothing inside. This is an example of a unit. What's interesting is that the value declaration and the actual type are written the exact same way. It's just a pair of empty parentheses. Now, what's interesting about this type is that it is the default return value of a function if no return value is specified, either explicitly or implicitly. So here's the easiest example that I can give you. Let's say that I declare a function here called mystery. And here are my parentheses. I'll accept no parameters. And here is my function body. And I'm not going to write any code within the body of this function within the curly braces. What is going to be the return value of 'mystery' if I invoke it here? The function literally does nothing. As you can see, the return value is going to be the exact same type: a unit, an empty tuple. What's interesting is because the unit is the default return value. Rust knows that to be kind of the fallback state. So we do not need to explicitly declare the return type of the function. For example, here we could provide our arrow syntax and say that the return value is a type of unit. It is an empty tuple. But we don't need to do that because that is the default behavior. That's why our code compiled out of the box, because the unit return value was the default. So what's interesting is if our function does something a little bit extra, like let's say it simply prints something out, like hello there, I'm going to end my line here with a semicolon. This function again doesn't explicitly return anything with the return keyword, and this line ends with a semicolon. So there's no kind of evaluation that has been incomplete. So thus indirectly, 'myster'y is going to again return a unit, an empty tuple. It's just the default behavior. So a function does not have to explicitly or implicitly produce a return value technically. But there will always be a return value. Either you will provide it explicitly with 'return' or from the evaluation of the last line, or if neither of those two situations apply, the return value will be a unit, an empty tuple, like we see here.

# Blocks in Functions

Earlier on in the course, in a lesson about scopes, I mentioned that we could declare a block within a function body. For example, within the 'mai'n function I could write some valid code. Here is a variable declaration. I'll call my variable 'multiplier' and set it equal to 3. And then directly within this function body I could declare a block like this. You might see this code from time to time. So I want to demonstrate that it is valid syntax. This block is not quite a function. It does not have a name or parameters, but it's somewhat of a similar concept in the sense that it is an isolated scope. It's an independent execution environment that happens to be nested within 'main', and it is within this nested block where we can write some lines of code and produce an output that is very comparable to a return value. So as a quick reminder, we have this word called scope. A scope is a region of code, and that is connected to the idea of a block, which is the section of code between an opening curly brace and a closing curly brace. A scope is like a region or a boundary of code. So we can say that this is a scope, that this is the main function scope, it's its execution environment. And then within that scope we have a nested scope right here declared with another pair of curly braces. We are creating somewhat of a separate execution environment in here. When this nested block ends, all of the variables declared within this scope will go out of scope and they will no longer be available in 'main'. It's kind of like a temporary journey that Rust takes to evaluate whatever happens to be inside this scope when the function runs. Now, what's interesting is this nested block has access to outside variables declared in the outer scope, that being the one that belongs to 'main'. So for example, I have access to the 'multiplier' name here within this nested scope. So, for example, within this scope let's declare a variable. I'm going to call it 'value'. And I'll set it equal to be 5 + 4. That's just arbitrary. Then, on the next line, I'll take my 'value' variable and I'll multiply it by 'multiplier'. So what's interesting like I mentioned is that this is not a function. There is no name. There is no parameters. But the very last evaluated line here works very similar to how it does within a function, in that it becomes the final product or output of this block. For example, what I can do is something like this. I can assign this complete block to a variable. For example, here on line #4, I'll write 'let calculation' and I'll assign that variable to the complete block. Now because it is a variable assignment, that requires a semicolon at the end right here. But notice that I'm not going to add a semicolon right here because that would create a terminating statement. You'll notice here that calculation is inferred to be an i32. And that integer value is this product right here. If I add the semicolon, well now we are completing our thought. So this nested block has nothing to produce our output. So as you can see very much like a function, it will thus give back a unit, an empty tuple. So there are some concepts here that are similar to those in a function, even though this block is a separate construct. So I'll remove this semicolon right here. And I want to show you that we can println! and 'calculation' is going to be what you expect. So we'll begin by adding 5 and . to get 9. We'll multiply it by 3 which we have access to through the 'multiplier' variable which we can use in here. So 9 times 3 should give us 27. And that's exactly what we see. All right. So it's just a little bit of an interesting idea because sometimes if you want to isolate some kind of related code or some sequential logic like a calculation, but you don't want to extract it to a separate function, but also want to isolate it and identify it as this distinct piece of code that has related logic bundled up. Sometimes, you might see this example of a block to capture that same idea. It's not quite a function, but it does have access to data from the outside through the use of variables, and it produces a final output as long as you omit the semicolon. And you can assign the complete evaluation of this block to a variable. Remember, Rust always evaluates the right hand side of an equal sign first. So when it gets to line #4, it sees 'calculation'. And it says: "Before I can give it a value, I have to process the entire right hand side of the equal sign, which is the complete block". So that's when Rust runs through all this logic, gets its value, assigns it, and then moves on. And after this point, the value variable is completely out of scope. You can think of it as extinct. It is no longer valid because it only exists within this nested scope, this nested independent execution environment.

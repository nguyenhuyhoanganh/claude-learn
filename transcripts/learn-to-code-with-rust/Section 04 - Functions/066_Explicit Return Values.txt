# Explicit Return Values

In the previous lesson, we introduced parameters and arguments which represent the inputs to a function. The complement to that is a function's return value. A return value is the output of a function. It is what the function produces or gives back to the caller, which is what invoked the function in the first place. Every Rust function must have a return value. So as a simple example, let's say that I want to declare a function called 'squar'e that will accept an integer and calculate its square. So I'll define my 'square' function right here, and I'll define my parentheses and my curly braces. And then in here, I'll accept a single parameter called 'number'. And I will set its type to be an i32. What I want to do in the body of my function is take number and multiply it by itself to get the square. Now, this is valid code that will calculate the square, but I'm not actually doing anything with that result. I'm not printing it and I'm also not returning it back. So when I invoke square in a place like main with an argument like five, I'm not actually going to get anything back from the square function. So what the square function is going to give back to me here in main is what's known as the return value. It is the output. In order to declare a return value, we need to do two things. The first is we need to add the 'return' keyword before whatever it is we want to return. So here I'm going to say return this calculation or the result of this multiplication operation. And then I'll add my semicolon. If I am returning something, I also need to clarify the type in the function signature. When I use the terminology function signature, I mean this section up here. In addition to declaring the types of each parameter, I have to declare the type of the return value so that the compiler can hold me responsible. The way that I annotate the type of the return value is after my closing parentheses, I add a space and then I do this arrow syntax, which consists of a dash. That's the key for me to the right of 0 and then the greater than sign ( > ). So it resembles this kind of arrow. And this will point to a type. So I'll add another space and I'll write i32. So what I'm saying here is that my 'square' function will accept a parameter called 'number' that will be of type i32 and it will return a value back that will also be of type i32. Now, the fact that these two are the same is purely coincidental. Your return value can be of any type that you want. You can have a function accept a number and return back a boolean or vice versa. It all depends on what your function is doing and thus what it's going to accept in, and then what it's going to return back out. So now Rust is holding us responsible that we are indeed returning an integer. So for example, if I replace this with something like return true, that would be a mismatch because we are returning a boolean when we told Rust that the function would instead return an i32. So the compiler is making sure we don't write incorrect code. Now, it's important to note that the return keyword terminates the function. That means it ends the function, so no code after the return keyword is able to run, because this represents the conclusion of the function's body. So for example, if I try to do something like 1 + 1 here, you'll notice we're going to get this warning in VSCode: "unreachable expression". It is unreachable because line #7 will never be run. And that is because this return on #6 will terminate the square function and produce this as the final return value. So once you add the return, the function is over. So now back in 'main', I can collect the result of this square function, the return value, and assign it to a variable like 'result'. And now, I'm welcome to use that return value. Notice that the rust-analyzer extension can know that this is an i32. The way it knows the type of 'result' is because it's looking at this signature right here, and knowing that we promised that that 'square' function would return a 32-bit integer. So now I can print my result and say "The square of five is {result}". And you can see 'result' is set to 25, which is the final return value of my 'square' function. But the beautiful part there is that we can again reuse the same function, but with a different argument. So here is the square of 13. I'll once again update the values here and once again the logic remains the same. The function performs the same mathematical operation, but the parameters customize what happens, and then the return value is what the function gives back or produces. And you can see it's totally different in each scenario. So the function stays reusable but also dynamic enough. And flexible to cover these different types of arguments. Right?

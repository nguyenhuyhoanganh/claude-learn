# Section Review

Congratulations on reaching the end of another course section. As always, let's take a few moments to review everything that we learned. In this section, we focused on functions. A function is a sequence of steps. I often like to compare it to a cooking recipe because it accepts inputs, then runs some kind of logic and produces an output. A function is some kind of procedure of step by step instructions. It encapsulates some bit of logic, and where functions really shine is if that logic is reusable, because then the function can be used over and over again and you do not need to rewrite its code. Functions begin with the 'fn' keyword and then a name in snake_case. snake_case means we separate all words with underscores and we keep it all lowercase. Now, every Rust program must have a 'main' function that will be run automatically. Any function after that is up to us to define. We can have as many or as few as we want, and when we define them, we are just declaring the recipe. We actually have to invoke a given function in order for its body to run and be executed by the program. So in our case, we declared our functions outside of 'main', and then we ran them within 'main' by writing the function's name and then a pair of parentheses. So, within the function declaration, we have our parentheses. And in there we can declare our parameters. A parameter is a name for an expected input to the function. A function can accept no parameters or as many parameters as you want. Each parameter must be declared with its associated type. We accomplished that with a colon after the parameter name, and then the data type that it should be. If there are multiple parameters, we separate them with a comma and then a space for readability. Now when we actually invoke the function, the compiler will validate that the correct number of arguments is passed in, and also that the arguments are of the correct type. Now, when you pass in those arguments to a function, the syntax is the exact same. We separate our arguments with a comma and a space. So the parameter is the name for an expected input. And that's what we use throughout the function body. We have full access to the parameter almost like a variable that we can utilize. And then the argument is the actual concrete value that fills in for that parameter whenever the function is invoked. And then the arguments can vary each time the function is rerun. So, if parameters are our inputs, return values are our outputs. A return value is the final product that a function will give back or produce for the caller, which is the function that invoked it in the first place. Now, the function signature declaration must annotate the return value type, and that is so the compiler can validate that the function body produces a value of that given type. Our first option is an explicit return value, where we use the 'return' keyword followed by the value that we want to produce, and then a semicolon. Keep in mind the 'return' keyword ends the function. It terminates it, so no code will execute after a 'return' keyword. Now our second option is an implicit return value. And that is when a function will automatically implicitly return the evaluation of the last line that it runs through. In that scenario, we want to omit or remove the semicolon. The function will automatically return that designated value. Now, if a function does not explicitly or implicitly return any value, it will return what's called a unit, which is just an empty tuple. That is a pair of empty parentheses. If the function returns a unit, we do not need to write that type in the function signature. It's just the Rust default. Now, the most common community convention you're going to see is these implicit return values. We're typically not going to use return that frequently. There are use cases for it. But typically you're just going to write the final thing you want to produce on the very last line of the function. But keep in mind, it's not going to be necessarily the last line of the function each time. It's going to be the last line that is evaluated. And later on in the course, when we see functions that are going to have multiple branches of execution, what the return value can be will differ, potentially depending on which branch our code goes down. We're going to talk more about that a little bit later. All right. Finally, we saw that, within a function body, we can also declare an arbitrary block with curly braces. And that creates its own independent execution environment without the need to declare any separate function. This is sometimes ideal when you want to quickly isolate a one-off procedure and just write a couple lines sequentially that deal with producing some kind of final value. It's not exactly a function, but it operates very similarly because that block and its last evaluated line can implicitly produce a final value to return back to the function that is capturing that block. And then that product of the block can then be assigned to something like a variable. So it's a nice little independent execution environment. All right. So that is a quick introduction to functions.

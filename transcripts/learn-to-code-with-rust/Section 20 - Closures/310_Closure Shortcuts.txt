So you might be curious why Rust doesn't just try to infer the types of parameters and return values in a similar fashion for regular functions? And the general answer is because functions have to be held to a stricter standard, a higher standard because other code is likely to use them. So the types that we have are part of a contract that a function offers. So say you're writing a Rust library. You don't know all of the possible developers who are going to be invoking the function that you write. It's thus critical to define the function's expectations for it to be able to run properly. It needs to know the kind of data it's going to be accepting in and returning out. Now, closures, in comparison, are not designed for external use or for use by other Rust crates or even other files in the project. They exist for simplicity and expediency in your code. Remember, closures are primarily meant to be used for short, one-off specific, narrow procedures. We haven't seen too many examples of them being utilized. We will see that later in the section. Right now we're just exploring the syntax, but they're meant to be these convenient one-off functions that we can declare as needed. So in a sense, there is less risk, so to speak, from the compiler inferring the type definitions based on what it sees immediately in the code. That's just typically the kind of environment or the kind of examples in your code that will merit a closure in the first place. Now, I want to make it very clear that the compiler is not just arbitrarily guessing here. It's not keen to take risks. Rather, it's going to make an educated guess or even conclusion based on what it sees happening in the code, such as a future invocation that we saw here, or just based on logic. Like if you multiply an integer by an integer, you're going to get back an integer. So if there's only one option logically left, the compiler will infer those reasonable defaults for things like your return type as well as your closure parameter types. All right. So the compiler is still going to do its work and assume reasonable defaults while still performing type checking throughout.

# The Fn Trait Hierarchy

So at this point, we've declared our closures inline and assigned them to variables. And we've seen how the compiler inferred their types, which so far have been a type that implements the Fn trait. The Fn trait is actually one of three traits that indicate a callable type, an invocable procedure. Rust uses the terminology "call operator" to describe these traits. Remember, an operator is just a symbol, like a plus sign for addition, that performs some kind of operation, and the word "call" means to invoke or execute. So call operator means that these types implement these traits indicating that they can be invoked with the call operator, which is the pair of parentheses. These traits indicate a type that can be called, that can be invoked, that can be executed. So these three traits are FnOnce, FnMut, and Fn and the first detail to remember is that the three traits form a hierarchy. It's actually a hierarchy of traits and sub traits. FnMut is a sub trait of Fn, and Fn is a sub trait of FnMut. So FnOnce is at the top and Fn is at the bottom. Now these traits have differences between them, and as we progress throughout the lesson, it's okay if the differences aren't super clear yet. We're going to see examples of closures that implement each one of these traits in the upcoming lessons. So the Rust documentation mentions that these traits are additive. And here's what that terminology means. So far we've declared our closures inline. Let's flip that perspective around. Say that we are defining a function or a method that we want to accept a closure as an argument. Remember, this is a valid operation in a functional programming paradigm. A closure is a valid value to pass into a method. So when we define the parameter for that expected closure, we need to declare its type, and we're going to use one of these three traits to do so. If a function requires the parameter to be a type that implements this FnOnce trait, then that function can accept an FnOnce closure, but it can also accept an FnMut closure or an Fn closure. That's what it means to be additive. It means that all of the traits below the current one, including the current one, satisfy that requirement. So FnOnce is satisfactory for a parameter that declares an FnOnce closure, but so is FnMut and so is Fn. Similarly, a parameter that expects a closure type of something that implements FnMut can accept an FnMut closure argument, but can also accept an Fn closure. Remember, additive means the current one and everything below. And then finally, a parameter with a type of Fn can only accept a closure that is Fn. It is the strictest one. There's nothing below it. All right. So what are the differences between these traits? Well, they each correspond to the different ways that we deal with ownership in Rust. FnOnce captures values by ownership. FnMut captures values by mutable reference. And Fn captures values by immutable reference or captures nothing at all. The key takeaway about the FnOnce trait is that the function or method that is accepting it will only invoke it once. And that's because the closure will capture values by move. Remember to capture means to save some data from the outside scope. In other words, the closure will capture its data, collect its data that it needs for its logic by taking some ownership away from some original owner. That only allows the closure to execute once, because that move can only happen one time to bring the value into the closure. After the closure executes, the original owner will no longer be the owner, so we cannot move the value again, so the closure cannot be redeclared and run an additional time. So FnOnce indicates that the closure will be invoked a maximum of one times. Now, if a parameter is declared instead to be an FnMut or an Fn closure, then the function or method can invoke that closure multiple times. So remember, we can still pass an FnMut closure into a function that expects an FnOnce closure. And that is because even though FnMut can be invoked multiple times, it satisfies the FnOnce requirement that the function is going to be invoking the closure only a maximum of one times. FnMut can technically be invoked multiple times, but that is sufficient to satisfy the "at most one invocation" requirement or standard demanded by FnOnce. I know it's pretty complex, so don't worry if this is confusing right now. Finally, what's the difference between FnMut and Fn? An FnMut closure captures its values by mutable reference and can be invoked multiple times because there's no danger to independently capture mutable references one at a time sequentially and run their logic again. And similarly, an Fn closure will capture values by immutable reference and can also be invoked multiple times. And it also has the capacity to capture nothing at all. So it really depends on what the body of the closure is going to be doing. And that is the requirement that we are setting when we declare the parameter type to be something that is one of these three possible traits. So to repeat a parameter that defines an Fn trait closure expectation can only accept an Fn closure. This is the strictest trait for a closure, and it's the rarest one you'll see in Rust, but once again, it is invalid to pass in an FnOnce or FnMut closure into a place where only an Fn is expected, but the same logic does not apply in reverse. FnOnce enables an FnOnce closure to be passed, or an FnMut or an Fn. All right, so I know it's been confusing and I know we're introducing these ideas at a high level.

# The static Lifetime

In this lesson, I want to introduce a special lifetime called 'static. The borrow checker understands 'static as a special lifetime that acts as a bit of an exception to the rules that we've encountered in the previous lessons. The 'static lifetime enables us to return a reference to data that is declared within a function, so the 'static lifetime is used with a reference that we can guarantee will exist for the whole program. 'static means this thing will exist for the duration of the program. For example, a string slice that we create from a string literal has a 'static lifetime. The text is hard coded into the final binary at compile time, so it lives in memory for the entire duration of the program. So for example, say we define a function called 'say_hello' and say I want to return a string slice from this function. So here I'll declare a string slice of "Hello". And here, I'll return a ref str, a string slice ( &str ). So currently the function will not compile because the borrow checker sees a return of a reference. It does not see any reference parameters, and thus it assumes that the reference is coming from somewhere inside the function. But if it's coming from data somewhere inside the function, that would be a dangling reference, right? If we returned a reference to, say, a vector declared in 'say_hello', that would be a dangling reference. But this is a special exception because we know that the text "Hello" will be embedded directly into the executable, so we can return that reference, because that reference will be to that part of the memory at runtime that is loaded in the file's contents and has that text "Hello" available. So we can solve this problem by adding these special 'static lifetime. So it's an exception of a lifetime because this name has to specifically be written out by us. It's like one special exception that the borrow checker can understand, and that is a lifetime by the name of 'static. So here I'm not going to provide any angle brackets or anything like that. I'm just literally going to do 'static as my lifetime name and the borrow checker understands. So now Rust knows that this is data. This reference is data that is guaranteed to live for the existence of the entire program, which is true for string slices. So for example, in 'main', I can invoke 'say_hello' and assign the return value which is a ref str, a reference, in other words to 'greeting'. And Rust understands that that reference is pointing to existing data. It's not a dangling reference. It knows it is pointing to data that exists because it is guaranteed to exist for the entire program. That is the designation of 'static and what it signifies. So here I can output 'greeting' and this should compile and execute our content. Here's another example. Constants. Constants are available and defined at compile time and similarly have a static lifetime. They are available for the duration of the whole program. So say I declare a constant here called 'COUNT', and I'll give it a type of i32 and a value of 400. But it's completely arbitrary and say I declare a 'value' function, and in the 'value' function I want to return a reference to my COUNT constant. So right here I'll provide my reference operator and then COUNT from above. And if I try to designate the return value here as a reference to an i32, which is what the return value is, once again, we're going to run into the same problem. The borrow checker thinks we are returning a reference to some data that is not going to exist, but very much like a string literal, this COUNT is a hard coded value that is known at compile time that the compiler will include in the final executable. That is not going to change. So if we return a reference to this fixed available value, that is going to be a reference to data that is guaranteed to exist for the whole program. So once again, we can use these special 'static lifetime to tell the compiler and the borrow checker that we know something that it doesn't, that we can guarantee that the returned reference is not going to ever point to dangling data, because the original referent is always going to be alive for the duration of the program. And similarly, in 'main', I can invoke the 'value' function, take my 'count' return value and output that, and you can see we are returning a reference to an i32 which we can dereference to get to the original constant's value of 400. All right. So that is an introduction to the special exception, the 'static lifetime.

# Lifetime Elision Rules II

A few lessons ago, we introduced lifetime elision rules. These are rules that the borrow checker applies when it evaluates references. If the rules are sufficient to establish lifetime associations, our code can elide or, in other words, leave out explicit lifetime annotations because the borrow checker is able to figure them out. The first rule is that every reference in a parameter list gets a lifetime, and the second rule is that if the return value is a reference and there is only one reference parameter, the borrow checker will associate the lifetimes of the two together. That is the only technical way that you can return a reference from a function and have it not be a dangling one, and that is that it is connected to a reference parameter. And thus if you only have one reference parameter and a reference return value, the two must be related. Now, the third lifetime elision rule that we're going to introduce in this lesson is this. When defining a method, if there are multiple reference parameters, but one of them is self, in other words, you have a reference to the instance, the borrow checker will automatically assume that the lifetime of the instance or the lifetime of 'self' is going to be tied or connected to the lifetime of the return value.

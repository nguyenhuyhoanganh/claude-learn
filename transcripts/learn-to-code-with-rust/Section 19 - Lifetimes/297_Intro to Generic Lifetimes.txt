# Intro to Generic Lifetimes

Many times throughout the course, we've used the terms generic versus concrete to differentiate between types. When we say generic, we mean general or non-specific. When we use concrete, we mean actual or realized. We've seen generic types plenty of times before. As a reminder, a generic is a non-specific placeholder type or a stand in for some future type. A generic adds flexibility by not hardcoding an exact type, so that later code can use a variety of types in the place of the generic. The generic is the placeholder that allows us to write flexible code, and then later on we substitute the concrete actual type. Just like with generic types, there are generic lifetimes and concrete lifetimes. A concrete lifetime is the actual region of code that a value exists in the program, which corresponds to the time that it exists at a single memory address. We saw from the examples in previous lessons that Rust understands the concrete lifetime of a value when it lives within a single function. Now, generic lifetimes are more abstract. A generic lifetime is a hypothetical lifetime, a non-specific lifetime, a future lifetime that has the potential to vary. We can declare these generic lifetimes in our code, and that will enable functions that similarly benefit from increased flexibility. These functions become more flexible because they can deal with various differing lifetimes. So in order to declare generic lifetimes, we use something called lifetime annotations. A lifetime annotation is a name or a label that we give to a lifetime, and it doesn't affect the code in any way. It doesn't change how long references live. It doesn't affect the logic in any way. It's exactly how a function parameter doesn't change the logic in any way, or alter the implementation in any way. It's just a contract that we provide that the compiler will validate. So a lifetime annotation is a piece of metadata that we provide to the borrow checker that it enforces, that it validates. And it looks at what we do in the body of the function. And it says, "Yes, you are living up to what you promised to do. You are living up to the lifetimes that you provided and the relationships that you are declaring between your references, particularly the relationships between the parameters and the return values".

# Concrete Lifetimes for References

So at this point, we've covered concrete lifetimes for regular values. Let's now move on to discussing lifetimes for references. There's an important nuance to point out here. A reference is a value. It's a piece of data like any other. However, a reference represents a memory address of another value. So by its very definition, a reference is dependent on the existence of an original value. A reference cannot exist independently by itself. The concrete lifetime of a reference follows the same rules as the values we saw in the previous lessons. The lifetime of a reference starts when it is written to a location in memory, when that address is stored somewhere, and the lifetime of a reference ends when it is moved or dropped from that memory location. But there's one additional constraint when it comes to lifetimes for references. A reference, again, is intrinsically linked to a starter value, the one that it is borrowing, so it is critical that the reference does not outlive the original value, or the reference may then accidentally refer to invalid data. So thus Rust will validate that the reference's lifetime is contained or lives within the lifetime of the referenced value. So this ensures that the reference points to a valid value for the complete existence of the reference. So remember we mentioned earlier on in the course that a reference is like an address to a house. It is not the house itself. It is an address to get to the house. So in real world terms, the Rust compiler is going to validate that the address of a house does not outlive the house itself. There is a lot of danger if a reference stores a memory address of a value somewhere else that is no longer valid or no longer exists. If you show up at an address and there is no house there, you'd be pretty frustrated in the real world and similarly in programming languages, when that happens, that can lead to serious bugs. So most of the time when we're talking about lifetimes in Rust, usually we're going to be referring to the region of code that a reference can exist. So all values in Rust have a lifetime.

# Concatenation

In this lesson, we'll learn about the different ways that we can concatenate content to the end of a string. To concatenate means to append or to add content to the end of an existing string. In order to modify a string, we need a heap String, the one with the capital 'S', because it is the only one that can expand in size. A string slice does not have that capacity, so let's begin by declaring a variable. I'm going to call it 'full_name', and I'll provide a heap String that's going to begin with the text "Sylvester". And since I'm going to be modifying this string through concatenation, I need to make sure that I make it mutable. It's about to change. Then below I can declare a 'last_name' variable. And let's set this to be a string slice. So just regular string literal syntax with double quotes, and I'll make this a text of "Stallone". Then on the line below, I can take my 'full_name' heap String, and the first method that is available to us is called 'push_str'. 'push_str'. And that's going to add or concatenate content to the end of my heap String. What this method expects is a string slice. So 'last_name fits the bill. I can provide 'last_name'. And that is going to add the content Stallone to the end of Sylvester. So afterwards, I can output my 'full_name' String. And we're going to get Sylvester Stallone. Notice that Rust takes the concatenation literally. So for example, it's not going to add a space in between the first and last names. Now if we make a reference here with the borrow operator, technically this is also not a string slice. This is a ref string ( &String ). It's a reference to a heap allocated String. However, through a feature called deref coercion, Rust can convert this 'ref String' ( &String ) to the expected parameter type of a 'ref str' ( &Str ). So behind the scenes, this becomes this. So when we pass in that String reference, deref coercion allows Rust to convert or coerce to nudge the 'ref String' ( &String ) to a 'ref str' ( &str ). Rust knows that there's no danger to doing this because it just creates a string slice from a string reference. It creates a borrow of some portion of text stored somewhere else. It just so happens that now that text is stored on the heap. So this proves that string slices don't always need to be references to something hardcoded in the binary executable, although they usually are. But in this scenario, our string slice type here is a reference to a partial fragment of something else. It just so happens to be not the original executable, but a dynamic heap allocated String that is created at runtime. All right.

So hopefully you enjoyed this nice review of the various different types of strings in Rust, as well as new features like the format! macro and the ability to collect user input using the 'io' submodule. So Rust is actually pretty distinct in the fact that it has two primary string types. That is a very common source of confusion for new Rust developers. In most other languages, you're just going to have your standard string, and it's going to be flexible and work in all kinds of circumstances. But again, the reason why the Rust development team offers these options is because both of these strings excel at different features and functionalities, right? The heap String is great for expanding and shrinking and mutating, while hard coded string literals and string slices that are known in advance -- if you know what it's going to be and you know that it's not going to change and you can embed it into the binary executable, well, that offers advantages as well. But it really is reflective of the fact that the Rust team is trying its hardest to reduce the total amount of memory, and they're willing to add a little bit more complexity to have these kinds of optimizations to use the smallest, most minimal type of string we can in a situation where we know the text up front and use a more complex, you could say, variant of a string, the heap String in the situations where you do need content that can expand. So it is tricky. It is complex, but hopefully you see the reasoning that the Rust team applied. And once you get comfortable with these types as well as your specific type declarations and annotations, it becomes pretty easy to work with it.

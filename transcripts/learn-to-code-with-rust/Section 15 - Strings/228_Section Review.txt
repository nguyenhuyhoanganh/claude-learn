A string is a sequence of text characters in order, and Rust supports two string types: the 'str' spelled 's-t-r' in lowercase and 'String' spelled completely with a capital 'S'. Now the 'str' type usually appears in its borrowed form, which is 'ref str' ( &str ), so we have the borrow operator in front of it, and we call this a string slice or a 'ref str', so we don't have to deal with any principles of ownership. So one common way that you can get a 'ref str' is from a string literal, that is, a string that you declare with double quotes representing hard coded, unchanging content that is going to be embedded in the final executable. So when the program runs at runtime, it will receive a string slice. In other words, a reference to the memory that is loaded in your program and has that hard coded piece of text so you can't mutate it. You can't change it. But it's more lightweight and simple because it's known in advance and it's available directly to use. Now, in comparison, the String type with a capital 'S' lives on the heap, and the advantage of this String is that it can grow and shrink. It can be mutated, in other words. So we've also talked about this idea of deref coercion, which is converting one type into another when it is necessary to do so. Now the operation does not work in reverse, which means we cannot coerce a 'ref str', a string slice, into a 'ref string' ( &String ), because there is no guarantee that that string slice came from a 'ref string' ( &String ).

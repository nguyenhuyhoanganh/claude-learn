Welcome to the next section of the course. In this section, we'll introduce a new type called a hash map. A hash map is a collection type that consists of pairs of keys and values. So when I use the word pair, I mean a connection between something called a key and something called a value. The key must be unique while the value can contain duplicates, and each entry in the hash map consists of that pair of key and value. In other languages, we often call this data structure a dictionary, a hash, an associative array, or a map. So there's lots of different names for it, but they all represent the same idea, and they all serve the same purpose. And that is to establish connections between two values in our program. So you should not assume the concept of order when working with a hash map. If you need to keep things in line, in position, in order, then you should use an array or a vector. If you need to establish connections or relationships between values, that's when you use a hash map. So a hash map establishes these mappings or bridges or associations between keys and values. So for a real world example, consider a restaurant menu. A restaurant menu is a collection of associations between menu items and their corresponding price. We can call each menu item the key. It is the identifier that helps us retrieve the corresponding value so on a menu, the entree item, like "Salmon", connects us to the value of the price like 29.99. We don't care about the order of these pairs of keys and values in a hash map. We just care about the fact that we are able to relate two values to each other in this larger collection of pairings, called a hash map. Now, as far as the terminology, the word hash map comes from the word hash. The word hashing refers to a deterministic mathematical calculation, basically a formula that we can apply to a key in order to locate its corresponding value in memory. And deterministic just means consistent each time. We don't have to worry about the computer science concepts under the hood. The key takeaway is that hash maps are very fast when it comes to using a key to locate an associated value. That's typically what we use hash maps for, where we have these mappings or associations. And we have a key that we want to search for in order to get its corresponding value. Like a vector and a string, hash maps are stored on the heap because their exact size cannot be predicted at compile time. A hash map can thus grow and shrink over a program's execution.

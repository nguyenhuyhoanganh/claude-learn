# Overwriting a Value with an Existing Key

As we mentioned earlier, every key in a hash map must be unique because it serves as the identifier for the corresponding value. If we had duplicate keys, how would Rust know which value we intend to extract? So that design raises the question what happens if we try to insert a key value pair with a key that already exists? In that scenario, Rust will replace or overwrite the existing key-value pair with the new one. So, for example, with our code from a lesson or two ago, we already have a key of "Latte" within my 'coffee_pairings' 'HashMap'. So take a look at what's going to happen if I call the 'insert' method and provide the same key of "Latte" and I'll provide a different value. So we'll be able to see which one wins out for the key of "Latte". So now I'll add "Pistachio Milk". This key already exists. So Rust will replace this entry, this pair of "Latte", "Oat Milk" with this new pair of "Latte" and "Pistachio Milk". I can even show you the before and after. I'll println! right here and show you the representation of 'coffee_pairings' before and after the 'insert' method call on line #10. Here you can see "Latte". The key has a value of "Oat Milk". Immediately afterwards, it is set to "Pistachio Milk', so the 'insert' method will write a new pair if one does not exist, but it will also replace, so you have to be careful when you rely on this method.

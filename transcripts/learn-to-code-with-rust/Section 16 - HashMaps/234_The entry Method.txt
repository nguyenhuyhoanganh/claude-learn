# The entry Method

In this lesson, we'll learn the 'entry' method. The 'entry' method accepts a hash map key and it returns an enum called 'Entry', and that enum has two variants representing the possibility that the given key exists and the possibility that the given key does not exist. So here I can take my 'coffee_pairings' hash map, call the 'entry' method and provide a sample key. Let's start out with a key that does exist. Let's do "Latt" right here. And if I command-click into 'entry' right here on a Mac or on a Windows this should be Ctrl click. This will take you to the actual definition of the 'entry' method in the Rust Standard library. You can see this method returns a type called 'entry'. And if I do the exact same thing, either Cmd-click or Ctrl-click onto 'entry'. I'll be taken to that definition and you can see it is an enum called 'Entry' with two variants. 'Occupied' and 'Vacant'. 'Occupied' means the key exists so it occupies that space. It is present and this occupied 'Entry' will actually store both the key and the value. And then you have similarly the inverse the vacant 'Entry', which means the key that you searched for does not exist. It is 'Vacant' or empty, and thus there is no corresponding value to include as well. Now the important thing here is that this 'entry' method returns that 'Entry' enum, and it is the enum itself that has a cool method called 'or_insert'. What this will do is it will add a key-value pair to the HashMap, but only if the key does not exist. So we saw with the 'insert' method in the previous lesson that if we had an existing key and we try to use 'insert', we would replace it. This allows us to skip that. This will insert a key-value pair, but only if the given key does not already exist. So for example, let's say I try to insert a corresponding value of "Pistachio Milk". So what I'm trying to do here is to add an 'entry' consisting of a key of "Latte" and a value of "Pistachio Milk". The only problem is a key of "Latte" already exists with a corresponding value of "Oat Milk", so this will actually accomplish nothing. I can show you below that I can output my 'coffee_pairings' HashMap, and we're going to see our "Latte" key with its original value of "Oat Milk". Right. But the beautiful part about this 'or_insert' method is that it does allow us to add a key-value pair if the key does not exist, and thus we prevent any accidental overriding as well. So for example, here I'll do 'coffee_pairings'. I'll once again begin with the 'entry' method indicating that I'm looking for some 'entry', some existing key-value pair that may or may not exist within the hash map. And I'm looking for it by the key so I can put a sample key like "Cappuccino". We're going to get back the same 'entry' enum. But now we're going to get that other variant which was the 'Vacant' variant, indicating that the key does not exist. Now on that 'entry' enum I'm going to call the 'or_insert' method, and I can provide the corresponding value to insert if the key does not exist, and it will be added as a pair. So here I can add something like "Pistachio Milk". And so notice line #10 accomplished nothing because "Latte" was present. "Cappuccino" is not present as a key. So we are going to add this new key-value pair. And thus we're going to get "Cappuccino" with a corresponding value of "Pistachio Milk". right here in our hash map. All right. So this is a cool way that you can insert something conditionally. Once again Rust is going to accomplish a lot of this conditional logic through the use of enums, through the use of helper methods. It really is all about figuring out the kind of type that you're getting as a return value, and then the methods it supports for various operations. By the way, the 'or_insert' method also returns a mutable reference to the actual value within the 'entry'. So if the key-value pair already exists, you're going to get a mutable reference to the existing value. And if you just added the new key-value pair because the key did not exist, you're going to get mutable reference to the newly added value. So it's kind of normalizing it. So you're always getting back a consistent return value and can work with the consistent data type that you're getting back. All right. That's all there is to cover in this lesson.

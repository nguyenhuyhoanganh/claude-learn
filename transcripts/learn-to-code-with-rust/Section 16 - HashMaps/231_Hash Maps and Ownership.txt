# Hash Maps and Ownership

The hash map type lives on the heap, so regular Rust principles of ownership apply. For example, if we assign a hash map to another variable, the ownership will move from the previous variable to the new one. In addition, as a collection type, the hash map is the owner of the data that is stored in both its keys and its values, and the same rules apply. If we use a type for a key or a value that does not implement the Copy trait, then the hash map will take full ownership of that key or value of that data from its original owner. In comparison, if we use a type that does implement the Copy trait, then Rust will create a copy of the data to serve as the key or value and the original variable or owner will retain ownership. That will be the string of "Latte" and my milk as the value that will be the string of "Oat Milk". Now at this point, ownership is going to move from the 'drink' and 'milk' variables to the hash map. The hash map will be the owner of both of those pieces of data, so that when `coffee_pairings` goes out of scope, it deallocates the memory for the hash map, and the hash map in turn cleans up the memory for its two nested strings.

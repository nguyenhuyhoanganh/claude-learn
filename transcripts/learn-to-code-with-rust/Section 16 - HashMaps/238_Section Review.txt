# Section Review

Congratulations on reaching the end of another course section. As always, let's take a few moments to review everything that we learned. This section focused on hash maps. A hash map is a collection type consisting of unordered key value pairs. A key is a unique identifier for a value. So the keys must be distinct and unique. The values can contain duplicates. They don't have to, but they can. A hash map exists to establish mappings or connections, associations, bridges between two pieces of data. So if we need to keep something in order, we use something like an array or a vector. A hash map serves a different purpose. It exists to form connections between two things, such as a restaurant menu item and its price, such as, say, a company name and its stock price. Whenever we have that A to B mapping, that's when we use a hash map. We don't care about the order, we care about the connections. We also talked about the length of a hash map. That is a count of its key-value pairs. So you can't have a key or a value by itself. It is the pairing of the two that is stored within a hash map. So how do we create a hash map? Well, the 'collections' submodule in the standard library contains the 'HashMap' type. So we first use the 'use' keyword to bring the HashMap name into our file scope. And then we have the 'new' constructor function which creates an empty hash map. Now, if you do not have any code to say insert a key-value pair, then the compiler cannot infer the types of either the keys or the values, and the code will not compile. And then we must provide a manual explicit type declaration. There are two generic types we have to define there: 'K and 'V', and those stand for key and value. So the type of 'K' will serve as the type of the keys, which must be of a consistent type, and the generic 'V' represents the type of the values. And they must be of a consistent type as well. All right. We also talked about various methods to mutate or modify a HashMap. For example, the 'insert' method adds a new key-value pair and if the key exists, we have to be careful because Rust will replace the existing key-value pair with the new one with the updated value. Once again, for any of these mutation methods, we do have to make the original variable mutable with the 'mut' keyword. We also talked about the 'remove' method. That removes a key-value pair by using the key. Once again, the key is always the identifier. It is our entry point. It is the thing we're using to search for the corresponding value. Now the 'remove' method has no guarantee of success because there is the possibility that the key-value pair does not exist. So that method returns an Option where the 'Some' variant will store the value, and then the 'None' variant represents that that key did not exist. We similarly have the 'entry' method that returns a special Entry struct, and that has an 'or_insert' method that will add a key-value pair, but only if the given key is not present. So depending on whether you want to overwrite or you want to be careful, you can use either 'insert' or this 'entry' method plus 'or_insert' to accomplish whatever result you desire. All right. We also talked about how we access a HashMap value. The first option is to use square brackets in which we provide the actual key. But keep in mind that the program will panic if the key does not exist. Very similar syntax to accessing, say, an element by its index position within an array, right? But the Rust protocol in general is to play it safe. And so something like the 'get' method is a little bit more idiomatic. That accepts a key and rather than panicking, it will always return a consistent return value of an Option regardless of whether or not that key exists. So if the key does exist, the 'Some' variant will store a reference to the associated value for that key. And the reason it's a reference is to prevent the transfer of ownership away from that variant. And then if the given key does not exist, then you're going to get the 'None' variant instead, which stores no associated data. And that will prevent any kind of runtime panics because with something like an Option you're going to be forced to write, say, a 'match' statement in order to account for every possibility. All right. That's all there is to cover in this section. Pretty quick one here, but a very critical, important data type and data structure for use in your everyday code.

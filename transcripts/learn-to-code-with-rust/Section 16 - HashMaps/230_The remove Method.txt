# The remove Method

In the previous lesson, we introduced the HashMap type and we saw how we could add a key-value pair to the HashMap using the 'insert' method. In this lesson, I want to show you the complementary 'remove' method, which deletes a key-value pair from a HashMap by using the key. Before we get there though, I want to show you another constructor function that is available on the HashMap type. So Rust version 1.56 introduced a function called 'from' just like 'new'. It is available directly on my HashMap type. It is called 'from' and what 'from' is actually going to accept is an array of tuple elements. Each tuple is going to store two elements within it, and the first is going to be a key, and the second is going to be that key's corresponding value. This just gives us a shorthand to allow us to pre-populate our hash map at the moment of creation. So I'm going to extract this array of tuples to a separate variable here called 'data'. And then I'll simply pass in 'data' below. So 'data' is going to be an array. So I'll begin with my square bracket syntax. And then inside my array, I'm going to store tuples. As a reminder, tuples are created with a pair of parentheses. And they are similarly a sequenced collection of values although the values in a tuple can be of different types. So each tuple that I store within my array will store the key and the value as its two positional elements. So what I want to model here is an employee system where I'm going to have a key of an employee's name and a value of a integer, representing the number of years that they've been within my company. So here within this first tuple, I'll do a string slice with a name like "Bobby". Then, I'll provide a comma. And for the second element within this first tuple, I'm going to provide a number like 7. So just to break things up so you can see what's going on here, I'll declare my array on one line and show you each tuple on a separate line, just so it's easier to parse what's going on later on. The Rust formatter may auto adjust this, but I do want you to see that here is my array. And here is one tuple element inside it. So I'll place a comma here and move on to my next array element, my next two-element tuple. And I'll do something very similar here an employee name of Grant. And let's give him 4 years at the company. And then one more comma, one more tuple element consisting of two values in sequence. Let's do a name of Ben. Let's do a number of years of 6. Right now this is just an array of tuples. But if we pass in this exact data type into the 'from' function, it will be able to convert it into an equivalent hash map. Each key here will be associated with the corresponding value and then stored within the hash map. So we're going to have three key-value pairs based on this original data source. So here I can assign this to a variable like 'years_at_company'. And then down below I'll use my Debug formatting to output 'years_at_company'. We can see that Rust can also infer the concrete type for the K and V generic. The key and value generic based on the values that it's getting from the 'from' function. And we can see here we have our hash map. All right. So now let's take a look at the 'remove' method. The 'remove' method attempts to remove a key value pair from the hash map. Now why do I use the word "attempts"? Well because there is the possibility that you provide a key that does not actually exist. So rather than raise any kind of panic, what the 'remove' method is going to return is actually going to be an Option enum. As a reminder, the Option enum has two variants. There is a 'None' variant, which indicates that there is no data or missing data, and the 'None' variant has no associated data in that variant. And then there is also a 'Some' variant which represents the fact that data was found, that there is something to give you back. And if you have the 'Some' variant, that variant is going to store an associated piece of data which will actually be the extracted value. So let me show you this example right here. I'm going to take 'years_at_company'. And since I'm going to be attempting to remove a key-value pair, that is considered a mutation or a modification of my HashMap. So I have to make sure to mark this as mutable first, but I'm going to call a method called 'remove' and it's going to accept a key. Right. There's going to be unique keys. So there's only going to be one occurrence of a key if it exists. So I do not have to provide both key and value. Simply the key of the key-value pair that I would like to delete. So let's say I try to remove Ben and I will assign this to a variable called Ben for now just so you can see the inference. Notice what I'm getting here is an Option with an i32. This is the type of the associated data in the 'Some' variant. So if the key of "Ben" exists, the 'Some' variant will store the associated value which will be 6 in our case. The key-value pair will be completely removed or deleted. I'm going to get back an Option that may or may not contain a value, depending on whether or not the key existed. If the key existed and it was removed, then my Option enum will be the 'Some' variant holding the corresponding value: in this case, 6. So let me show you once again I'm going to use the Debug formatter on my actual 'ben' variable. So you can see here is 'Some(6)'. So 6 is coming from right here. It is the corresponding value for the key of Ben that was removed. This 'Some' variant in and of itself means that the key of Ben was found. And of course if you want to take that 'Some' variant and get the actual nested value within it, there's many different ways to do so. You can do something like a 'match' if you want it to be more exhaustive. But for now, I'm going to stick with the basic 'unwrap' method to extract it. There's always the possibility that this fails if we have the alternative 'None' variant, but in this case we know that we have the 'Some' variant, so this will work just fine. And here you can see the value of 6 corresponding to the removed key of Ben. And then if I copy and paste line #7 below, we'll see that after this removal operation, our hash map is left with only two remaining key-value pairs. Let me try one more time to remove a key of Ben, which should no longer exist. So if we try this line again this time around, notice the return value is consistent. It's always going to be an Option that could contain an i32 in its 'Some' variant, but the actual concrete return value here will be the 'None' variant, because there is no more key of Ben to remove. So you'll notice if I output Ben here from the declaration on line #14, we can see that now we have the 'None' variant. So if I try to call 'unwrap' on this, we would get a a runtime panic. All right. So that is how we can insert or add as well as remove or delete key-value pairs from a hash map.

# The clone Method

The ownership model in Rust exists to prevent common memory problems that are present in other programming languages. Another benefit of ownership is that it requires the programmer to explicitly state when a copy should be made of heap data. Rust wants to avoid making copies when possible. It wants to be fast. It wants to use less memory, so we have to tell it explicitly, manually when we do want to duplicate heap data. So to force a copy of existing heap data and thus not move ownership and avoid the issue we're seeing here, we can invoke a method called 'clone' on the original value. So here on line #3, let's invoke 'clone' on the 'person' variable. The 'clone' method is actually a requirement of a trait called cCone. That trait is Clone with a capital "C", but the method that it mandates is this 'clone' method with a lowercase 'c'. When a type implements the Clone trait, the type promises that it will define how it should be cloned, or in other words, how it should be duplicated. The String type implements the Clone trait, so thus it supports the 'clone' method. So notice we are now able to reference the 'person' variable. After we assign 'genius', we can in fact run the program. We are going to get a warning because 'genius' is unused. But here on line #5, I'm outputting the value of 'person'. And 'person' is still a valid variable. So we could see its value of "Boris" right here. So what has happened here? In this example, there is no transfer of ownership. There is no move. Rather, there are now two owners for two separate, distinct but equal pieces of data on the heap. The 'person' variable is the owner for this String and the 'genius' variable is the owner for this cloned copy. All right. So this is similar to the functionality we saw with stack-based data like integers. But here with heap based data we have to be explicit and call 'clone' to get the same effect. Now the cost of the 'clone' method is that we have doubled the text. "Boris" on the heap. We are storing that text twice, and so we generally want to avoid doing this unless it is necessary. So if we can reuse the same string without creating copies of it, we should. So I want to make another point to close this lesson off. And that is that even though we talk about all of these optimizations, when you are starting out writing Rust programs, you shouldn't concern yourself with trying to minimize memory at all costs. So that means: don't be scared of the 'clone' method. It's okay to make copies. And then as you practice and get better, you'll figure out more ways to reduce making those extra copies, right? We'll see how we can accomplish this with references in the very next lesson.

# The String Type

In this lesson, we'll introduce a data type that is stored on the heap and that is the String. Now Rust has two core string types, which is a common point of confusion for new Rust developers. We've seen one of them before and that is the 'str' string. And we can see an example here on line 2. Whenever we use a pair of double quotes and that syntax is called a string literal, we have the 'str' version of a string. Now as it turns out, this type is actually not stored on either the stack or the heap. Rather, it is embedded directly into the binary executable that the Rust compiler produces. And the reason that is done is because the value is already known at compile time. In this program, this string will always be the text "pasta". It's always going to be those 5 characters in a row. It's not capable of changing or mutating, so at compile time, Rust knows that it can include this text directly into the binary. And what we have here is actually a reference which we talked about a little bit earlier, but we'll get more in detail on this a little bit later. Just realized for now that this is one type of string that is built into Rust. The String type that we're introducing in this lesson is a totally different string. It's literally a different type. It has a capital 'S' in its name, and the word Rust is spelled out fully. So this is the type that looks like this: String with a capital 'S'. This String type is still a piece of text. In more technical terms, it's still a collection of UTF-8 encoded characters. So why does Rust need this second String type? Well, this 'str' type is great when we know the exact string value at compile time, but that won't work in every situation. We sometimes need dynamic strings, strings whose size we can't predict at compile time, or strings that are going to change over the course of the program. For example, we may want to collect some bit of text input from the user, but we can't predict how many characters the user will give us. Or we may want to read a file's contents into a string, but we can't predict how large that file will be. Or we may simply need a dynamic string to which we can add characters, or remove characters, or replace characters within. These are all mutation operations, and they're all impossible with a 'str' like this. And they're all possible with a String like this, and that is because it is dynamic and mutable, which also means it must be stored on the heap. Rust doesn't know the size of the Rust data at compile time, so it requests the correct amount of space or memory when the program actually runs. So this Rust type is mutable, which means it can grow and shrink and change. But the heap is the perfect place in memory to support those kinds of operations. So to clarify, 'new' is not a method. It is a plain function but one that lives within the String namespace. You can think of it as being housed within the type. So we cannot invoke 'new' directly. Rather, we need to prefix it with the type String which is its namespace, and then with the two colons, we navigate into that namespace and it's there where we can find this 'new' function. This is in fact a common Rust convention where a type is going to define a new function within its namespace, and what that 'new' function will return is a new value of that type. We typically specify the type's name, two colons, then invoke the 'new' function inside that namespace and get back that type.

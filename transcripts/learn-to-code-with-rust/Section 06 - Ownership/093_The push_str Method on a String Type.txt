# The push_str Method on a String Type

In this lesson, I want to show you how we can mutate a String and also describe what happens on the heap in that situation. We're going to use a method called 'push_str'. And what it does is it adds content to the end of a heap-allocated Rust. The technical word for adding text to the end of a string is concatenation. So the 'push_str' method is not available on a string slice or a string literal. This is this type that we've seen before with the double quotes. This is text that Rust is going to hard code directly into the binary executable, and the program is actually working with a reference to that text from the executable. So we can't mutate something that is written in place in the executable file, but we can mutate a String on the heap. That is the entire reason why we created on the heap for that flexibility. Let's start out by declaring a 'name' variable, and I'm going to set it to a String of my name: "Boris", and we'll use the 'String::from' syntax from the previous lesson. This is the 'from' function within the String namespace or the String type. We're going to give it a string literal of "Boris". And now we have a String on the heap. Let's take a moment to explain what happens behind the scenes. This might be a bit confusing, but stick with me here. The string's text content will live on the heap, but this creation of a String will also create a stack entry. So there's data on both the heap and the stack. The stack entry will hold three pieces of data. The first piece of data will be a reference to the String, and remember, a reference is an address to the heap location where the text is stored. The second piece of information on the stack will be the length of the string, which is the current number of bytes that the text occupies. Now remember, the length of a string in bytes is not always equal to a count of its characters, and that's because certain UTF-8 characters, like emojis or foreign language characters, occupy more than 1 byte per character. For letters in the English alphabet, though, 1 letter is equal to 1 byte. So in this case this String will have a length of 5 bytes. Now, the third and final piece of information on the stack is the capacity and what the capacity is, is the amount of bytes that is available in the heap location. For example, the memory allocator on the heap might find a spot for "Boris", which has 5 or a length of 5 bytes, but maybe that spot in the heap has room for 10 total bytes, so we can have a length of 5, but a capacity of 10, even though we're only using 5 of those spaces. So the length is how many bytes we're using. The capacity is how many bytes we can use in that location. And the reason the memory allocator does this is precisely for that situation where the length might expand. If we add new characters, for example, and they can fit within the capacity, then we do not need to find a new place on the heap. We already have that memory allocated that we can utilize for new characters. So now, let's use the 'push_str' method to concatenate to the end of the string. Variables are immutable by default, so first up we'll need to add the mutable modifier. I'm going to add it right here to the name variable and that permits mutation of the String. The 'push_str' method is going to be invoked directly on my variable. And the method is 'push_str' It's kind of a abbreviated form of "string". It's a method to add content to the end of the string, to concatenate, to append, whatever word you want to use. And this method accepts an argument of a string literal, also called a string slice. So in this case, I'm just going to try to add a space and start my last name "Pask". And there you have it. And what I'm going to do is print out the value of 'name' before and after so we can see the differences. And there we can see we have modified or expanded the contents of the String. So I want to talk about two possible things that can happen when we concatenate. The first possibility is that the existing heap space has enough capacity to support the new characters. In that scenario, the new characters will simply be written to the heap's memory, so the reference to the heap stays the same on the stack, the capacity stays the same, and the length value grows to reflect the current number of bytes that are actually being occupied by text. The second possibility that can occur is that the allocated capacity in that heap location cannot fit the new characters. So, for example, maybe. We started out with a capacity of 10, and here we had a total of 5 characters. So 5 bytes. Here we have 10 characters. So 10 bytes. And now we try to concatenate again. So I'll once again invoke the 'push_str' method I'll add on the remainder of my last name. So what could happen here? Well, if the allocated capacity cannot fit the new characters, then the text will be moved to a new heap location with the greater capacity that can support the expanded size. And then the old space in the heap will be deallocated. And that's the beauty of the heap. It has flexible space to work with. So again, in a situation like this, perhaps the text will be moved to another heap location with the capacity of 20 bytes, and that stack entry will automatically be updated, so it will store a reference to the new heap location with the new length of, say, 15 bytes and the new capacity of 20 bytes. Every time we mutate the string with additional characters, if it can fit within the existing capacity that's been allocated, then it will. And then when the heap needs to move that string or its text content in order to fit the new characters, then it'll do so at the right time. Right. That's once again, the beauty of the heap is the dynamic element of it. Strings can expand in size, strings can shrink in size, characters can change. We gain the benefit of mutability, which we do not have with our regular string literals, also called string slices. All right. More on that in upcoming lessons. So I will see you there.

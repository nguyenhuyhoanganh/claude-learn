# Mutable Parameters

Just like variables, function parameters are immutable by default. This means we cannot mutate the parameters value within the function body by default. We have to explicitly declare when we want a parameter to be mutable, or in other words, capable of change, and, only after we've declared it as mutable, Only then can we perform some kind of mutative operation in the body of the function. So let me show you this in action. In my main function, I'll declare a String. I'm going to call it burger. And right here I'll assign 'String::from("Burger")' And then I'll define another function called 'add_fries' And it will accept a parameter called 'meal'. That's also going to be a String. And inside the body of this function. What I'm going to want to do is to take my 'meal' string, and I want to call the push string or 'push_ str' method to concatenate some text to the end. So let's say I want to add on the text " and fries". And that's also preceded by a space. So as a reminder, this method concatenates which means it adds content to the end of the string. In this case the 'meal' string passed in to this function. All right. So we're going to notice a couple violations here or a couple errors. But let's talk through them in sequence. So you might think starting here in main that we can simply call the 'add_fries" method and pass in 'burger'. And then you're going to see this violation. And you might think to yourself "Okay, this 'meal' string needs to be mutable here in order so that we can concatenate this text to the end of it. But "Burger", that string at this point is not mutable. So you might think that we can make this violation go away by making this 'burger' variable mutable, but you'll notice it's not going to fix this problem right here. So what's happening here? So the first key takeaway is that that this code will not work regardless of whether the 'burger' variable is mutable or immutable. And that is because ownership is going to move from the 'burger' variable to the 'meal' parameter when we invoke this function. And the 'meal' parameter here is immutable by default. It doesn't matter whether 'burger' is mutable or immutable, because 'burger' will no longer be the owner of this string when 'add_fries' is running. So let's come back to the previous lesson and let's review what's going on here. Remember, when we pass an argument to a function, we are either copying it or moving it. Well, let's say I copy and paste this line above. Let's say we ignore 'add_fries' for the time being. What would happen in this situation? Well, what's happening here is we're transferring ownership from 'burger' to 'meal'. 'burger' is declared as a mutable variable, which means 'burger' has the permission to mutate or modify the String. So we are totally able to do something like this: 'burger.push_str' and do something like " and milkshake", right? That's totally valid. But when we transfer ownership to 'meal', we are transferring ownership to an immutable variable. But the key takeaway here is every time ownership is transferring, we could be changing the dynamics of the name. Everything starts out as immutable in Rust, so the exact same principle is happening with the code that we started the lesson with. We are transferring ownership from a mutable owner, the 'burger' variable, to an immutable owner, which is the 'meal' parameter. 'meal' has not been marked as mutable, so it has no permission to modify the string that it is becoming the owner of with the 'push_str' method. All right, so how can we make this parameter mutable? We once again use the 'mut' keyword, but this time in front of the parameter name. So with variables we declare 'mut' before the variable name. With parameters, we declare it before the parameter name. So now we have a mutable 'meal' parameter that has permission to mutate the string that it receives right? So this code should now work. The answer is because it's not performing any kind of mutation operation, right? It's only when 'meal' is the owner right here that we are actually modifying the String. The Rust compiler sees that, as long as 'burger' is the owner, there's no actual mutation going on. 'burger' exists and then it moves ownership to the 'meal' parameter.

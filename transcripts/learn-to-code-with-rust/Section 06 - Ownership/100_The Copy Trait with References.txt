# The Copy Trait with References

Earlier in this section, we mentioned that stack types implement the Copy trait. This means that Rust will create full copies of those values when they are needed. For example, when assigning one variable to another. And the reason this is the protocol is because stack data is fixed in size and relatively cheap and easy to copy. Well, it turns out the same rules are going to apply to references. A reference is still a type. It's an address, but it's still a type, and references in Rust implement the Copy trait as well. That means if we have a variable storing a reference and we assign that to another variable, Rust will create a copy of the reference. So here I have the 'ice_cream_variable' which is a string slice. But that is also a reference. The ampersand symbol ( & ) should always remind you that it's a reference, that this is data borrowed from somewhere else. In this case, it's directly hardcoded into the binary, and we have a reference to that. But it could be a reference to heap data. The same rules apply. So for example if I assign a new variable called 'dessert' and I set it equal to 'ice_cream', we are not going to have any kind of movement of ownership. There's going to be two owners in this example, and they're going to each own a reference. And this reference right here of 'dessert' is a full copy of the reference from 'ice_cream'. So now the two variables, 'ice_cream' and 'dessert', both reference the same "Cookies and Cream" text from the actual binary. When we assign 'ice_cream' to 'dessert', Rust copies this reference, creating another reference that is pointing to the same underlying piece of data or the same underlying memory. So the stack will now have two entries. Each one is going to be a reference. A reference is still a piece of data. But what it is is an address to something else. So 'ice_cream' is still going to be a valid name in our program. There's no movement of ownership when it comes to the reference type. So I can for example reference 'ice_cream' right here. It is a reference, but as we know, when we use it within println! Rust is automatically going to dereference it, which means follow that reference to the underlying data source. So we're going to see "Cookies and Cream" printed right here. And I can similarly interpolate the value of my 'dessert' reference. That will also be dereferenced behind the scenes. And so we're going to see "Cookies and Cream" twice in a row. So we still have one total piece of data in the executable. This thing we just have two references to it. Think of this like two separate pieces of paper that store the same address. And that address will lead you to the location where "Cookies and Cream" is stored.

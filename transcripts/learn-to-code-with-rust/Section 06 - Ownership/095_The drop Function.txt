# The drop Function

I want to provide some more context on what happens when a variable goes out of scope and, as an owner, cleans up some heap allocated memory. Rust has a function built in called 'drop', and the 'drop' function deallocates memory on the heap. Rust automatically calls the 'drop' function at the end of a scope, at the closing curly brace, and it automatically passes in every variable one by one that is the owner of some heap data. So behind the scenes there is a 'drop' function, and Rust will call it with 'person' when the main function ends, when it reaches the end of its scope. Now the variable must be the owner of heap allocated memory. Stack memory doesn't work with the 'drop' function at all. As it turns out, this process that Rust does automatically, we can actually do manually. We can explicitly invoke the 'drop' function in our function to invalidate a variable and deallocate its corresponding memory before the function is done running. So for example, here I have my 'person' variable with a String. I'm going to invoke this 'drop' function. It's available at the top level. And I'll pass in my 'person' variable. So the 'person' variable is now invalid and cannot be used. And Rust will ensure that once 'drop' is called, the program cannot access the value again because if we tried to use 'person' again, it would be referring to a heap location that no longer has valid data. That data has been cleared. It's been deallocated. So of course if I try to use println! and output the value of 'person', this is not going to be valid because 'person' is an invalid variable, right? It's no longer the owner because it's gone effectively out of scope. But what's also interesting is if I try to do what we did in the previous lesson, which is transfer ownership to another variable. For example, if I declare a 'genius' variable and try to assign person to it here, that is also invalid. It's invalid because 'person' is no longer the owner, and thus there is no ownership to transfer to the 'genius' variable. 'person' stopped being the owner when the 'drop' function was called, because the variable was invalidated and the corresponding heap memory was cleaned up. So the 'drop' function in summary is what Rust is calling explicitly behind the scenes for every variable that is representing heap allocated memory when that variable scope ends.

# The Copy Trait

In this lesson, we'll learn about the Copy trait. We previously introduced the Debug and Display traits. A trait is like a contract that a type promises to uphold. When a type implements a trait which means it defines some kind of required method or methods, then the type promises to be capable of performing some kind of behavior that that trait mandates. So, for example, a type that implements the Display trait promises that it can be displayed, and types can implement some traits but not others. It all depends on the type. So in this lesson I want to talk about the Copy trait. The Copy trait mandates that a type can be copied, which means that a full duplicate can be created from it. Rust's primitive data types, or the fixed size ones that we store on the stack like integers, floats, Booleans, characters, and more. They all implement the Copy trait, and this means that full copies of those values will be created automatically in situations where duplicates are needed. So let's walk through an example of a situation that will trigger an automatic copy. We'll begin with a 'time' variable and I'll assign it to the value 2025 an integer. And below we'll declare a 'year' variable. And rather than assigning it to a value, we'll assign it to the value of time. So what do you think will happen here? Remember, the right hand side of the equal sign ( = ) is evaluated first. That means Rust looks on the right side. It sees the variable 'time' which is equal to 2025. Well, what happens next? Because integers implement the Copy trait, Rust will create a full copy of this integer on the stack. The value 2025. This means the 'time' and 'year' variables will hold and represent two duplicate, separate, independent copies of the value 2025. So, as a result, we will have two owners here: 'time' and 'year', and each owner will be responsible for one of the 2025 values. 'time' is responsible for cleaning up its stack entry of 2025, and 'year' is responsible for cleaning up its stack entry of 2025. It's generally easy to make copies of integers and other stack based data, because it is easy to locate items on the stack, and also easier to make copies of fixed size data. Its size is known in advance. Another important takeaway here is that the original 'time' variable remains valid after its value is copied to another variable, and we can prove this by using the 'time' and 'year' variable after this assignment. So I can use println! here and output something like the "The time is {time}" and "It is the year {year}". Run this code and we can see we are able to use both of those variables. That might be expected behavior for now. But as you'll come to see by the end of the section, it will not always work this way. It's only going to work this way right now, because we have simple types that implement the Copy trait. Now the same rules from the previous lesson apply. 'time' and 'year' are variables, and they're both valid until the main function ends, and then they'll both go out of scope, and then they'll both clear their respective values of 2025 from the stack. The 'year' variable is the first one to be removed, because it was the last one that was added to the stack, and then the 'time' variable will go out of scope as well, and its same value of 2025, that separate copy, will be removed from the stack as well. All right. So to close this lesson off with a bit of a summary, many of Rust's scalar types like integers, floats, characters, Booleans, and more all implement the Copy trait. That means it will create a copy when needed, such as with code like this. So you can practice this reassignment syntax with any of those data types to see the exact same result. But as you'll come to see later in this section, when dealing with heap data, the result will be different.

# The Dereference Operator

In this lesson, we'll learn about the dereference operator. Remember, an operator is just a symbol that applies an operation to a value. So the plus sign ( + ) is an example of an operator. It's the addition operator to add two values together. So the dereference operator is represented with the asterisk symbol ( * ) on your keyboard which is Shift + 8. It's this symbol ( * ). It's the exact same symbol that we use for multiplication. So what does the dereference operator do? To dereference means to access the data that a reference points to. So this symbol, the dereference operator, follows a given reference's memory address to the stored value at that address. So you can think of the asterisk as an instruction that says "Take this address, go to the address and get the value that is stored there". So this symbol can only be used with a reference because we need something with an address that the dereference operator can track down to the original value. So here's what that looks like. Right here, I'm going to do println! And I'm going to provide my interpolation syntax. And I'm going to write 'my_integer_reference' which is the reference, right? In front of the reference, I'm going to add my dereference operator ( * ). So this is saying: "Take the address that 'my_integer_reference' is storing. It's a reference. It's an address. But follow it to that place in memory and get the value that is stored there", which of course is going to be the original value of 2. So here we're going to see the value of 2. And I can repeat the exact same thing with 'my_heap_reference'. So, once again, println!. I'm going to interpolate a dynamic value. I'm going to write in 'my_heap_reference' and then provide my dereference operator ( * ) to follow the address in that reference to the original value that is being stored. And here, of course, it is our string of "Toyota". It's important to note that the dereference operator needs a reference. We cannot use it with a regular value. So you'll notice here that if I copy and paste this line and try to provide something like 'my_stack_ value', 'my_stack_value' is not an address, it's an actual integer. And thus it says this type integer cannot be dereferenced. The only type that you can dereference is a reference, right? It could be a reference to an integer. It can be a reference to a string. It can be a reference to anything. But it needs to be a reference because we need an address to follow. I'm going to remove that code. It's important to understand what's going on behind the scenes, which is why I wanted to show you the dereference operator first. But with that said, let's see what happens if we remove the operator and simply try printing out the reference itself. So here I'll remove the asterisk. And here I'll remove the asterisk as well. Notice that we are trying to print out a reference which is an address to a value. Right. What do you think we're going to get? We're actually going to get not the address but the actual value that is stored in that address. Right. So this is the exact same thing as printing out 'my_stack_value'. If we try to interpolate the address, we're actually going to get an output of the value at that address. And the reason for this is because Rust implements the Display trait for references, so that they will display the value that the address points to. Remember, when a type implements the Display trait, it defines a human readable string representation of itself. In this case, it's the representation of a reference. The technical type here is not an integer ( i32 ) , it's a reference to an integer ( &i32 ), and here it's a reference to a string ( &String ). So both of these are references. They're addresses. But when we interpolate them in a string, Rust sees the Display implementation which tells it to follow the address to get to the value, and then offer the string representation of the value itself, not the address. So this exists as a nice convenience that allows us to skip the dereference operator ( * ) in most situations. So what we just did with the asterisk is totally valid, but it's a little bit more verbose. It's automatically going to be handled in this situation, because Rust's Display trait implementation for a reference will automatically dereference. It's automatically going to take the address and say "I figure you don't want to see the actual address in memory. I'm guessing you probably want to see the value stored at that address. So I'm automatically going to dereference behind the scenes and give you the actual value". So what we saw at the beginning of the lesson is what Rust is doing behind the scenes when we write code like this.

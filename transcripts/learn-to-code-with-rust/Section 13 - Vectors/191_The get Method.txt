# The get Method

Another common way to access a vector element is with the 'get' method. The 'get' method avoids the problems with a non-existent index position, and what the 'get' method actually returns is an Option enum. As a reminder, the Option enum represents a situation where we have either some value or nothing at all, and there is a 'Some' variant and a 'None' variant. So if we provide a valid index position to the 'get' method, we're going to get back an Option that will have a 'Some' variant. And the associated data that it will store will be a reference to the element at that index position. If the index that we provide to the 'get' method does not exist, then the 'get' method will return the 'None' variant of the Option enum. So for example, here I can take 'pizza_toppings' from the previous lesson. I'm going to call the 'get' method and provide a sample index. Let's start with an index that we know exists. I'll do index 2 which should be our "Sausage" String right here. I'll assign this to a variable called 'option'. That variable name is up to me. But that's just to show you that our type here is an 'Option'. And remember this concrete type for the generic represents the type of the associated data that the 'Some' variant is storing. So no matter whether you have a vector of heap allocated data or data on the stack, the 'get' method will always return the 'Some' variant storing a reference. And that is just for a consistent design. That way you don't have to worry about the data type in your vector. You can just call get with an index and know that you're always going to get a reference, which will always allow you to get to the original value, whether it be something that implements the Copy trait or whether it doesn't. It doesn't matter. You have a consistent return value. So now that we have an Option, one thing we can do, as always, is combine it with the match keyword, which will force us to write an arm for each possible enum variant. So here I can use my 'match' keyword and match on my Option enum. This will not compile until I provide an arm for both 'Some' and 'None'. So I'll start with 'Some' and I can extract the corresponding data it stores, which I will call 'topping', and then I'll provide my arm and output some text like "The topping is {topping}". Notice once again here that when we are accessing this piece of associated data, the 'topping' name is up to us of course, but its type is a ref string ( &String ), and that is because it is a reference to whatever type is being stored within the vector. If this was an i32, this would still be a reference to an i32. It's always going to be a reference stored within that 'Some' variant. Now for the 'None' variant there is no associated data. So I can write it like this. And println! something like no value at that index position. And there we have it. So I'm going to run this file. We do have a valid index. So we're going to hit this variant right here: the 'Some' variant and output the corresponding text. The topping is "Sausage". Now I can provide an invalid index like 50. In the previous lesson, we saw that if we provide this to square brackets, we do have the potential for a runtime panic, which the compiler cannot warn us about. With a 'get' method, the advantage is this is safe 100% of the time, because in the scenario that the index does not exist, you're never going to get a panic. Instead, you're going to get the 'None' variant. So we're going to get the Option storing the 'None' variant. Hit this arm of the match statement. And we're going to see no value at that index position. All right. So get is a little bit of a safer option in your toolbox. That's all there is to cover in this lesson.

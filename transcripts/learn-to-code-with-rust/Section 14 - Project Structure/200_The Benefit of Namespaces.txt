# The Benefit of Namespaces

Another advantage of modules is that they enable us to have duplicate names within the program, and that is because each duplicate name can live within its own module, its own separate namespace, its own container with a unique module name. For example, let's declare another module in the same file. Once again, I'll use the 'mod' keyword followed by my module name. Let's select a module name of 'orders'. We can pretend that this is a separate part of our business, a separate logical container to isolate and categorize the constructs within our Rust program. Inside this module, within its pair of curly braces, I'll declare another public constant, and I'm going to call this one 'MANAGER' as well. So once again, we need a type for a constant. So this will be a string slice. And let's say the manager who is in charge of orders will be somebody like "Oliver Orderson". So now when we print each manager's name, we prefix that constant with the respective module name and the scope resolution operator. So here I can say something like println! And then "The manager of our orders is And here, I'll refer to my 'orders' module. Two colons the scope resolution operator ( :: ). And then our name is 'MANAGER'. Within here, it is publicly available so we can access it. And there we have it. "The manager of our orders is Oliver Orderson" So in other words, there are no name collisions. Rust has no problem with this because each 'MANAGER' constant lives within its own module, its own namespace. The namespace is like its own qualifier. It's exactly like how it works on a hard drive. We cannot have a file with the same name in the same folder, but we can have a file with the same name in two different folders, because the folders provide their own differentiating names. All right. So that is another benefit that you get from modules in Rust.

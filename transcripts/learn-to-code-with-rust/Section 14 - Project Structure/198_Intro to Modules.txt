# Intro to Modules

Welcome back to VSCode. As a reminder, in this section we're going to be modeling a warehouse. So our Rust code will include different functionalities for things like managing inventory and creating products. The next unit of organization to introduce you to is a module. A module is an organizational container that encapsulates related code. Inside a module, we can store any valid Rust constructs. We can have constants, functions, structs, enums, etc. We can describe a module as a container that collects similar pieces of code together. One analogy that I often like to draw is to compare a module to a folder on your computer. A folder has a name and it serves as a container for files and other folders. As far as how we want to organize our Rust constructs, it's up to the developer. Just like it's up to you to choose your folder names and how many folders you want to have on your system. So within a Rust program, you can choose whatever module names you want and what you want to store in each module. You can have large modules and small modules. It all depends on how you want to group or categorize the constructs within your Rust program. Each module will have a unique name that will serve as a namespace for the items that that module will store, that that container will hold. So first up let's explore how we can create a module. We declare a module with a new keyword called 'mod', 'm-o-d'. That is short for module. Then we provide a space and then the module name which is traditionally written in 'snake_case'. So I'm going to pick a module name of 'inventory'. This is up to me. And this will be one organized aspect of our warehouse management operations After the name, I'll provide a space and a pair of curly braces and everything that I write here within the braces will belong to this module. So we now have a module, an organizational container. You can almost think of this like a folder within our program. And this 'inventory' module is also a protected namespace around all of the content that it will contain. Within the 'inventory' module, let's declare some constants an enum, a struct, and a function just for some variety. Let's begin with our constants. As a reminder, constants require the 'const' keyword and an explicit type annotation. So when it comes to inventory, let's say we have a constant called 'FLOOR_SPACE'. And I'll declare this as, say an i32 and say we have 10,000 square feet of floor space. Let's also declare a constant called 'MANAGER'. Constants are going to be written in all uppercase and underscores between multiple words. We'll do 'MANAGER' here which will be a string slice. So I'll do a refactor here. And let's say our manager will be Ivan inventory. So these are two names within our 'inventory' module. Let's also declare an enum and I'll call this one 'ProductCategory'. Let's say that our company is going to produce two types of products. Let's say we're going to have ladders as well as hammers. And immediately I will also derive my Debug trait above using the 'derive' attribute like so. And once again this enum does not live at the top of our Rust program. It is specifically nested within, housed within the 'inventory' module. All right, let's also declare a struct. I'm going to call my struct 'Item' and 'Item' will have three fields.

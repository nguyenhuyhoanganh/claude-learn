# Multiple Binary Crates

So to review, a Rust package requires at least one crate, which can be either a binary crate or a library crate, and it can combine the two of them as well as we saw in the previous lesson. It can also optionally have multiple binary crates, which means multiple executable programs that are capable of compiling and running by themselves. All right. In that scenario, we can still use the 'main.rs' file, which can represent our primary binary program, if you will, but we can also ignore it. So what this allows us to do is essentially have multiple working programs within the same codebase. So in order to accomplish this, we need to create a new folder within our 'src/' directory right here. So right click, "New Folder" and our folder will be called 'bin'. 'bin' is short for :binary". And the way this works is that Rust will treat every Rust file, every file with a '.rs' extension within the 'bin' folder as a separate binary crate. So you can think of it as equivalent to 'main.rs'. But now these files can have whatever name we want. And the beautiful part about this design is that we do not need to change any configuration settings. The Cargo manager's default is to figure out which crates you have based on what source files are available, so it realizes any '.rs' files in the '/bin' directory represent independent executable programs, independent binary crates that it can compile. And the library crate that we have in the 'lib.rs' file can be used among any of our binary crates, and so any reusable code, code that is meant to be shared can be stored in the library crate in 'lib.rs', while our individual binary crates can each handle different bits of logic and continue to rely on the reusable aspects of the library crate once again by referencing 'warehouse'.

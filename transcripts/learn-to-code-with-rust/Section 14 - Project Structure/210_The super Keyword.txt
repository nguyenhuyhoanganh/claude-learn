We can also navigate in the opposite direction. We can start at a given location within a specific module, and access an item or name from the module above it, the one that it is contained within. So a common terminology to describe these relationships is parent and child. Modules can be described as having a parent-child relationship. The submodule is the child module. It belongs to a parent module, which is the containing module, the module that holds the submodule. Right. So we navigate downwards simply by writing the child module's or the submodule's name. How can we navigate upwards? We can't simply write the parent module from here. For example, 'products' is contained within the 'inventory' module. But from 'products' perspective, there is no way for us to simply write 'inventory'. Rust doesn't know what 'inventory' is at this level because we're one step downwards. We're one level or layer or dimension underneath. We are within the nested 'products' submodule. So in order to get access to the parent, we use a special keyword called 'super'. 'super' references the parent module. 'super' means above, just like the word 'sub' means below. A submodule is below us. A super module or 'super' is above us. I always like to remind myself of Superman who flies above us. That's a nice, easy way to remember this. So with 'super', we are getting the parent module from the current module. So anything that as a child can reach up into the parent and get something from it if it needs to regardless of whether the 'pub' keyword is present.

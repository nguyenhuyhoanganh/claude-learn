So it turns out that even our struct fields are private by default when declared within a module. This is a different behavior from enums, as we can see here. With enums, when we use the 'pib' keyword for the top enum, all of its variants are publicly available. However, when we use the 'pub' keyword for a struct, the struct technically the name becomes public. It becomes exposed so we can access the 'Item' name here. However, these struct's fields remain private. Very interesting nuance of the Rust language. So as it turns out, back in 'inventory', we can designate different struct fields as public or private. Once again, we need to add the 'pub' keyword before every struct field that we want to make public. And if we want to create a full 'Item' struct instance with our regular curly brace syntax like we're doing in 'main.rs', we have to mark all of these structs individual fields as public. So here I'll do 'pub name', 'pub category', and 'pub quantity'. So you might be curious, why does Rust even do something like this? Well, technically it is possible in more advanced design patterns to only make some fields public while keeping other struct fields private. And the way we do that is, for example, we can implement a public associated function that lives on the struct, that lives on the type, that constructs the struct instance, and then the associated function's body, because it lives within the same module, can provide a hard coded value for a specific private field. And this is valid because again, the associated function will live within the same module as the struct definition. In fact, if you have any private fields, that associated function is a requirement. That function needs to exist because it offers the only way to create an instance of this struct to have that public associated function return that concrete instance. If we want to use our regular curly brace syntax, however, we are using the regular instantiation protocol, in which case all of the fields in the struct need to be made public. One other note: when it comes to methods which we declare with the 'impl' keyword, followed by the type's name. We do not mark the 'impl' keyword as public. Rather, we mark the individual methods within the 'impl' definition as public or private. That allows us to make some methods public so that they can be called on the instance while keeping other methods private, essentially prohibiting them from being called from outside the module. Very nuanced, more complex design patterns that you'll see in more advanced Rust codebases. But just realize for now, that even Rust's struct's fields need to be declared public.

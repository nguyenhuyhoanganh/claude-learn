# Packages and Crates

Welcome to the next section of the course, which is all about project structure. We're going to begin in this lesson with a discussion on packages and crates. So all of our previous Rust programs have lived within a single 'main.rs' file. In this section, we're going to learn how we can create larger projects consisting of multiple files and folders. There is a lot of terminology to introduce you to, and to be honest, a lot of these terms can be somewhat confusing because of how similar their definitions can be. So I wouldn't worry too much about memorizing all of the nuances. It's more important to understand the big picture here, which is that this is all about structuring larger projects consisting of multiple files. So every Rust project begins with the 'cargo new' command. When we run the 'cargo new' command, we create a Rust package. Now, the formal definition of a Rust package is a folder that contains a 'Cargo.toml' file. You can think of the package as the top level project or workspace. At the end of the day, it's just a directory or folder that contains a 'Cargo.toml' file. That Cargo file holds metadata about the package, such as its name, its version, and any dependencies that it needs to run. Now, if we want to provide a more technical definition, we can also say that a package is a collection of one or more crates. A package must contain at least one crate, but it can contain multiple crates. So what is a crate? A crate is a collection of Rust code that produces either an executable or a library. And we're going to talk about that difference between those two terms in just a moment. A crate can also be described as the smallest amount of code that the Rust compiler considers at a time. So in the beginning of the course, we used the rust compiler, the 'rustc' command line tool, to build and run a single '.rs' file, and we did that without the use of Cargo. So in that scenario, the Rust compiler considered our single Rust file to be a crate. It's just the smallest amount of code that the Rust compiler can compile. So a basic .rs' file with a main function is enough to be considered a crate. Now there are two categories of crates. A binary crate is a program that compiles to an executable. A binary crate has a 'main' function that sets what happens when that program runs. So every crate that we have written so far in this course has been a binary crate. It is meant to run by itself. It is an independent program. The second type of crate, which we have not seen so far, is a library crate. A library crate does not have a main function because its intent is not to compile to be an independent executable program. Rather, a library crate exports functionality for other Rust programs, i.e. binary crates to share and reuse and utilize. So library crate is usually other people's code that you are pulling into your own binary crate. Now, in the Rust community, the term crate is usually going to refer to a library crate. It's some external dependency. It's somebody else's Rust code that you are pulling into your own project. However, technically speaking, the term crate applies to both library crates as well as binary crates. So in summary, a Rust project is a folder with a 'Cargo.toml' file that's also called a package, and that package must contain at least one crate, which can be either a binary crate or a library crate. It's also technically possible to have both at the same time, but you only need one, so you're going to have a package that's going to store or contain at least one crate. So all of the code that we've written so far in the course has consisted of a package with that 'Cargo.toml' file that has had one binary crate within that package. All right. So now let's talk about what we're going to be working on in this lesson. We're going to be modeling a warehouse management application. So for this section there is a 'warehouse' package that I created with the 'cargo new' command. If we run 'cargo new' without any additional command line arguments, Cargo will default to creating a package with a single binary crate. So the intent again is an independent executable program. Cargo creates that 'Cargo.toml' file and it creates the 'src' directory with the 'main.rs' file. Inside the 'Cargo.toml' configuration file, we have a bunch of fields. We have metadata and there is a special field there called 'name', which sets the name of the package. And in this section that package name will be 'warehouse'. Again, you can think of the term package as the high level project. It is the directory with all of our Rust code and a 'Cargo.toml' configuration file. So every package will have that. Now, Cargo is going to do a couple different things. The first is it's going to look for a 'main.rs' file in the 'src' directory within our package. If the 'main.rs' file exists, Cargo will assume that the package contains a binary crate whose name is going to be the same as the package. So in our scenario, we have a 'warehouse' package and it does contain a 'main.rs' file. So Rust will infer that we have a binary crate named 'warehouse'. Ok. Similarly, Cargo will look independently for a 'lib.rs' file within the 'src' directory. 'lib' is short for library, so if the 'lib.rs' file exists, Cargo assumes that the package contains a library crate also with the same name as the package. So if we have a 'src/lib.rs' file, Rust would assume we have a 'warehouse' library crate, and it is possible to have both at the same time. We can have a 'warehouse' binary crate and a 'warehouse' library crate. It all depends on whether Rust finds either one of these files, right? 'main.rs' means we have a binary crate at least. 'lib.rs' means we have a library crate at least. We can have both of these. But at the bare minimum, we need at least one crate within our package for it to be valid. So we can have either a binary crate or a library crate, or both, but we cannot have neither. All right, that's a lot to take in. Once again, don't overthink it. Don't commit all these details to memory. We're going to proceed through a lot of these concepts step by step and get a lot of time to review them. All right. But there's lots of fun up ahead as we start to explore how we can build larger and larger Rust projects with more directories and Rust files within them. So I will see you in the next lesson.

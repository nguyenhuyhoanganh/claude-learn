# Documentation Comments

In this lesson, we'll learn about documentation comments. A regular comment in Rust starts with two forward slashes ( // ), and then the compiler ignores everything after the comment. We can also create a special type of comment called a documentation comment, which consists of three forward slashes ( /// ). Then what the compiler can do is it can convert these comments into automatic documentation for your program. The compiler will auto generate a webpage that will have living documentation for whatever construct you want to provide documentation for. Could be functions, structs, enums, etc. and the compiler will use these documentation comments, these occurrences of three forward slashes in a row, to generate that documentation for you. It's pretty cool stuff. Now, as far as where we place these comments, it's very similar to how a directive works. We write our documentation comment directly above the line that we want to apply the documentation for. So for example, for my main function within 'main.rs', right above 'main', I'm going to add my documentation comment: three forward slashes in a row, then a space. And I'll write something arbitrary. Whatever it is that I want to provide in this comment, whatever it is that I want to explain. So I can say something like "Primary entrypoint into our warehouse program". So let's now apply documentation comments to a wide variety of different constructs, and we'll see how they appear in the browser in just a moment. So I'm going to open up my 'create_product_category' binary crate. Separate program within our 'bin/' directory. Once again, right here above the main function, I'll add three slashes, a space, and then provide my description, my annotation, my documentation, whatever it is that I want to communicate to future readers. So I'll put something like "create a fictional product category". Let's next go into our 'summary.rs' file. That's another binary crate. Once again above the main function, I'll provide three slashes. And this documentation comment will state something like: "Get a summary of our current managers". Now, more often than not, the benefit of documentation comments is for your library crates, because that's typically going to be the shared code, the reusable code that other developers will be utilizing. And they're the ones who are most likely to need clarification and documentation to understand what you are exposing from that library crate. So let's now transition to 'lib.rs' and once again we can provide documentation comments wherever we want. But we're going to place them on the line above the entity that we want to annotate. So for example here for 'inventory', I'll place my documentation comment and write something like. This module represents "Tools for inventory management". Same thing for 'orders'.I'll say "Tools for order management". So now we've annotated functions. We've annotated module declarations. Let's go into our 'products.rs' file which is our 'products' submodule in 'inventory'. Let's provide some annotations for our enum and our struct. So here above this derive syntax, since that is part of the attributes for my enum declaration, I can provide my comment and say something like "A category of product that our business sells". And then for our documentation comment for 'Item', once again on the line directly above our 'derive' attribute, I'll write "A concrete item in stock within our warehouse". We can also provide comments for functions and methods. So for this 'new' constructor function inside my 'impl' block, but directly above the declaration of the 'new' function, I can provide an arbitrary documentation comment like "Create a new item". Finally, let's do one more for a constant. Let's open up our 'mod.rs' file, which is the 'orders' module. Here we just have a single public constant called 'MANAGER'. I'll annotate this as "Our jolly manager", and you are not obligated to annotate everything. You can annotate or provide comments for as little or as a lot as you'd like, but now we have our documentation comments directly within the code, let's try generating the documentation. So I'm going to open up my Terminal which should open directly into my 'warehouse' package. And I'm going to run 'cargo doc'. "doc" is short for documentation. This will generate documentation.

# Module as File

In the previous lessons, we declared two modules with the 'mod' keyword and a block of code within curly braces. This code is totally valid, but it's actually one of three possible ways that we can declare a module in Rust. This approach is technically fine, but it cannot scale forever. All of our code still lives within one main file, and that is not going to be able to grow gracefully forever. The file will just keep getting longer and longer the more modules we introduce. So we're going to start to break things up in this lesson. But before we get there, let's once again talk about some of the technical terminology. So the 'inventory' module is declared within the main file. And Rust thus considers the inventory module and the 'orders' module to be part of the top level 'warehouse' binary crate. As a reminder, Rust knows we have a binary crate because we have a file specifically named 'main.rs' within our 'src/' directory. Rust also knows the name of the binary crate to be 'warehouse', and that name is specified in our 'Cargo.toml' file. So if I open up 'Cargo.toml' at the top level, here is the name field set to 'warehouse'. So Rust says you have a 'main.rs' file. I know you have a binary crate. And what is its name? Its name is 'warehouse' and that comes from the 'Cargo.toml' file. So 'main.rs' is what's called a crate root. A crate root is the root or base or foundation of the binary crate. The crate root is the starting point. It is the Rust source file that the compiler starts building the executable from. It is the entry point. It is where Rust starts to build everything. We can think of this crate root of 'main.rs' itself as constituting an unnamed root module. So for example, when we declare our main function here, it's not wrapped within any module. It sort of exists at the top level of the crate root, at the top level of 'main.rs'. You can almost think of it like living within an unnamed root module. Now, within this crate root of 'main.rs', we declare other modules. So for example, the 'mod' keyword declares there is an 'inventory' module, right? And Rust says: Okay, how do I figure out what are the contents of this specific module? Well, in this scenario we see the exact definitions inline, which means directly written within the curly braces within this file within this module declaration. But there are other ways that we can declare a module but define its contents elsewhere. Okay. We generally want to keep the main file, the crate root, pretty lightweight because it is the launching pad for our executable program, and we want the content here to be easy to decipher. We don't want a lot going on. So to start breaking things down and simplifying this, let's begin by moving our 'inventory' module to a separate file. So when we declare a module with the 'mod' keyword, Rust will look for the module's items in three different ways. So in this example again I apologize for the repetition. But in this example the module's definitions are directly defined within the curly braces. We do not have to define the contents elsewhere, they just coexist with the initial declaration of the module. The second way that Rust will look for a module is in a file with the module's name. So if for example, if we write 'mod inventory' by itself without curly braces, and let's pretend that this part here does not exist. If we write 'mod inventory', Rust will look for a Rust file with the same name. That means a file called 'inventory.rs' within the same folder. In this case, our 'main.rs' file is within 'src/'. So if we write 'mod inventory', Rust will look for 'inventory.rs' within the 'src/' directory. So let's extract this 'inventory' module's contents to a new file called 'inventory.rs'. Here I'll expand my files and in 'src', I'll right-click and create a new file. I'm going to call it 'inventory.rs'. All lowercase and with the '.rs' extension. All Rust files end in '.rs'. So what this file will do is create an automatic module, and automatic contained namespace. So let's begin by going back to 'main.rs'. And furthermore that part happens in main when we're going to be using this code. Therefore Rust will look for a file called 'inventory.rs'. And it knows that all of the content in here belongs to a module called 'inventory'. That happens automatically with this syntax. Therefore, we do not need this 'mod inventory' statement as well as the curly braces with this syntax. So now we can simply remove 'mod inventory'. Remove this and remove our closing curly brace. So the Rust compiler will start at the crate root which is the 'main.rs' file. Rust sees the 'mod' keyword. So it knows it needs to find an 'inventory' module and all of its contents. So the first thing it checks is for an inline definition. It looks for a pair of curly braces and looks for the content there. In this scenario, that does not exist. So Rust moves on to the second option. And the second option is if we have a module declared called 'inventory', Rust will look for an 'inventory.rs' file in the same directory, in this case 'src/'. So once again, if we add a module called 'nonsense', Rust would look for a file called 'nonsense.rs'. Right? Assuming we did not have curly braces, it's like a sequence of options that Rust will look for, and any one of them is suitable enough for us to understand what that module contains. So if it sees curly braces, that's great. But for 'inventory', it doesn't. So it then assumes it should look for an 'inventory.rs' file in the same directory. It then locates that file, understands its constructs. All of these constructs still live within a module called 'inventory'. Notice as well that we are mixing and matching the idea of a module as a file, along with an inline module declared with regular code. Mixing and matching is totally fine. These are all just different ways that Rust will look for a module and the contents that it is supposed to hold. All right, so hopefully that makes sense.

# Create Aliases with the as Keyword

In previous lessons, we talked about avoiding name conflicts, such as with 'MANAGER', by providing the module prefix before each duplicate name. Here we see an example with 'inventory::MANAGER' and 'orders::MANAGER'. If we were to import one of these names with the 'use' keyword, we would not be able to import the other one because there would be a name collision and Rust would be confused about what 'MANAGER' refers to. So this is one option to fix the problem. An alternative option is to import the names with aliases. An alias is a nickname or alternate name that we can give to an import to one of these shortcuts, and that alias will only exist within this specific file, within this specific import. We use the 'as' keyword to create an alias for a given entry. We previously encountered the 'as' keyword way back when, when we learned how to cast or convert one type into another. It's the exact same principle here. The 'as' keyword treats something like something else. But in this case, it's just a name switch. It's an alternate name. So here's what we can do here. I'll begin once again with 'use'. I'll provide my 'inventory' module. And in here I'm going to reach into 'MANAGER'. This by itself would be fine because there are no conflicts. But then I'm going to add a space and use the 'as' keyword. And this will allow me to provide an alias, an alternate name for this construct right here. So I can call it something like 'INVENTORY_MANAGER'. So now the name 'MANAGER' will not exist within this file, but the name 'INVENTORY_MANAGER' will. And what it will be is basically an alias for the 'MANAGER' constant within the 'inventory' module. Below, I'll do the exact same thing for my 'orders' module. It also has a 'MANAGER' constant and by itself, by the way, this would be totally fine because now this would be the 'MANAGER' name. There is no conflict with 'inventory::MANAGER', but just for consistency, let's give this one an alias as well. And I can call this one 'ORDERS_MANAGER'. So now there is no 'MANAGER' name whatsoever, but there are these two. So here I can remove our former code and just write 'INVENTORY_MANAGER' as well as 'ORDERS_MANAGER'. And these aliases offer us another way to avoid name conflicts. So now you'll also notice that we have multiple 'use' keywords for the exact same module which is 'inventory'. So as always, we can consolidate these two lines into one using curly braces. And within the curly brace syntax, we are welcome to use the 'as' keyword as well. So here I'm going to add curly braces like so. Then a comma. And then I'm going to cut and paste this section right here. Delete this line. And there we have it. We are importing 'FLOOR_SPACE', the name as is, from the 'inventory' module. And we are importing the 'MANAGER' name but renaming it or giving it an alias of 'INVENTORY_MANAGER' instead. All right. And that helps us simplify the number of import lines. All right. So that is a quick introduction to aliases for imports. And I will see you in the next lesson.

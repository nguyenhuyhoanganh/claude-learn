So next up within our main function, let's try to access a name from within our 'inventory' module. Let's say the 'MANAGER' constant. So I'll start with a println! And I'm going to say something like "The manager of our inventory is" and I'm going to try to interpolate 'MANAGER' by itself. Let's see what happens here. This is not going to work. If we try to output 'MANAGER' directly, we run into an issue because this name is inaccessible. In fact, it's not valid at all. The 'MANAGER' name does not exist within this scope. It does not live at the top level of our program. Rather, it is tucked away within the 'inventory' module. This is a container that encapsulates and holds this 'MANAGER' name, so this is not going to work. So to reach into the inventory module we need to use a special syntax. And that is the double colon syntax. The Rust community calls this the scope resolution operator. And we previously saw the scope resolution operator with associated functions. We write a type like say our struct or enum, or even something like a built in type like String. Then we provide the scope resolution operator, then the associated function name. It's a similar syntax with accessing a name inside a module, because it's the same idea. We are accessing some nested name within a namespace, a name that is stored within something else. So I'll try to provide here our module name 'inventory'. Then the scope resolution operator, two colons, and then our name which is 'MANAGER'. But unfortunately this will also not be enough. Let's take a look at what it says here. It says "constant MANAGER is private". Let's talk about the concept of privacy. The word private means just what it does in the real world. It is the state of being free from public attention. The opposite of private is public, which means existing in open view, easily accessible. Right? So by default, Rst considers every module item, every name within this module to be private. Private means that we can only access a module's items from within the module, within this scope. For example, our 'talk_to_manager' function inside 'inventory' can access the 'ProductCategory' enum or the 'Item' struct. That's because they live within the same module, the same container, the same scope, but nothing else has access to the content inside this 'inventory' module. In other words, we cannot access this item by default from outside the module, and again, outside of the module means outside of the scope of these curly braces. So in order to make an item public, we use a special keyword called 'pub'. 'pub' is short for public, and we write it before every item that we want to make public. We have to explicitly annotate every individual construct in here that we want to expose, that we want to make publicly available. If we declare something as public, that means that other parts of the program outside of the inventory module, outside of the scope, can access that item. So in regards to 'MANAGER', what we're going to do is write for 'const'. we're going to add that key keyword 'pub'. So now that constant becomes public. Every other item in here such as 'FLOOR_SPACE', 'ProductCategory' 'Item', and 'talk_to_manager' are still private. We have to explicitly write 'pub' before any construct that we want to make public. So now this code is finally going to work. There's a lot of warnings because these constructs are not being used. But here at the end you'll see "The manager of our inventory is Ivan inventory". That name is coming from this constant. All right. So to reiterate the name 'MANAGER' and that name could be anything, a constant a struct, an enum, a function. This manager name does not exist at the top level of Rust. It only exists within a nested namespace called 'inventory'. Furthermore, we cannot access this name unless the module chooses to make it public with the 'pub' keyword, and in order to access a named construct within a module, we use the scope resolution operator ( :: ).

# Module Ambiguity

So now we know that there are three ways for the Rust compiler to register a module's contents. The compiler will raise an error if it finds multiple definitions for the same module. In other words, we cannot have both an inline module and say a module file, or we cannot have, for example, a module file and a module folder with the same name. That represents duplication, and Rust doesn't understand what to utilize. So I want to show you this error in action. You do not have to follow along. Just note what's going on in the video. So within the 'src' directory, I'll create an 'orders.rs' file just like I did for inventory. This 'orders.rs' file would be totally fine as long as the 'orders' directory didn't exist and vice versa. Unfortunately now, even if I have nothing within the 'order.rs' file, Rust will be confused because it's not going to know where 'orders' is coming from. Is the module's contents found within the 'orders.rs' file or within the 'orders' directory's 'mod.rs' file? So here we can see "file for module 'orders' found at both 'src/orders.rs' and 'src/orders/mod.rs' "delete or rename one of them to remove the ambiguity". Rust doesn't know. So when I run this we're going to get the exact same compiler error. This is a fatal error. Our program does not run. So again the solution here is to have one or the other.

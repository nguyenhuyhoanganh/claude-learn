# External Crates

In this lesson, we'll learn about pulling in dependencies into our Rust package. A dependency is another crate, an external crate whose functionalities we will utilize. It's called a dependency because we will be dependent on somebody else's code. As a reminder, we have what's called a binary crate, and a binary crate is simply a Rust program that is designed to compile into an executable. It is an independent program. A dependency that we pull into our project is an example of what's called a library crate. Remember, a library crate is still Rust code, but its purpose is not to compile into a running executable. Rather, it is Rust code that exists to be imported and used by other Rust projects. So we're going to be utilizing somebody else's Rust code for our benefit. All right. So we're going to specify our dependencies within the top level `Cargo.toml` file. It is available right here. All right. And when we run either `cargo build` or `cargo run`, Cargo is going to download the source code for the dependencies that we list right here. In fact, when we list them we're also going to list the specific version number of the dependency. So Cargo will download the dependency including any sub dependencies. Because anything we list here may itself require other crates to function. But Cargo will take care of figuring out all of those requirements, downloading everything it needs, and then once it has the code, Cargo will compile all of the dependencies as well as our code and produce the final executable.

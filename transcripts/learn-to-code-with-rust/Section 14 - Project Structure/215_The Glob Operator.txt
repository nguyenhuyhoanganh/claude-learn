# The Glob Operator

In this lesson, I want to introduce the glob operator, which is the asterisk symbol ( * ), and the word glob is spelled "g-l-o-b". So this is also the multiplication operator. So it can be a bit confusing. But Rust will figure out what we're trying to do based on where in the code we're using this symbol. So we can use this glob operator within a 'use' statement to import every public name from within a module. So you can think of this asterisk as saying "Give me every public name from this module automatically without me having to write it out". For example, the Rust standard library has a 'collections' module, so I'll start with my 'use' keyword. Bring in my standard library. Then I'll provide my scope resolution operator ( :: ). In here, I have a nested submodule called 'collections' and in 'collections', I have a whole bunch of different data types. These are all various data structures that you might need in advanced Rust programs. So say for example, I picked the one at the very top here: 'BTreeMap'. So now I have 'BTreeMap' available to use directly within my program. But say I want to pull in some other names from this 'collections' submodule. Of course, I can provide my curly braces and separate every two items with a comma, but then I still have to explicitly list out every name that I want to bring in. In comparison, the glob operator looks like this. I'm going to follow up my scope resolution operator with a single asterisk ( * ), and then we provide our semicolon. So what this does is it automatically imports every name from that 'collections' module into the current namespace. So if I hold my Command key on a mac, and I believe it's the Control key on a windows. And I click into 'collections' and scroll down. Any name that you see here is what we're going to pull in. So 'BTreeMap', 'BTreeSet', 'BinaryHeap', 'LinkedList'. All of these names are now available directly within my 'main.rs' file. So you'll see this code from time to time, but it's generally not recommended because it may make it confusing to identify where a name came from since you now don't know explicitly that a name came from the 'collections' module. In addition, these imports are implicit, and they also increase the chance of name collisions because the 'collections' submodule might include a name that will conflict with another name from another module that you import from with the glob operator, and then it becomes harder to identify where those name collisions are coming from, because you don't even have the names explicitly written out in your code. There's a little bit of magic going on where we have a name like 'LinkedList' available to use in here, even though it is being brought in implicitly, magically with the glob operator. So that's why it can be a little bit confusing. And this pattern is generally not recommended, but you might see it from time to time. So I did want to introduce you to it. One other note throughout the course I may have mentioned the Rust prelude, which is a collection of names that Rust makes available to every program, even without the 'use' keyword. So these are the names that we automatically have access to in every Rust program. For example, we can use enums like Option and Result out of the box. We can use their variants out of the box. We can use types like vector. We can use traits like Copy, and they are available to use without any imports without any 'use' keyword. And why is that happening? How is that possible? Well, that's because the Rust prelude imports them automatically from their respective modules in the standard library. I can actually access that prelude directly. I just want to show you what it looks like. I'm going to say 'use std'. In here, there is a 'prelude' submodule, and in there there are a couple different submodules. I'm going to target V'v1' which is just short for version one. And if I similarly Command or Control click into here, this is the prelude that defines all of the top-level names that you're going to have access to in Rust. So for example here is our Option enum. We're providing 'self'' here. So we're going to have Option available as a top name to use. But also it's 'None' and 'Some' variants. Same thing for the Result enum and its 'Err' and 'Ok' variants. Here are some traits whose names are available for us to directly use within the program. Right? If I scroll down, we're going to see some other things that we may or may not be familiar with. Here's the String type, here's the Vec type, etc. These names are available automatically, so you can think of what happens behind the scenes as the equivalent of this. It's the equivalent of the Rust team reaching in to this 'v1' submodule, and pulling in all of the names with the glob operator. This is what is happening secretly behind the scenes every time we run a Rust program, and that is what allows us to have these names available in our program without having to write the code manually, right? That's why the operator, the glob operator, is in the language because it supports facilitating operations like this. But more often than not, it's going to be handled by other people's code and code in the Rust library. Once again, while we can use it and sometimes it is helpful, we generally try to avoid using the glob operator because of the possibilities for name collisions, and also the implicit, more confusing nature of it where we don't know where a name came from.

# Mutable Array Slices

Rust does not permit mutable slices of strings. If we are borrowing a string slice, we can only do so immutably. We cannot modify any element of that slice, which is a reference to a portion of the original string. However, Rust does permit mutable slices of arrays, and that's what I want to show you in this lesson. So let's begin by declaring a mutable array of integers. It needs to be made mutable because our mutable slice that we'll show you in just a moment will eventually modify this array's elements. So 'let' for my variable. Then, it's going to be a mutable value with the 'mut' keyword. I'm going to call my variable 'my_array' and assign it to an arbitrary array of integers. Let's do 10, 15, 20, 25, and 30. Once again, we do need mutability here because the original owner of this array, which is the 'my_array' variable, needs to be aware that the value it represents is going to be changed by something else, by a mutable reference. So below, let's borrow a mutable slice. The syntax is going to be a combination of several syntaxes that we've seen before. So here I'll declare a variable called 'my_slice'. What is the slicing syntax. It's going to be the borrow operator ( & ) followed by our array: 'my_array'. Then the sequence that we want to borrow, starting from the starting index position and then to the ending one. So let's say we target index positions 2 up to but not including 4. This is a slice. This is a category of a reference right. It is not taking ownership. It is borrowing but it is borrowing a fragment. But by default with this syntax, this is an immutable slice. So we have permission to read the data at the original address but not to modify it as a reminder, what we can do to make something mutable is to add the 'mut' keyword. We saw this in the references and ownership section of the course, but in those examples we were having a mutable reference to the complete original entity. Here we're going to create a mutable reference, but just to this slice or chunk that we are creating a borrow for. So when I add the 'mut' keyword right here, I'm going to have the ability to modify anything within this slice. But this slice is only going to consist of these elements right here index 2 and index 3. Right. This is the subset that we have targeted with our slice. And now we have made that reference to this portion mutable. All right. The ampersand ( & ) here in the type indicates a reference. The 'mut' after the borrow operator ( & ) means a mutable reference and a mutable reference to what: an array of i32 values, right? If we do not include any of these types. Should we choose to write an annotation, it's going to be a type mismatch, right. So it's important to understand what exactly is being inferred here. So to restate: the 'my_slice' variable is not an array. It is not an immutable reference to an array. Rather it is a mutable reference to an array and more specifically, a mutable slice, which you can think of as a subcategory of references. It's a mutable reference to a portion of the greater whole. So first up, let's see what 'my_slice' looks like. Here I'm going to use println! and I'll output my slice and provide my Debug formatting for the value of 'my_slice'. And we should see two elements: 20 and 25 which is a slice to this portion of 'my_array'. So now let's go ahead and mutate the immutable slice by using our square bracket syntax to target an index and then an equal sign and the new value. So this is our slice, 'my_slice', which is mutable. I'm going to target index 0 and then use an equal sign to assign a value of 100. So we are mutating a portion of the slice. But the slice itself is a portion of the greater whole of my array. So in doing this, I will inherently modify the original array of my array we are focusing in on this section. This is what my slice represents. And we are modifying element 0 of the slice which is 20. But in modifying this section, this chunk, this portion, we will also inherently mutate 'my_array'. So if I take a look at 'my_slice' after the fact, we're going to see 'my_slice' has indeed updated the value at its index position 0 from 20 to 100. However, if I output the value of 'my_array' afterwards, 'my_array' will also be affected. Here, the original value of 20 was replaced by the value of 100, right? This extracted this portion, or rather a reference to this portion. It did not take ownership of these elements, but it provided a slice or a reference to this chunk. Then it updated part of that chunk, which itself was part of the greater whole, which led to the original array being mutated. All right. That just goes to show that it's the same idea of ownership and references, and the same principles of mutability versus immutability that we saw in the references section. The only difference here is that there's additional complexity because we're only affecting a portion. We're not borrowing the whole 'my_array', we're borrowing a sequence of it and then modifying that sequence through the mutable slice called 'my_slice' And that will have an impact on the larger 'my_array', from which the mutable slice is created from.

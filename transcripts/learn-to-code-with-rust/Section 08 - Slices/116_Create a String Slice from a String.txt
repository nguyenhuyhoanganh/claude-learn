# Create a String Slice from a String

Now that we have a better understanding of the theory, let's take a look at slices in action. We'll begin with string slices. We can create a string slice from either one of Rust's two different string types: 'str' or 'String'. Let's start with the easier example, which is a string slice from a heap allocated String. So I'll begin by defining an 'action_hero' variable, and I'll set it equal to a string of the text. "Arnold Schwarzenegger", my favorite childhood actor. There we go. So first up, as a quick reminder, we can create a reference to the complete String. That is the syntax that we explored in the previous section. And it looks like this. Here, I'll declare a 'string_reference" variable and I'll use my borrow operator, the ampersand symbol ( & ), provide the 'action_hero' String. Now I have a reference. This is not technically a string slice. It's a reference to the complete string, and its type is &String. &String We saw this in the previous lessons, so here I can output the contents of 'string_reference'. That will dereference the address to get us "Arnold Schwarzenegger" right here. So this syntax is totally fine, but its disadvantage is that we can only borrow the whole String value. We cannot borrow a portion or chunk or slice of the original text. Now let's turn that into a reality. The syntax for borrowing a slice is very similar. We're going to begin with our borrow operator ( & ) because a slice is still a reference. We're then going to provide the value to borrow which is still 'action_hero'. But then we're going to provide a pair of square brackets inside those square brackets. We're going to specify a range. Now we discussed the Range type earlier on in the course in the data type section. A range represents an interval or a sequence. In this case, inside the square brackets we declare a range of bytes to borrow. It's important to note that the range will contain the index positions of the bytes, rather than the index positions of the characters. One English alphabetic character is equal to one byte, so this example will work as you expect. But remember that not every character is going to be one byte long. For example, an emoji might occupy 2 or 4 bytes in memory, even though it visually appears as one character. So inside the range we are specifying a byte interval, a byte range, not a character range or interval. So let's try to target the first name here. So these characters or the bytes that represent the characters of "Arnold" right here. So I'll rename my variable to 'first_name'. And in here I'm going to use my range syntax. As a reminder, that consists of a lower bound, two dots, and then an upper bound. So I'm going to write 0..6. So what I'm saying here is start at byte index 0 and then go up to, but not including, byte index 6. That's going to be a total of 6 bytes, which in this example is going to be 6 characters, the first 6. So here I'm going to output 'first_name' and we're going to see just "Arnold". So take a look at the type that you see assigned to 'first_name'. This is an example of a string slice. It is a reference to some portion or fragment or slice of the original heap allocated String. This type right here is called a 'ref str', also equivalently called a string slice. Now you'll notice this type likely looks familiar because we've seen it before when declaring basic string literals with double quotes. We're going to come back to talk more about that example in the next lesson. But for now, notice that the type is the exact same. We are welcome to explicitly annotate the type as well. For example here, the type is not going to be 'str'. It's not going to be a String, and it's not going to be a reference to a string ( &String ). Rather, it is a string slice, a reference to some portion of the original String which is annotated '&str'. Now here once again, Rust is going to dereference the address to get to the original value in memory. But now we are storing the address not of the complete string text on the heap, but basically an address to just the first 6 bytes which comprises the content. "Arnold". All right, so now let's repeat the process by targeting the last name. So similarly here I'll declare a 'last_name' variable. The syntax remains the same. We are borrowing. So we use the borrow operator. Then we provide our original content by itself. This is valid, but this creates a ref string ( &String ) which is not the same thing as a string slice ( &str ). To create a string slice, enabling a reference to a portion or piece of the original content, we declare those square brackets to provide a range. That represents the interval of bytes or the chunk, in other words, of the original content that I want to borrow, right? I am borrowing a fragment here. So for example, here the capital 'S' in "Schwarzenegger" starts at byte number 7. Byte 6 is the space in between the two names. And then the final 'r' in "Schwarzenegger" is index 20. So I'm going to start at index 7. Then go up to but not include index 21. Remember, the final index in this interval sequence, in this range syntax, we go up to it but we do not include it. So we want to go up to the hypothetical index 21 but not include the value there. So here you'll notice if I output 'last_name', we're similarly going to get a string slice. Same type. But now we're borrowing that portion of the original String. It's important to note that there is potential for error here. Rust will panic at runtime if we go outside the byte boundaries. For example, let's update this range to go up to but not including byte 22. So again, the last 'r' in "Schwarzenegger" occupies index position 20 or byte 20. But if we go up to 22, that means we're going to include 21, which does not actually exist. So we're going to see a panic at runtime. Panic means Rust encounters an error and is unable to proceed further. You can see right here: byte index 22 is out of bounds, right? That's the issue you're going to see. Now beyond that ... that's just a case of potential error ... The important thing here is to notice the types of these two variables. This ampersand str ( &str) is called a "ref str" or a string slice. And it represents a reference, a borrow but of a chunk of the original content. And again that chunk is technically by bytes in memory rather than by characters because one byte is not always equal to one character. It is with plain English alphabetic characters, but that is not always the case. More on all of this in the following lessons.

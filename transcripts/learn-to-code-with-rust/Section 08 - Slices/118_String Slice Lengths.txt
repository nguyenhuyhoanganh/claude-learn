# String Slice Lengths

Next up, let's talk about the length of a string slice. The length of a string slice refers to a count of its bytes, not a count of the number of characters we see. We can invoke a method called 'len', which is short for length to get the length of a string slice. For example, here I have a 'food' variable that is set to the string slice "pizza". This is a collection of 5 bytes, and that is because one English alphabetic character occupies one byte in memory. So for example, if I want to output a dynamic value and will take our string slice and call the 'len' method, 'l-e-n', that is short for length, we're going to get the length in bytes, which is a total of 5. And then if I create a smaller subset of my original characters, for example, here I'll declare a 'pizza_slice' variable. I can provide our regular slicing syntax. So our borrow operator ( & ), 'food' And then let's say I target the first 3 bytes. So I'll do 0..3. This will be a reference or a string slice to the first three bytes of the text data in the executable. So similarly, if I copy this code and replace 'pizza_slice' right here, this is the letters "piz". And so its length or the number of bytes that those three characters occupy, the length of the area of memory that we are referencing, is three. Now, when dealing with English alphabetic characters, we've been pretty lucky because one character always occupies one byte in memory. But remember, that is not always the case. We have to be careful because this slice range must occur at valid character boundaries. In other words, if we have a character that occupies multiple bytes and we use this syntax, we can accidentally stop at a byte that is in the middle of a byte sequence representing a single character. So let me give you an example. Let's say I want to replace this content with an emoji of a pizza slice. That emoji is actually part of the Unicode character standard. So I'll delete all of this content. And then there's a shortcut we're going to utilize on our respective operating systems. So on a MacBook, I'm going to press the function key ( Fn ) and the letter 'E'. And on a Windows computer, I'm going to press the Windows key on the keyboard. And then the period ( . ) And either one of those shortcuts should bring up the emoji keyboard. It looks something like this. There it is. And here I'm going to select the pizza slice. There might also be a search bar where you can search for an emoji. And so I'm going to select this pizza slice. And you can see to us human beings that appears as one character. Now I'm going to comment out these two lines of code and run our program. And notice that the length in bytes of that character is 4. It appears to us visually as one character, but behind the scenes it occupies 4 bytes in memory, and that is the 4 bytes in memory that loads in the binary executable file's contents. And that's what 'food' is a reference to. It is a reference to that memory address. So if this thing occupies 4 bytes in memory, what's going to happen when we attempt to create a slice to just the first 3 bytes of that required 4 byte sequence. We're going to run into a runtime panic because this is not a valid character boundary. We cannot take a partial collection, right, of those 4 bytes. We cannot provide a reference to a invalid byte sequence that doesn't represent a full valid character. So you'll notice right here it will tell us this byte index 3 where you are ending is not a valid character boundary. It is inside the collection of bytes representing that pizza slice emoji. And it'll tell us that complete collection of bytes is 0 through 4. So the only way that we can take a valid string slice in this case is if we do 0 through 4 because that will capture the bytes representing the complete character. Same rules will apply, of course, if I, for example, go to a final byte position of 2 or a final byte position of 1. Any one of these examples suffer from the same problem. They are not extracting a valid character at its respective byte boundaries. And now if I switch this to 4, we're going to see that we get what we want. We are able to have a compiled and running program, and all of this is just to demonstrate and reinforce the idea that a string slice is ultimately a reference to a sequence of bytes, not a sequence of characters. It is an address to a chunk of sequential memory, or a portion of sequential memory that holds some content. Usually, because we're dealing with regular alphabetic characters in most of our work, we're not going to run into this problem because one character in most languages is equal to one byte required in memory, but that is not always going to be the case when dealing with special symbols and emojis. So I wanted you to be aware of that caveat.

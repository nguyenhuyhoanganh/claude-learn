# Mutable Reference Restrictions

A value in our program can have any number of immutable references at the same time. We saw that in the previous lesson. The next rule to remember is that a value can only have a single mutable reference at a time. So if we declare a single mutable reference, we cannot have any other reference to that same value coexist at the same time. Once we declare a single mutable reference, we cannot declare a second reference at the same time. Regardless of whether that second reference is mutable or immutable, it does not matter. The compiler will prohibit it. So let's talk about why that rule exists. We can't simultaneously have a mutable reference and another reference because that would create the potential for the problem described in the previous lesson. The mutable reference has permission to mutate the value, while the immutable reference expects that data at that location to remain what it originally was. It's that same analogy about one friend expecting a blue car, while the other friend has permission to change it to be a red car. If that second friend starts changing it, well, then the first friend's expectations are not met. It's the exact same principle here. A mutable reference has permission to change, so if there's any other reference depending on the original data, it may accidentally depend on data that is no longer what it is or what it planned it to be, because the mutable reference has the potential to change it, and the compiler wants to prevent that from happening.

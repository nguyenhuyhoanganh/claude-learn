# Debugging in VSCode III

In this lesson, I want to explain what the other buttons on the debugging toolbar do. All of the buttons relate to navigating through the code, but not from a position of navigating from breakpoint to breakpoint, which is what the Continue button does, but rather navigating function by function or even line by line. Now, you'll still need at least one breakpoint somewhere in the code, because the buttons will only apply when we are paused at some breakpoint. If we have no breakpoint and we try to enter into Debug mode, well, then the program will just execute normally, never pausing just like if we ran the Run button. So I want to show you at the very beginning here that if I remove our two breakpoints right here and here by clicking on it, and I try to run the program in Debug mode, it will just run regularly. We're going to see that toolbar appear very quickly at the very top. But then there are no breakpoints, so it successfully finishes executing. So we need at least one breakpoint. So here's what I want to do. I want to take my 'countdown' function that I am currently calling in 'main', and I want to call it a total of three times. And then I'm going to place a break point at the very first line in the main function. And that will just establish again a stopping point. So let's begin by pressing Debug. We are now running in Debug mode. And we're going to pause at the very first breakpoint. So of course if we press Continue, that is going to progress to the next breakpoint. There are no more breakpoints because we are only declaring one on the very first line of main. So that of course will complete the program. Now, if I enter back into Debug, this second button that we have is called Step Over. And it's just like the name suggests, whenever you're on a line with a given function invocation, you have a couple options. You can choose to explore that function by going into that function and navigating through its code one line at a time or one breakpoint at a time. Or you can choose to step over it, which means run this function but ignore the internals. Ignore the nested steps of what's going on here. So if you think about stepping over something on the ground, it's the equivalent here. We are stepping over or ignoring this function and what this is going to do once I click it is it's going to progress over the first invocation of the 'countdown' function and then land on the next line to be executed, which is line #13. Now notice we did not place a breakpoint on line #13. This is just the automatic navigation that's going to happen if we use any one of these buttons. So we are no longer navigating by breakpoint. We're actually navigating line by line. But we're choosing to step over a given function versus step into it. So once again this button is Step Over. Ignore it. And it has the keyboard shortcut F10. So if I press it again, we're going to step over this second invocation of 'countdown' on line #13 and then land on the final invocation. Now we're not skipping the code. We're not ignoring it. It's still executing it. We're just not concerned about the internals of the function. So you can see on the right hand side here in my terminal, I have the outputs from the previous two invocations of 'countdown', which proves that the function ran twice. Right? We've just stepped over the internals. And if I step over one more time, we're going to enter into this interesting state where we are kind of paused at the conclusion of the main function. In fact, if you click Step Over again, we might enter into this weird state where we start going deep into the Rust internal code. We're basically inside the Rust source code that deals with the conclusion of a function. Usually, if you're this deep, it's probably some internal detail that you don't care about. At that point, you can always press Continue to progress to the next breakpoint. And since we have no breakpoint, we're going to reach the end of our debugging. And there you have it. Right. So that is Step Over. It steps over a given function invocation. Now if I start again in Debug mode, the button right next to it is called Step Into and it has the keyboard shortcut F11. This does the opposite. Rather than stepping over the function and ignoring it, it steps into it. Which means we're telling Rust: "We do want to explore the internal code in the given function on the line that we are on." So this is going to step into or navigate inwards into the 'countdown' call. So this is our first 'countdown' call on line 11. You can see 'seconds' here is equal to 5. And once again there is no breakpoint on line #2. But now we are sort of transitioning the mode of navigation to navigate line by line. So if we do not have a given function call on a line like we do here on line #2, and we press Step Into again, it's not going to navigate inwards because there's nowhere to navigate into. There are no nested function executions. So instead, this button will simply progress us to the next line of execution. So after our if statement, the next line is logically the first line in the else clause, because 'seconds' is equal to 5. So now we are in here. Once again println! is not a function, it's technically a macro. So if I press the Step Into function, it's going to navigate us downwards, once again pausing on line #6. And now we have the exact same options available to us. We can either step over this nested invocation of 'countdown', which will keep us at the top level of the first 'countdown' with an argument of 5. And if I press Step Over again. Now we're back in main after the conclusion of the initial invocation of 'countdown' with an argument of 5, or just to start from scratch if I have the exact same option by stepping into 'countdown', pressing that a few more times until we get back here, if I press Step Into again, then I'm saying I do not want to skip this invocation of 'countdown'. I want to step into that one, go one more level or layer or function call deeper so I will step into 'countdown' with an argument of 4. And then the process begins anew. I can once again say Step Into to keep progressing until I get to the next function call, at which point I can choose to either step over it, ignore that nested function call, or step into it with the next button to go one more level deep. Now the final button on our toolbar is Step Out. What that does is it takes the current position that you are within, the current level or layer or function execution, and it completes it and returns you back to the higher level, the layer that is one above. So it's important to note here this is not reversing code or moving backwards. It's just saying whatever layer that I'm within, complete that layer. Complete that nested function invocation so that you can return back up to the original caller that got us to this nested function execution context. So currently we are in the invocation of 'countdown' with 'seconds' equal to 4. So if I go back up we are back up to our higher level 'countdown' invocation, where 'seconds' is equal to 5. You can see all of the invocations have completed, and we are now finalizing that first invocation of 'countdown' with an argument of 5. So this is after all of the nested recursive calls have completed. This is our first invocation of 'countdown' with an argument of 5. All of the nested code has completed. So now if I press Step Into, we are at the conclusion of that function, and then we are back once again at the top level of 'main' at the conclusion of this invocation of 'countdown' with an argument of 5. So if I continue downwards, we are now once again at the next breakpoint, which is just the next line. And once again have the same choice. We can step into this invocation of 'countdown'. We can then press this button to step back out, which takes us back to the conclusion or finale of this second invocation of 'countdown'. So now we are back at 'main' and can once again choose to progress forward to the next invocation of 'countdown'. So again, Step Over steps over the function call, still executes it, but ignores the internals. Step Into navigates into the function call. And if you don't have a function call, Step Into will simply progress to the next line of code, one line at a time. You can almost think of it as creating automatic breakpoints line by line, but you are within a nested execution context, inside a nested function call. And then if you want to return one level up, return back to the original caller function that got you into this context, you want to return back up to where you stepped into the current function that you are within, this Step Out will take you one level up. Right? So if you realize you've navigated too far down and you don't want to keep navigating line by line in the current function, you can just return back to the caller at the point of completion, at the point of finishing the current function that you are within. You can do so with Step Out, and you can of course progress as many levels or layers or function calls down and up as you need to get to the point of code where you want to pause and take a look at the current state of the program. And then, of course, this final button that I unfortunately neglected is this Restart button. As you might guess, that just clears the slate and begins the debugging process anew. So that will take us back all the way to the start of main. And the first line, which is paused before the execution of 'countdown'. Right? So this is basically the equivalent of just starting from scratch. If you were to finish the debugging and click Debug again, it will take you to the beginning. And that's exactly what Restart will do right here. It just spares you an extra button click. Right? And that's all the available buttons here on the toolbar. Once again, they're there to assist you to either progress by breakpoint or by navigating function by function, line by line into whatever nested context you want to in order to take a look at the code at that juncture. And then also reverse yourself and head back up to the higher level or layer or context if you want to break out of the current level that you are within. All right. So that is the debugging toolbar in VSCode.

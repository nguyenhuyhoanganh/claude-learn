# The else if Statement

When our program consists of multiple related conditionals, we can tie them together using an else if statement. An else if statement can only be applied after an initial if statement. It cannot live independently by itself. The else if statement allows us to check for another condition after the first if statement, and that second condition corresponds to a separate block of code to execute. The way it works is like this: If the first if statement evaluates to true, then its associated block is run. If the first if statement evaluates to false, then Rust will evaluate the else if statements that follow afterwards, and there can be any number of else if statements afterwards, so Rust will keep trying until it finds the first conditional that evaluates to true. Rust is looking for the first true value and it will execute the corresponding associated block. Let's take a look at this in action. Let's say that I have a variable called 'season', and I'll set it equal to a string of "summer". There are 4 seasons: summer, winter, fall and spring. And say I want to execute a different block of logic depending on what season I have in my 'season' variable. So I can begin with an if statement and use the equality operator ( == ) to compare my 'season' variable with a string like "summer". Here, I'll provide my block just like in the last lesson. And I'll output some text like "School's out". So here I can write something like if the season is equal to "Winter" and then I provide another pair of curly braces. That represents the logic to run if this statement evaluates to true. And Rust is only going to check if this statement evaluates to true, this one right here, only if this first one was not met, so only if the season is not "summer" will Rust even check if the season is "winter". It's like a sequential check. First check this and run the associated logic if it's true. Otherwise, continue checking until you find the first condition that is true. You might be curious about the difference between this syntax versus writing 4 separate if statements. So I could in theory do, if 'season' equals "summer", and then repeat that logic 4 times comparing season to the other values. So this code is technically valid, but it's actually going to operate differently. The difference here is that each if statement is an independent construct. If we have 4 if statements like this, Rust will evaluate all 4 of them guaranteed. And there's the possibility that if multiple if statements evaluate to true, then multiple blocks will be executed. Each one is an independent check because each one starts with just if. With this else if design, Rust, in comparison, will look for the first conditional that evaluates to true and it will not execute any other else if statements that follow. It's looking for the first match, not for all matches. That's the difference. If Rust, for example, gets a true here, it's not even going to bother evaluating else if right here and elseif right here. So which one you use depends on how you want your program to function and what you want it to do. Generally speaking, using else if is recommended when your conditionals are all related as they are in this scenario. We just want to check if 'season' is one of these four values. All of these checks are connected to each other. We probably do not want to check anything else after we get our first true, and thus it makes logical sense to use if and else if. In comparison, we would use multiple if statements separately when our checks are independent, where we may want one bit of logic to run if something is true, and then another bit of logic to run if something else unrelated is also true.

# Nuances of unwrap Method on Result

There are some interesting caveats when we use the 'unwrap' method on the Result enum type, and I want to show you them in this lesson. So as we know the Result enum defines two generics: 'T' and 'E'. Rust knows that either type can be stored inside the Result in the two respective variants. The 'Ok' variant stores data of type 'T', and the 'Err' variant stores data of type 'E'. Whether we're using a method like 'unwrap' or 'expect', or a construct like the 'match' keyword, we are reaching into the Result enum, the container, and attempting to pull out a value from either the 'Ok' variant or the 'Err' variant. The problem is the type that is being stored that we are extracting may or may not implement the Copy trait. Once again, if it does, Rust will create a full copy. But if the type does not implement the Copy trait, ownership will move out of the enum variant to, let's say, the variable that it's being assigned to. And the compiler has to be careful about honoring the rules of ownership. And that's going to lead to some interesting compilation results.

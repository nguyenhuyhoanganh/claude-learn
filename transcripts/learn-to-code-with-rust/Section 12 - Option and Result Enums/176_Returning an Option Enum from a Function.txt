# Returning an Option Enum from a Function

In the previous lesson, we defined a function that accepted an 'Option' as a parameter. Let's now flip the situation around and declare a function that returns an 'Option'. This is similar to how the 'get' method on an array works. The 'Option' is a distinct type, which means we can specify it as a return value of a function, but we are required to provide the concrete type for the 'T' generic and live up to that return value in the body of our function. So let's imagine that we are writing an inventory system for our warehouse. So we're going to define a function called 'is_item_in_stock'. And this is going to check whether an item is in our inventory. To keep things simple, let's say that there are three possibilities. The first possibility is that the item that we're searching for exists in our catalog and is in stock. We're going to return a 'Some' variant with a true in that situation to indicate that we have found some item and it is available. The second possibility is that the item exists in our catalog but is not in stock. For that situation, we'll return a 'Some' variant holding a false indicating that we understand what the item is. It's just not available in our warehouse. And the third possibility is that the item we're searching for completely doesn't exist within our catalog. And then we'll return a 'None' variant in that situation. So let's declare two parameters here. We're going to call the first one 'item_is_in_system'. And this will be a Boolean. And the second one will be 'item_is_in_stock'. That will also be a Boolean. And then I'm going to specify my return value. And if I write 'Option', that by itself is not going to be enough because I need to provide a concrete type for the generic. So here I'll provide my angle brackets and specify that I must return a 'bool' in the 'Some' variant. So once again, if we return a boolean from the body of this function, that is a type mismatch. And if we return an 'Option' but not containing a boolean, that is also a mismatch, we need to make sure we return either the 'Some' variant storing a boolean or a 'None' variant, because those are the only two that qualify as being members of the 'Option' enum. So let's write our logic here. Let's not make it too complex. I'll say if our item is in the system and our item is in stock, we've located it in here. I'll return my 'Some' variant storing a value of true as its single piece of associated data. That lives up to this standard right here. Then I'll check If our item is in the system, and I could check if it's not in stock. But since that is already going to be captured here, the kind of positive case that it is in our system and in stock, if it is in our system but not in stock, we're automatically going to get a true here anyway. So that captures that scenario and we do not need to add the additional item is not in stock logic. So here if it exists in our system but it has not been found to be in stock, we understand what it is. It's just not available. So we're going to return the 'Some' variant but storing the value false. And finally in our else clause, if we're not able to locate it at all, we can just return the 'None' variant, indicating that it has not been found for all three of these lines. Make sure you do not include your semicolon and that will return one of these three options, pardon the pun, and that will satisfy our return value. So now in the body of main we can practice invoking this function a couple of times. I'll declare a variable called 'availability' and invoke it with a couple different values. Let's try true and true. And then I'm going to take the return value, which will be an 'Option' storing a bool in the 'Some' variant. And I can print out that variable in Debug format. So this is an example of true and true. So we should hit this arm right here. We're going to get back our 'Some' variant storing the value true. And if I switch this up to something like true and false then we should get the other one, 'Some(false)' etc.. So again a very popular combination with the 'Option' enum is the match statement because it forces us to handle every possible variant. So instead of printing this out in this Debug format, we can of course combine the match keyword with our very own 'Option' that we return. So for example here I can match on 'availability'. I have to provide a match arm for both my 'Some' variant and my 'None' variant. Let's first take care of our 'Some' variant. That is going to store some associated boolean, either true or false. I can extract it to a variable like 'value' which I have permission to use in my match arm. So I can say something like "Item is available" and then interpolate the value of 'value'. Once again, that's going to be the extracted data, the extracted associated data that I pull out from the 'Some' variant, either a true or a false. And now I have it available to use in my match arm. For my other arm, which is going to be my 'None' variant, there is no associated data so I can output some basic string like "Your item doesn't exist in our system". So once again, we're now getting an 'Option' of type bool or storing a type bool in the 'Some' variant. We're hitting this arm right here. So we should match right here in our match statement. And output "Item is available: false". And there we have it. And if we try another 'Option', let's say we provide false and false right here. That should make us hit the else clause in our function. That means the 'is_item_in_stock' function will return the 'None' variant still satisfying the promised return type. That's sort of a little bit of a cheat code if you think about it, because we can have a single specified return value, an 'Option' storing a boolean, but have different representations of ideas stored in that singular return value. We can return a 'None' variant and still satisfy the compiler right here. And that is the beauty of this design is we have this one type, but it actually can represent two different things which can elegantly model this real world situation where a function may need to return something or nothing, right in a graceful way that avoids errors and captures either one of those two situations. And then we handle it right here. So now we're going to return 'None' satisfying this return value criteria. We're going to match on it right here. And we're going to get "Your item doesn't exist in our system". As a quick reminder from the enums section, we can also declare a separate match arm for different pieces of associated data. For example, we can declare a match arm for the 'Some' variant specifically with an associated data of true, and then a separate match arm for the 'Some' variant with a associated data of false. So we can react differently not just based on the variant, but on the associated data that a variant holds. So for example, here, instead of providing the name 'value' to represent whatever boolean is stored within that 'Some' variant, I can instead declare the specific value. So for example, if I say true right here, I'm writing a match arm in the case that we have the 'Some' variant returned and it is specifically holding the value true. So here, for example, I can say something like "Yes, the item is available", but the compiler will not be happy yet because now we have not covered every possible case. We have not covered the scenario where we have a 'Some' variant storing a false piece of associated data. So here the compiler will tell us you're missing that match arm: 'Some(false)' not covered. So once again same syntax. We'll provide our variant of 'Some'. And the other piece of associated data we need to cover is a false. Once again it depends on the data type you have. With a boolean, it's pretty nice because we have two possible values. But if this were an integer for example, we'd have to cover every possible integer in the world, and that's where the complexity starts to creep in. So here I can output a println! and say something like "No, the item is not in stock". So we either have it available, we don't have it in stock or we don't recognize it at all. We're modeling that real world example right now. We're hitting this else clause right here. And that is going to match on the 'None' variant when we use the match keyword in our main function. So we're going to get "Your item does not exist". And if we return back to our first scenario. Let's say a true and a true here. Now we're going to hit this arm or this conditional in the function body. We're going to implicitly return the 'Some' variant storing a data point of true satisfying the return value. We're going to match on that right here and thus execute the associated arm and output. "Yes, the item is available". So that is an example of returning an 'Option' enum from a function.

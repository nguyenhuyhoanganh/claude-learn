# Real Example of Option Enum (The get Method on an Array)

So next I want to show you an example of the Option enum in the real world. So in this lesson we'll invoke the 'get method on an array. And this is an example of a method that returns an Option. And we'll see why in just a second. So let's begin by declaring an array. I'm going to call my variable 'musical_instruments' And my array will consist of three Strings. So here I can do 'String::from' and let's do "Guitar". After that we'll do "Drums". And finally we will do "Bass". So of course one option is to provide the index position within square brackets. But that always has the potential for failure because there is the possibility that we access an index position that does not exist. Now sometimes the Rust compiler can catch you, for example, if we hardcode the index position directly in the code. But if it's coming from somewhere unpredictable, like, say, the user input, the compiler cannot predict all possible values in advance, and thus there is the potential for a runtime error. So a safer option to extract an element from an array with an index position is a method called 'get', and the 'get' method is going to return an Option. And the reason that's the case is because it needs to account for two scenarios. One is if the index position exists, then we can target the element at that position. But then if the index position does not exist, we also need to safely account for the other scenario where there is no value at that given index to give back as the return value from the method. So the Option enum is a perfect solution because it captures both of those scenarios. So let me show you right here. I'll declare a 'bass' variable and I'm going to take 'musical_instruments' and call the 'get' method. This method accepts the index position of the element I want to target. Index positions start from 0. So the "Bass" string which is third in line is actually index 2. So we're going to invoke that method. And notice that we're going to get an Option. Notice as well that the type for generic type 'T' is a String reference ( &String ). So the 'get' method is not going to extract the element itself because that would move ownership of that element outside of the array. So instead it just gives you a reference. But the point still holds. This will be an Option that's going to be one of two variants either 'Some', in which case the associated data will be the string reference for the String at that given index, or it's going to be None if the index position does not exist. But the reason this approach is safer is because you're never going to run into an error. So once again, we can manually annotate this type if we want. So we're going to provide an Option here and then provide our specific type for type 'T' as '&String'. So a String reference. I want to state once again for clarity that the type returned by the 'get' method is not a String, and it is not a String reference, it is an Option enum. And one possibility is that that is the 'Some' variant of the Option enum. And if that is the case, then that 'Some' variant will be storing associated data of the ref string ( &String ) or String reference type. So the core type being returned here is an Option, right. It's not actually a String or a String reference ( &String ). So we can use the Debug formatter on this Option type. So here I can provide my question mark syntax ( ? ) and then provide 'bass' right here. And we're going to see that we have the 'Some' variant which means a success value. Right. We were successfully able to find this index. But we're going to have our result wrapped in the Option enum. And then the specific value that is being stored is 'bass'. Technically speaking, it's not actually the String itself, it is a reference to the String ( &String ). This is just the text representation of that when we print it out using the Debug format. So now let's take a look at the opposite situation which is if the index position is invalid. So here I'll declare a variable called 'invalid_instrument'. And once again take my 'get' method. And let's say we try to access the element at index 100. Now if we try to do this with square bracket syntax and say the index of 100 came from the user. This would cause what's called a panic at runtime. The Rust program would quit because it's in an error at runtime. The Rust program is trying to get an element at an index that does not exist, and thus we have problems. But again, the beauty of the 'get' method. And at a higher level, the beauty of the Option enum is that it can gracefully handle that scenario. So notice that the type here is inferred to be the exact same as it was here. It is an Option enum where the concrete type for 'T' is a String reference ( &String ). However, as you might guess, the actual specific variant that we're going to have in this scenario is going to be the 'None' variant, because there is no value to return. So here we're going to get 'None', right? So that's the kind of beautiful part here is there is no capacity for error. and yet we're still returning a consistent type from the 'get' method. Imagine that you were the Rust developer who was in charge of building the 'get' method. Think about how you would annotate the return type. The return type has to be a consistent type. So what do you put? Well, if you put let's say a ref String ( &String ) that's fine. But that's not always going to be the case. That's only going to be the case if the provided index position exists. Then you can find the index string and return a reference to it. But what if you get an index position that does not exist? Well then there's not really a String reference to return, right? So annotating the type if you were the developer to be a 'ref String' ( &String ) is not going to be stable. It's not going to work 100% of the time. But by annotating the type of the 'get' method to always be an Option enum, we have this versatile enum type that has two variants that support both of those possibilities. Either a present value in this case a 'ref String', a present retrievable value, or the other variant is an absent value representing the non-state, the absence of something, the missingness of something. And the program compiles, and it never runs into a runtime error because we're able to accommodate both of those scenarios. Right. So this code will continue to compile even if we provide an invalid index, which makes it more versatile and more durable for providing a nonexistent index compared to the square brackets. So it's in many of these types of situations where there might be a valid value or there might not be anything, that's when the Rust team is going to give you back an Option. All right. So hopefully the benefit of this enum makes sense. We're going to see more examples of the kind of problems that it solves as we progress throughout these lessons.

They assumed that we had a 'Some' variant within our 'Option' enum, and were thus able to extract the corresponding associated data, but they led to a runtime error if the variant was 'None'. So what is the more elegant, more conventional way to solve this kind of problem from the previous lesson? How do we handle both scenarios either having a value or not having a value? So you may recall from the enums section of the course that an enum supports the 'match' keyword. The beautiful part about the 'match' keyword is that that construct will force us to declare a match arm or pattern for each possible enum variant. Thus, a match statement for an Option enum will require us to declare logic for the 'Some' variant and the 'None' variant. The code will not compile if we do not cover both cases. So while 'unwrap' and 'expect' will fail if there is no value, the 'match' keyword will handle both the presence of a value and the absence of a value. Pretty gracefully.

# Real Example of Result Enum (The parse Method on a string)

So let's take a look at a sample method that returns a Result enum. I'll begin by declaring a 'text' variable, and I will set it to a string that consists of the digits "50". So this is a string slice. It is not an integer, but say that we want to attempt to extract the integer equivalent of this string. So we want to convert this into an equivalent, say, i32. So there is a method available on a string called 'parse'. The 'parse' method on a string attempts to extract a different data type from the string. So we're trying to parse out the integer equivalent. So I'm going to assign this to a variable called 'text_as_number'. Now, this operation will either succeed or fail with an error. It is possible that we successfully extract an integer if the string has numeric content within it, but it is also possible that we will fail if there is no numeric data to pull out. Rust will thus return a Result enum. If the parsing is successful, it will be the Result's 'Ok' variant and the variant will store the extracted integer, and if the parsing fails, the Result will hold the 'Err' variant instead with its corresponding error value. Now, when we invoke the 'parse' method, we need to use the turbofish operator to specify the type of the success value. So there's many different types of integers that we could extract from something like "50" We could do an i32 or an i16, etc. Rust doesn't know what we want by default, so what we can do here is use our turbofish operator, which is two colons followed by angle brackets ( ::<> ), And this is providing a concrete type for a generic behind the scenes. And we can say that we want an i32. So now you can see Rust can infer that we're going to be getting a Result type, which is the enum. And if we have a successful extraction, the 'Ok' variant will store an i32. And the error or 'Err' variant will store a 'ParseIntError' which is a different type that we haven't seen so far. So now I can output the content and we'll have to use Debug formatting. And we're going to output 'text_as_number'. This is our Result enum. This is our outer wrapper. And we can see with the text of 50, we are successfully able to extract the value 50 which is the associated data that is stored in the 'Ok' variant. This 'Ok' variant is an Option within the Result enum. So this is still a result. It is the 'Ok' variant within the Result. Let's take a look at a very similar example. I'm just going to copy this entire chunk of code below, and then I'm going to provide a string that is completely lacking in any kind of numeric content. So maybe something like "Alabama". So now once again notice our code will still compile. We're not going to have any runtime panics or errors, but now the 'parse' method will be unable to successfully parse out an integer from this text. But the return type of the 'parse' method will be a consistent Result enum. But this time around we're going to get the other variant, which is the 'Err' variant right here, and it is going to store a totally different type from the i32 that is stored in the 'Ok' variant. This is the 'ParseIntError', which is its own separate type. I believe it's a struct behind the scenes, but the key takeaway is this type and this type are different, but they are both captured within the larger enum called Result, and the 'parse' method can consistently provide a return value of the same type. It will always be a Result, but the beautiful part about that type is that it encapsulates the possibility of success in this variant, and the possibility of failure with this variant. All right. So that's really all there is to cover in this lesson. This hopefully gives you a real world example of where the Rust development team puts in actual Results return values throughout many of their methods, wherever there is the possibility of either success or failure, because an operation may or may not succeed, the method will give you back typically a consistent return value of a Result. It's just that that Result may encapsulate or hold either the success value in the 'Ok' variant or the failure value in the 'Err' variant.

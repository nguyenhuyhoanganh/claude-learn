# The Result Enum

In this lesson, we'll learn about another popular enum in Rust and it is Result. The Result enum models the outcome of an evaluation that can produce either a success or an error. So the Option enum is for representing presence versus absence, while Result is for modeling success versus error. The Result enum has two variants which you can see on the right and they are 'Ok' and 'Err' - E R R but that is short for "error". The 'Ok' variant indicates a success and the 'Err' variant indicates an error or a failure. There are also two generic types, 'T' and 'E', which are short for type and error. The 'T' generic represents the type of the 'Ok' variant's associated data, and the 'E' generic represents the type of the 'Err' variant's associated data. So if the Result value is the 'Ok' variant, it will contain the success data. So to speak, which will be of type 'T'. And if instead the Result enum value is the 'Err' variant representing a failure, it will contain an error of type 'E'.  And 'T' and 'E' can be different types, or they can also technically be the same type as well. So other programming languages have this idea of exceptions. And those are basically types that model the idea of errors or something that goes wrong. Rust doesn't have exceptions, but the Result enum effectively models the same idea. So if you are working on anything that could potentially go wrong, the common rust design pattern is to return back a Result which could represent either scenario, and then the compiler will force us to react to both situations, the happy path as well as the unhappy path. The error path. All right, So the compiler as always holds us responsible. So let's now transition to VSCode and see the Result enum in action. Because a Result enum will always be one of the two variants, the compiler will not be able to infer the type of one of the two generics.

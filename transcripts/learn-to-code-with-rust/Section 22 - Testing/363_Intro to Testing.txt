# Intro to Testing

Welcome to the next section of the course, which is focused on testing. In everyday language, the word "test" means to check the quality, performance or reliability of something. So how do we test our Rust programs? How do we validate that they work as expected? So far, we just compile and execute them manually and observe that the code accomplishes our intended result. And there's nothing wrong with that. You should absolutely compile and run your program to validate that your code does what it is supposed to do. The problem with this approach is that it takes time and knowledge, especially as your code base grows in size and complexity. You can't test everything manually after a certain point, just because of all of the complexity of the interweaving pieces. But you want to be careful to ensure that any new code you add doesn't break existing functionality. The good news is we are working with a programming language, and that offers us a unique advantage to testing that other domains do not have. We have the power of code. So when we talk about testing in the context of Rust or software development, we're usually referring to writing code that will validate that our program code works as expected. So we're going to write additional code, supplementary code, testing code, whose whole purpose will be to run some other Rust code and validate that that original code produces an expected output. It's up to us, the developers, to define what needs to be tested in our program, and then how to test it. So for this section, I've created a testing crate and you should go ahead and open it up in VSCode. And I created this Cargo project using the command 'cargo new' as always. But I also added the '--lib' flag for library. So this creates our a Rust crate as a library crate. Remember, a library crate has code that is intended to be used by other Rust crates. It's a community crate that other binary crates can pull in and utilize. It thus does not need to have a 'main.rs' file or a 'main' function. Rather, it's going to have a 'lib.rs' file, which is going to be the crate root of our library crate, and that's where we're going to be writing our code within this section.

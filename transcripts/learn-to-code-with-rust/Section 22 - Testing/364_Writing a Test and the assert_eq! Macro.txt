# Writing a Test and the assert_eq! Macro

A test in rust consists of assertions. An assertion is a verification that a statement is valid. The word assert means to state a fact, to declare that something is true, so the test will typically execute some code and assert or validate that the code produces an expected output. The value of tests is finding regressions in your code. A regression is essentially a bug introduced into working software. To regress means to return to a former or less developed state, and a regression is just the noun form of that. So tests will help us to identify situations where you can make some changes to your code and accidentally break existing functionality that is meant to work. So ideally you should be running your tests after every code change to verify that the existing code is continuing to fulfill its original requirements. In other words, that you haven't broken anything. Now, in technical terms, a test is going to be a plain rust function that's going to be annotated with a special attribute called test. Remember, an attribute is just metadata that we add on the line above some construct that will influence how the compiler parses the code. So two examples of attributes that we've seen so far are the derive attribute for implementing a trait, as well as the allow attribute for silencing a warning about behavior that the compiler would otherwise be unhappy about. So the syntax is consistent. It's always going to be a hashtag followed by a square bracket combo. Right? And in there you write your attribute. For us our attribute is called test. So we are going to add this line above the declaration of a function. And then that function will be marked or identified as a test function. Otherwise it's just a plain rust function. Now, this execution is actually a good design principle of the test suite because it ensures that your tests are deterministic.

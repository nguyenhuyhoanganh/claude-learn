# Ignoring Tests

We can add another attribute above a test called ignore, which will skip or bypass that test when cargo test runs. For example, here is my equality test and what I'm going to do. Still above the function is provide another attribute using the exact same syntax a hashtag followed by a pair of square brackets. But this one is ignore. We still need the test one above to mark it as a test function. But now we are saying please ignore this test. So here is the result of my previous execution of cargo test. You can see we had five passing tests. Now we're only going to run a total of four tests because one of them is being ignored. So now you can see the output says four passed. We have effectively ignored or skipped this test. So this is a helpful tool. Whenever for example, you want to skip certain tests. Maybe they are failing because the feature has not yet been built. Or maybe you simply want to reduce the total number of tests that are running to speed up the test suite temporarily so you can focus on other tests. Maybe this is a example of a passing test, and you know it passes and you don't want to keep rerunning it to save computation time on subsequent test runs. There are a couple scenarios where it can be helpful to utilize this attribute, but ultimately I would recommend not committing this to your final source code because why would you add an ignore test, right? It's as good as never having been written in the first place. So this is really just a tool to help you in the development process as a temporary stopgap to kind of disable a test, if you will. Almost the equivalent of commenting out the test entirely, but using a special compiler directive. The ignore attribute. So realizing that I'm going to remove this ignore attribute to get us back to a fully running test suite that runs all of our tests. But it is a good tool to have in your toolbox.

# Test Options

In this lesson, I want to show you some more testing options that we have available. Now, the way that we can see all of the available command line arguments that we can pass is by adding this setting --help. What's really interesting is that we can pass this option to either cargo test to get the settings for the core cargo test command line command, or we can actually pass --help to the compiled executable that cargo test produces. And the syntax is going to be slightly different for both. So let's begin with the first example which is cargo test. And here I'm going to pass --help. So this is asking for the settings or help for the core cargo test command. Not to the compiled executable that will run the tests. These are top level settings and options that we can pass to cargo test. And as I scroll up, you can see there's quite a lot of them. So, whenever you have a moment, you can feel free to dive in here and see all of the different ways you can customize how this command is going to work. One interesting one I want to show you now is this one of --lib, which is short for library. And that allows you to just execute your library tests. So effectively this is going to ignore the integration tests at the top of your project. The ones inside the tests folder. This is basically going to run your unit tests. So here I can show you that if I execute cargo test and pass in the setting of --lib, that option is going to run the unit tests within our src directory, but skip out the integration tests. Now if you want to run only the integration tests, the complement... It's a little bit of an interesting syntax, but what you're going to write is cargo test. Then, you're going to pass a option here that's actually also called test. So --test. And then this is really interesting. You're going to provide a string in single quotes. And it must be single quotes. And inside that string you're going to place a single asterisk. So it's going to be the single quote, the asterisk, and then another single quote. And that is going to run the integration tests within the top level 'tests' directory. So if I scroll down here you can see we only have one. And it's going to execute that. If you only want to run the documentation tests, that's going to be cargo test. And then the setting is --doc. That is going to limit the tests to just the documentation test. Now all of these are settings that we pass to the top level cargo test command. Remember cargo test is going to effectively create an executable, a Rust program that has its own ability to accept command line arguments. So as you may recall, in order to pass command line arguments into that program, we need to provide the initial command, then provide the two dashes just to distinguish the arguments we're passing, not to cargo test, but to the executable that it produces, and it's to that executable that we want to pass --help. So this command and simply cargo test help by itself are accomplishing two different things. And this is going to give us a whole set of different options that we can pass to the actual executable. So as I scroll up here, you're going to see a whole different set of various settings that you can configure. Just to show you how one of these will work, let's take a look at format here. This is going to configure the formatting of the test output. And the default one is "pretty". So let me show you how this setting works. I'm going to execute cargo test. And remember all of the settings that we just saw are for the executable. So just like the previous command, if we want to pass the command line setting into the executable rather than into cargo test, we once again have to provide a -- first. And then after space we provide our command line arguments. So that setting was called --format. And then after a space we can configure which format we would like to print the test in. So the default one is called "pretty". And that is going to give you a nice verbose output. It's going to have for example, all of the names of the modules and the the test names within them. But if you want something that's a little bit more lighter and takes up less space, a complementary way that you can run your tests is once again providing the --format command line setting to the executable and changing it from pretty to terse. Where terse is going to do is it's going to place a green dot. You can see here the green dots, the green dots for every passing test. And I believe it's going to be a red F for a failure. So this just creates less clutter in the output. The word terse literally means limiting the number of words of something. And that's exactly what it does. But the key takeaway here is this is a setting that is specifically applying to the command line executable that cargo test is generating, and there are settings for that and settings for the top level cargo test command itself. Hopefully that makes sense. And with that I will see you in the next lesson.

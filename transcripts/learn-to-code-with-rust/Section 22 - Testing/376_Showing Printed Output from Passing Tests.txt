# Showing Printed Output from Passing Tests

If within a test we output text to the screen using the print line macro or a comparable macro, the test runner will not print that content unless the test is a failure. If the test is a success, the printed content will completely be ignored or at a minimum, not actually output for us to see in the test output. So let me show you a quick example. I'm going to declare two test functions, and we're going to delete them by the end of the lesson. This first one I'll call Print Success. And in here I'm going to use my print line macro. And I'll output a string of success inside the function. And then I'll use my assert macro and pass in a boolean of true just for an easy passing test. Then I'm going to copy and paste this test below, and I'll call my next test print failure, and I'll update this print line to be something like failure inside the function. And I will cause a test failure by asserting on a boolean of false. So this test will pass, which means this content will not be seen in the output and this test will fail, which means this content will be seen in the output. So here I'm going to run cargo test. Notice we're going to get our failures. And here is the actual printed content from our print line underneath the failure section for the passing test of print success right here. We got the okay here. But notice we did not get the text success inside the function printed anywhere here. Now, if you want to override this and ask the test runner to always show you any output printed to the screen, you can provide an additional testing option. It's not going to go directly to cargo test. It's going to go to the compiled executable that it produces. So as a reminder after cargo test we're going to add two dashes in a row. And then after that a space. And then we provide the actual command line argument to ensure it flows into the executable that cargo test generates rather than a command line argument into cargo test itself. And this command line argument is going to be two dashes, then sho, then dash output. Show the output. Show any printed content in other words. So when I run this now notice we're still going to get our failures and they're going to have the content that we printed right here. But for our successes, there's going to be a separate section right here called successes. And by the test organized by the name of the test, in this case the print success test, we're going to see anything that we output to the screen right here. So that is the show output option in order to show all of your printed output. Sometimes this can be helpful because you just want to validate, for example, that a certain part of the test ran as expected, or that a piece of data looks as it should. But unfortunately, without this command line argument, you're not going to see your output if the test is passing. So with that, I'm going to remove these two test functions. They were just for the sake of example and get us back to a passing test suite. And with that I will see you in the next lesson.

# The assert! Macro

In this lesson, I want to introduce another assertion macro called assert! The assert! macro validates that some condition or value is true, the Boolean value true. The assert! macro expects one argument, which must be a Boolean and assert! will pass the test if the Boolean that is passed in is true. If it is false, then the assertion will fail. So let's define a new test function. As always, I will begin with my #[test] annotation and I'm going to call this one"museum_can_have_impressive_ art_collection". So as a reminder we have a method on our Museum struct called 'has_impressive_collection' that gives us back a true if the Museum has more than two paintings. And the way that the Museum acquires paintings is by buying them, which is represented by this method. So the beautiful part about this test is by validating the logic here, we are also going to have an opportunity to invoke this method and ensure that that functionality is working as expected as well. So what I'm going to do is instantiate a new Museum struct, call 'buy_painting' three times to have a total of three paintings, and then ensure that 'has_impressive_collection' returns a Boolean of true. In fact, I can take the return value of this method and use it as my input into the new assert! macro. So here in my test, let's begin by once again creating a mutable Museum right here. We'll utilize the 'new' constructor function. Then I'm going to call 'buy_painting'. And I'm going to pass in a string for the painting name. Let's do Mona Lisa. And then I'm going to copy and paste this line two more times down. Let's buy another painting of The Starry Night as well as Girl with a Pearl Earring. So now my vector should be storing these three strings. And so I can take my museum and call the 'has_impressive_collection' method on it. So technically speaking, what you could do is this -- you can use the assert_eq! macro that we've seen before. And you can pass in the return value of the method and compare it to true. But that is effectively what the assert! macro is doing anyway. So assert! is considered the more idiomatic way to accomplish the same result. So I'm going to call assert! instead. It only expects one argument, which must be something that produces a Boolean. Can be a Boolean. Can be an expression. Can be a struct field, can be a method return value, whatever you want. I'm just going to pass in this method invocation right here. And once again it's going to pass if we get back a true. So I'm going to run my test suite and everything is passing as expected. But once again the tests are keeping us honest. So for example, if tomorrow we introduce a bug... Let's say we reverse this logic and use the incorrect symbol. Say we use the less than symbol instead of the greater than symbol. Well, then our test should fail and allow us to identify that something has gone wrong. Now, with the assert! macro, there are no longer two arguments like there are with assert_eq! so there are no left and right descriptions. We're simply going to have the test listed under the 'failures' section. And it's basically going to tell us that the assertion failed specifically with this invocation that was passed into our assert! macro. Once again with assert!, we just know that we are getting back the incorrect Boolean. So the failure here tells us that assert! received a false Boolean value instead of a true that allows us to look into the test, and then ultimately at the implementation to figure out, "Ah, this is where I made the mistake, I can fix it. And now we're back to having a passing test suite. So again, the assert! macro expects a single argument. Must be a Boolean and it will pass the test if that Boolean is true.

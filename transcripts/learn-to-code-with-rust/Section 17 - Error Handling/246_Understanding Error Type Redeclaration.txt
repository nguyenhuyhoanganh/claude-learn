A type alias is a nickname for an existing type. An alias is an alternate name. So they're not creating a new type. They're sort of redeclaring an existing type, but with a different name. Now here on the right hand side, you'll notice this result:: Result. What this is right here is actually the main Result type that we've been talking about throughout the course. They're saying we're going to declare a Result type within the 'io' submodule, within input/output, it's going to accept a generic type T and what it represents, or what it is an alias or nickname for, is the existing Result type that we are familiar with, and they're going to pass down whatever is the T declared here to the T in the regular Result. In other words, this 'T' will be the type of the success variant. But rather than specifying any kind of generic for the 'E' that this Result needs, they are hard coding this Error struct down below. In other words, they're saying we're going to have a very specific exact version of the regular Result enum that we know and love. The 'T' is subject to variance, but the 'E' is always going to be the 'io::Error' type right here. It's always going to be this struct, because all Results generated from this input/output module, their Error type is going to be a consistent error type: this struct right here. So the advantage of this approach is now they don't have to explicitly specify the type of 'E' every single time they want to return something that looks like this, a regular Result with a generic T and a concrete value for 'E' being this 'Error' struct right here.

# Using ? with Option

So at this point, we've seen how to apply the question mark operator to a Result enum. You may also recall the complementary enum which is Option. Option holds two variants, Some and None. The Some variant stores one associated piece of data and the None variant stores nothing. It basically indicates the absence of a value. So we can apply the question mark symbol to an Option as well. If the Option holds the None variant, then the function will terminate early and return the None variant at that point. In comparison, if the Option holds the Some variant, then the associated data on the Some variant will be pulled out and it will become the value of the expression and the function will continue executing. So it's very similar in principle to Result in the sense that if you have what you need, whether it be the Some variant or the Ok variant, then the function continues. And if you have either an error or are missing a value, the function terminates early. So let me give you a super simple example of this. Let's begin by declaring a mutable vector. I'm going to call it 'animals' and our vector will store three string slices. Let's populate it with "Giraffe", "Monkey" and "Zebra" and say I want to define another function. And what I want this function to do is to calculate the length of the last element. So what I want it to do is to remove the very last element in the vector if there is one, and then give me the length of that string. So I'll define a single parameter for our vector. I'll call it 'input', and this will be a mutable reference to avoid taking ownership. So I can define my type as being a mutable reference to a vector specifically holding string slices, which I can do with the ref str ( &str ). All right. And what I want this function to return is going to be an Option enum. And this Option enum requires one concrete type for its generic. And this will be the type of the data on the Some variant. So if I am able to pull out the length of a given string, that is going to be a number. And more specifically, when Rust takes the length of a type, it returns the usize type. As a reminder, that is an unsigned integer, meaning a positive integer. but the concrete data type that this is varies across different operating systems. Basically, this is going to be either a u32 or a u64. But we don't have to worry about it. It should just work out of the box. All right. So within the body of this function, the first thing I need to do is to take my vector and get the last element. So that is going to be achieved by calling the 'pop' method. Now the 'pop' method returns an Option. The reason it returns an Option is because there may be some value at the end of the vector to pull out, or there may be no value if we have an empty vector. So in order to have a uniform return value for the 'pop' method, the Rust team chose the Option. Right? So if I assign this to a variable like 'last_element', notice that the compiler will infer the last element to be an Option that may contain a Some variant storing a string slice. So what I'm going to do is the exact same thing that we did in the previous lesson. I'm going to add a question mark here. What this is saying is: If there is a None variant, in other words, if the vector is empty, return early. And if you have the Some variant indicating that we were successfully able to pop off some element, then last element will be the associated data from the Some variant. So you can see the inference change in real time from being an Option to being the string slice representing the last element that was pulled off, because if it had failed, in other words, if 'pop' had returned the None variant, then the function would return early and return that None variant anyway at this point. So at this point, Rust can guarantee that we have a string slice. Then what I need to do is to take that string slice and call the 'len' method on it. But this is going to give me the actual number, the actual usize of the length. Right? I need to make sure that I package it up in the expected return value, which must be a variant of the Option enum. So if I am successfully able to get the length because I was successfully able to extract an element from the end, I want to package that up in my Some variant. This is the exact same thing as 'Option::Some'. I'm just writing it the more abbreviated way. And there we have it. So now we are either returning the Some variant right here, or the None variant indirectly with the question mark. It's a little bit implicit, a little bit magical because we don't see None. But that is what question mark will return in the case of 'pop' returning the None variant. So let's take a look at this in action. Right here, I'm going to provide my curly brace syntax. And I'm going to provide my Debug format. And what I want to interpolate is the return value of the 'length_of_last_element' function, passing in my 'animals' vector, a mutable reference to it. So each time I call this 'length_of_last_element' function, I'm going to remove one more element from the end until we run out. So for example, the first element is "Zebra". We're going to pull that out and get the length of 5 captured in the Some variant of the Option enum. Exactly what we expect. And if I call this again, we now have a vector of two elements. We're going to pull out "Monkey" and the length of "Monkey" is 6. One more time. We have one element remaining in the vector. We're going to pull it out. We're going to pop. This is not going to fail. So all three of these calls, the 'pop' method is going to return the Some variant. We're going to pull out the associated data of that Some variant into 'last_element' with the question mark. Then take the length of that string slice and package it up into Some variant. Now on the fourth invocation, 'animals' is empty. So now when we call the 'pop' method, we get back an Option with the None variant. Then we apply the question mark to that Option. And because there is a None variant, we terminate early. Rust automatically terminates the function early, sending up the None with no associated data. And there it is. And of course if we want to keep calling it again we're going to get the same consistent Result because there is no more element to pop and therefore there is no more element to take the length of. All right. Same basic principles as with the Result enum. If we are able to progress, we do. If we are not able to continue, we return early and propagate some data back up, either the None variant in this case or the Err variant in the case of a Result enum. All right. That's all there is to cover in this lesson. So I will see you in the next one.

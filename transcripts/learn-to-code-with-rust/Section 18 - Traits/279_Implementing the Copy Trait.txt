# Implementing the Copy Trait

In this lesson, we'll learn about the Copy trait. The Copy trait is a subtrait of the Clone supertrait that we covered in the previous lesson. What's interesting is if a type chooses to implement the Copy trait, we do not need to define any additional methods. We just need to define the 'impl' block for the implementation of that Copy trait. Now keep in mind because Copy is a subtrait, if we choose to implement the Copy trait, we are obligated to implement the Clone supertrait and its 'clone' method. So if a type chooses to implement Copy, then it must implement the Clone trait, which is the parent trait. The same logic does not apply in reverse. If a type chooses to implement just the Clone parent trait, it does not have to choose to implement the Copy subtrait. All right. Now what does the Copy trait actually do? If a type implements the Copy trait, then it will be copied instead of moved in operations like assignment with the equal sign. So the way I like to think about it is consider the existing types in Rust that implement Copy like integers, floats, and booleans. Whenever we have a variable with one of those values and we assign it to another variable, we create a full copy instead of a move. We do not have to worry about the principles of ownership because ownership does not transfer. There are then multiple owners for duplicate, independent pieces of data, and Rust knows from the Clone parent trait how to create that duplicate, and it just does so automatically with the equal sign syntax if we also choose to implement Copy. Now, what's also interesting is if you try to implement the Copy trait on any type, say a struct, that contains non copied data, such as, say, fields on a struct that implement or utilize strings. Any one of those nested values not implementing the Copy trait will make it impossible to implement the Copy trait on the greater struct, on the larger data type that is holding that nested data. So if we try to implement Copy on our struct from the previous lesson, the Appointment, it would actually not work because our fields there are storing Strings which themselves do not implement the Copy trait.

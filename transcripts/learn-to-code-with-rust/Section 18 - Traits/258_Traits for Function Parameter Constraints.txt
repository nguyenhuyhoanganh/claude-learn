# Traits for Function Parameter Constraints

In this lesson, I want to show you how we can use a trait to add constraints to a function's parameter. We can make a function accept any type that implements a given trait. So without declaring the specific type, but only declaring the trait that that type must implement, we can make our functions very versatile because they can accept a wide variety of inputs. For example, let's declare a function above 'main' and I'm going to call it 'book_for_one_night'. And I want this function to accept a parameter called 'entity'. And of course I could declare 'entity' to be a concrete Hotel or an Airbnb. That is technically valid, but it is not versatile because I'm going to bind my 'entity' parameter to be only one possible type. It's not flexible. Instead, what I can do is tell Rust that 'entity' will be any type that implements the Accommodation trait. So for that here instead of a concrete type, instead I'm going to do the 'impl' keyword and then the trait after a space which will be Accommodation. So what I'm saying here is 'entity' can be any type as long as it implements the Accommodation trait. Rust will not care about the exact type or types passed in, but it will validate that those types implement the Accommodation trait. And because Rust can guarantee that they implement the Accommodation trait, Rust will also know that we can invoke either 'get_description' or 'book' on 'entity' regardless of what entity happens to be.

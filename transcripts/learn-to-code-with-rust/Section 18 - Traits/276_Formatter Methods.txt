# Formatter Methods

In this lesson, I want to show you an alternate way that we can create our desired string for either the Display or Debug trait's 'fmt' method. This is another way that we can return the expected type of a Result, but utilizing a different approach from the write! macro. Instead, we're going to utilize the 'formatter' struct that we receive a mutable reference to as the parameter here. So what I'm going to do for my Debug implementation for my AppleType is just remove this former implementation completely, and I'll show you another way to accomplish the same result. So if I refer to my 'formatter' parameter, you'll see it has a whole bunch of methods. And many of these methods are here to assist you with generating the final string that you want. So there is a family of methods that all begin with the word 'debug', and they're all specialized for a specific type in Rust. In this case, Apple is a struct, and there is a convenient method here called 'debug_struct'. And what this is going to return to us is actually a struct called DebugStruct that is also going to have its own collection of methods to assist with formatting various struct contents and within the final string that we're going to create. So all of these methods are specialized. It basically allows us to generate what we want, but through a use of methods versus just a manual string that we inject dynamic content to. I'm not saying either approach is better or worse, it's just another way to think about it. So what the Debug struct method expects is a string slice that's just going to represent the beginning of the content of the string that we're eventually going to see if we ask for the Debug representation of an Apple. So in here I'm going to do something different. I'll do two asterisks. Then the word Apple after a space, another space, and two more asterisks. It's entirely arbitrary and up to us. Now on this Debug struct return value, there is a helpful method called 'field'. As you might guess, this will assist us in adding one of the existing struct's fields to the final string that this operation is going to return. So 'field' is going to accept two arguments. The first is a string slice representing the name of the field as we would like to output it. So here for example I can do 'Kind'. And then the second argument is a reference to the actual data that will be associated with this "Kind" string in front. So for example here I can reference 'self.kind' and I need a reference here. That is what the 'field' method expects. So I'm going to change this to be a reference to 'self.kind', which is a reference to this enum. Now this is actually utilizing something called the builder design pattern, which we talked about a little bit earlier in the course. What that means is this 'field' method is actually returning the DebugStruct struct that we see right here that was the return value of the 'debug_struct' method. And the reason it does that is so that we can continue chaining on sequential methods to the previous return value. So what I can do here is given that I have a DebugStruct, I can call the 'field' method once again, because the previous 'field' method will return the same DebugStruct instance, which will have the same 'field' method. So I'm going to call 'field' one more time. Let's add another key of "Price". And for that I'm going to provide a reference to 'self.price'. And then finally, to wrap all of this up I need to call a method called 'finish'. And once this formats and the errors go away, you're going to see kind of the goal here. So this you'll notice is satisfying the expected return type of the 'fmt' method which is aRresult. But you can see instead of the write! macro and the manual interpolation syntax of curly braces, we've now used a method-based approach. That is what the formatter is here to help with. It has a wide variety of these methods that are based on different types in Rust, not just structs, but things like tuples and various lists and similar methods that are going to assist with converting elements of those types to strings or a portion of the final string. This 'field' method is specifically dedicated to taking a field on a struct and rendering its string representation in the final string. So we kind of build up the final result with this sequence of methods. So all in all, I just want to show you. Here we have our Debug formatting. I'm going to run the code. And here's what we're going to get. So let's take a look at how all of these calls map to the output. So first up you'll see the double asterisk ( ** ) syntax. So the Debug string is going to kick off with whatever we passed to the 'debug_struct' method. Then, for both of our two fields, the string slice we passed as the first argument is going to appear here and here. And we can customize that as well. So for example if I want to refer to my 'price' field but output the name of the field as 'Cost', I can do that. And you can see we're now going to have "Cost" here. You can almost think of it like a key-value pair. This is the key that we're outputting, and this is the corresponding value which is a reference to some field on the struct and its data. So here we can see "Kind" and "Cost". And then of course we have the corresponding values, which is what the second arguments to the 'field' method provide. And then of course to indicate that we're done, we call the 'finish' method. And it's that which is going to return the Result type thus satisfying the method. If we do not call 'finish', we're going to keep getting back the DebugStruct itself. And that will be an invalid return type mismatch. So once we call 'finish', Rust will write that string. And it will also return the expected Result type, basically emulating the exact same scenario we had in the last lesson with the write! macro. So this is just an alternative way that you can use this formatter struct and its methods to construct the string that you desire. And this will work of course, for both the Debug trait and its 'fmt' method, as well as the equivalent method for the Display trait. With that, I will see you in the next lesson.

# Implementing the PartialOrd Trait

So next up let's talk about the PartialOrd trait, which is short for partial order. We can implement this trait on a type to indicate that that type supports the concept of order or comparison. With this trait implemented, we can allow our types to use symbols like greater than, less than, greater than, or equal to. It also means that we can sort a collection of that type in order, because the type now supports the idea of being ordered, of being placed inline in comparison with other values of the same type. So the PartialOrd trait is included in the Rust prelude, and it requires a single method called 'partial_cpm', where "cmp" is short for compare. The 'partial_cmp' method receives a reference to the type and a reference to another instance of the same type by default. But we can also define logic to be able to sort values, even if they're of different types. For now, let's just stick with a single consistent type in this lesson. Now I want you to notice that the 'partial_cmp' method must return an option. And in fact, the Some variant of that Option will hold an Ordering enum variant. And that Ordering enum comes from the standard library. So the return value of the 'partial_cmp' method is an enum storing a nested enum. All right. It's also possible to return the None variant of an Option if you want to indicate that two values cannot be compared, and that is needed in certain situations, such as with NaN or not a number which we talked about in the previous lesson. Another thing worth knowing is that the PartialOrd trait is a subtrait of the PartialEq supertrait. So that means if a type chooses to implement PartialOrd, it must also implement PartialEq. And that hopefully makes sense, because if you can sort two things in order and determine which one is greater than or less than the other, it's also logical that you should be able to compare the two and find them to be equal as well, right? It's hard for one thing to be greater than or less than to another thing if we can't also compare whether they are equal, right? So that is why if you're going to be able to sort things and put them in order, the PartialEQ trait is required to also mandate how equality is defined between the two.

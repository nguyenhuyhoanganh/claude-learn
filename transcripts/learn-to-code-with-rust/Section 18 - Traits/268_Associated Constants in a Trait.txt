# Associated Constants in a Trait

So at this point, we're all finished with our lodging project, but there's still lots of concepts to explore around traits, and we're going to cover them throughout the remainder of this section, so you can feel free to delete all of the extra files and folders that we created in the previous lessons, and we're going to pick things back up in a single empty main.rs file. So what have we covered so far? We've seen how to define traits and within them how to require certain methods and functions with various signatures. We've also seen that we can define default implementations for methods within the trait definition. Another thing that we can do within a trait definition is define an associated constant. As a reminder, a constant is declared with the 'const' keyword and it represents a name that is assigned to a fixed, unchanging, immutable value. We've defined constants before in the course, but these associated constants live within the trait. They are part of the trait. So in a sense they represent some bit of data that we can include or store within a trait. Furthermore, the methods inside a trait definition will be able to access that constant and its associated value. So now we can store some data within the trait as long as it is fixed, unchanging, immutable data. So let me show you how this is going to work. I'll begin by defining a trait and I'm going to call this one Taxable. So later on we're going to define various structs that implement the Taxable trait. And Taxable is going to apply to any type representing something that can be taxed, such as your income or such as a restaurant bill. All right. So I'm going to mandate a method for any type that implements the Taxable trait. I'm going to call the method 'tax_bill'. And it's going to give us back the amount that is actually owed in taxes. All right. So this will accept an immutable reference to the instance, some type. And it's going to give me back a float 64 representing the total tax bill. All right. Here is where I'm going to define my associated constant. I'm going to write this code directly within my curly braces. So it is associated or in other words nested within, living within the trait. And only the methods in here will have access to the constant. Nothing else will be able to access this name and its value. So as a reminder, we use the 'const' keyword. Then the name of our choice. I'm going to choose 'TAX_RATE' and the convention here is to write this in all capital letters with an underscore between subsequent words. And then when we declare a constant in Rust, we need to provide the explicit type annotation. Inference will not work. So here I will declare this as being a f64. And then we need an initial value. And furthermore the value cannot change. That's why it's called a constant, because it is constant. It is fixed and unchanging. So I'm going to pick a float representing some tax rate. Let's say our tax rate will be 25%. So I will model that as 0.25. And now I have an associated constant within my Taxable trait. So next up let's define a sample type that will implement the Taxable trait. Down below, I'll define a struct called Income. And this struct will hold a single field called 'amount'. That is how much income I earned. And that can be a float 64. Immediately I'm going to derive my Debug implementation just in case I want to print this out and down below, once again I'll use my 'impl' keyword to implement the Taxable trait for my Income struct. My income is in other words, taxable. So first up, the requirement here is that we need to define a 'tax_bill' method. So let's go ahead and start writing 'tax_bill'. Once I get my IntelliSense, I'll press Enter. And now we have this auto completed. So in order to calculate my tax bill, what I can do is take my 'amount', which is a field that lives on my Income struct. And then I can multiply it by my tax rate. My tax rate lives within the Taxable trait. And because Income is implementing Taxable, it will have access to any constants defined within the trait of Taxable. So here I can say I'm going to take 'self.amount', which I will have access to, then multiply it by TAX_RATE. How do I get access to TAX_RATE? I can actually use the capital-S 'Self' keyword. Remember that is in reference to the type that the methods are being defined on. So this is Income. But Income will technically have access to any constants that are defined within the trait. So if I provide two colons here to access whatever is defined, we can see for example, that tax bill method that we are within. And here is also TAX_RATE. That is coming from the Taxable trait. So I'm going to access it like that. So I'm going to take my TAX_RATE, multiply it by my amount. Make sure to omit the semicolon because we want to return this. And there we have it. Now in the main function, let's actually create an Income. So right here, I'll create my Income struct. I'll provide my 'amount' field. Let's set it to be something like 50000 and 50 cents. And down below I can println! and say "Total tax owed on my income". Here I'll interpolate a value. As a reminder, we can use this formatting right here a colon followed by .2. And what that is going to do is round to a precision of two, which means two digits after the decimal point. I'm also going to add a dollar sign ( $ ) in here before the actual amount. And then of course I can take my Income struct, which will have a 'tax_bill' method mandated by the Taxable trait. And that method will rely on the TAX_RATE constant. And there is the total income that I owe. Okay. Now the beautiful part about this design as well is that it's also flexible. We can also override a constant's value within a specific trait implementation block. For example, maybe this tax rate is not uniform for all of the types that implement the Taxable trait. Maybe this is the most common one, which is why I might want to define it in my trait. Just like I may want to define a default method implementation if that is the most common way that that method could work, but still I can override it when needed. So for example, here let's define another struct called Bonus, representing the bonus that I might get paid at work. And for now I'll define a similar amount field set to a float 64. And similarly I will derive a Debug implementation, and I will also implement my Taxable trait for Bonus. And let us indeed copy and paste 'tax_bill' from above. Let's say the logic for calculating our tax bill will be the same. Take the amount and multiply it by some tax rate. But let's say the tax rate for a bonus is higher than it is for regular income. Well within this block right here, I can declare the exact same constant as above: TAX_RATE and it will override or win over the TAX_RATE in the Taxable trait definition. So here I can declare TAX_RATE. It must be the same name. This will be a float 64. And let's say that the tax for a bonus is going to be higher at 50%. So I'll do 0.50. All right. So when we call 'tax_bill' on an Income struct, it's going to utilize this value. And when we call the 'tax_bill' method on a Bonus struct, it's instead going to utilize this constant right here in its calculations. So down below I can create a Bonus. Let's say my Bonus income this year was $10,000.23. And I can println! once again and say "Bonus tax owed". Once again, I'll provide my dollar sign ($). Once again inject some dynamic content with a precision of two for my floating point. I'm going to take my Bonus struct. It's going to have a 'tax_bill' method as mandated by the Taxable trait. But even though the logic is the same, it will rely on a different tax rate. And if you think about it, 50% of 10,000 is roughly 5000. So we're going to get this output right here. So even though we define constants right here, and even though we can define default method implementations in the trait definition as well, within any given type that implements a trait, we still have the flexibility to override either those methods or those constants as well. So that is a quick introduction to associated constants. They are fixed, unchanging constants, names assigned to constant pieces of data that can live directly within the trait definition and be accessed by any method that is defined or mandated by the trait.

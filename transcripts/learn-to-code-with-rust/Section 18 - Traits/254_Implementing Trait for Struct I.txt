# Implementing Trait for Struct I

Now that we have an Accommodation trait, let's define the first type that's going to implement it. So below the trait I'll define a new struct called Hotel. A hotel is one example of a real world type that will honor the Accommodation trait. It has the distinguishing quality or characteristic of being a place where a person can seek accommodation, where a person can take lodging for a night or two. So we'll begin by defining a struct. We're going to have two fields in this struct. The first one will be the name of the hotel, which I can store as a string. And then I'm going to add a reservations field. And this is going to store information about the people that are staying at the hotel, as well as the number of nights that they are staying. And for this struct, I'm going to store that as a hash map. It's my choice what kind of type or data structure I want to use. Let's go with a hash map here. So first up I want to import the HashMap type into the current module with the 'use' keyword. And it comes from the standard library's 'collections' submodule. So up here I'm going to do use we're going to start with our standard library which is 'std'. Then the scope resolution operator. I want to reach into the 'collections' submodule. And I want to pull in a name from inside that submodule, and that is the 'HashMap' type. Now I have that available at the top level. So I can declare the type of reservations to be a HashMap. Remember that a HashMap requires two concrete types to fill in for the two generics. The first is the type of the keys, and the second is the type of the values. And I'm going to provide that in my angle brackets. Our keys will be Strings representing the person's name and the nights or the values for how long the person is staying will be represented as a u32, an unsigned 32-bit integer. So it'll be something like (Dave, 5) to indicate that guest Dave is staying for 5 days. So that looks good. I'll immediately add my 'derive' syntax right here to derive a Debug implementation. And this on line #8 is secretly an example of traits in action. Recall that Debug is a trait itself with its own method requirements. So what we're doing here is we're asking for Rust to take care of creating the implementation of honoring the Debug trait's requirements. We're just falling back to Rust's default Debug implementation for a struct. For our own trait like Accommodation, we're going to have to write that implementation code from scratch. Next up, let's define a regular 'impl' block for our Hotel. This is where we can define our methods and associated functions. For now, I just want one associated function. A function called 'new' that will serve as a constructor for a Hotel. So here I'll do 'new'. I will not provide 'self' since I want to have a constructor function, not a method. And then I'll accept one parameter here, which will be the hotel name. I'm going to accept it as a string slice just for more flexibility. And this 'new' constructor function will return an instance of the Hotel. I can either write Hotel here or capital S 'Self' to indicate the same thing. And similarly, in the body of this constructor, I can either create a Hotel struct with Hotel or with the capital S 'Self'. Let's go with this approach since it's more durable to change, and I'm going to provide my 'name' field which is required. Here we are getting a string slice, but we need a heap allocated String. So I'm going to take my string slice and I'm going to call 'to_string' on it to get a heap allocated String. And then for 'reservations', we can just create that HashMap inline. So I'll just do HashMap::new. The HashMap has its own 'new' constructor function which I will utilize here. So now I have a simple constructor function to create a new Hotel. So at this juncture, our Hotel struct and our Accommodation trait are decoupled. Let's now make the promise that our Hotel struct will implement the Accommodation trait. We implement a trait for any type by using the familiar 'impl' keyword. Very similar syntax to what we have here, but now we're going to specify the exact trait that we are implementing. So below here in a separate 'impl' block, I'm going to write 'impl' then the trait that we want to implement. So I'm going to write 'impl Accommodation', then a space, then the 'fir' keyword, and then the type that I am implementing the Accommodation trait for. In this case, I want to implement it for Hotel. I am choosing or opting in my Hotel struct into implementing the Accommodation trait. So as this code stands, this will not compile because Rust is unhappy because not all trait items have been implemented. The trait requires these two: 'get_description' and 'book', which we declared in the previous lesson, and we're going to declare them within this block. We're going to define them as regular methods on our Hotel struct. But now Rust will make sure that we honor all of the trait's requirements, that we honor the contract right here. So here inside the 'impl' block, we'll define these two required methods, this time with the actual concrete implementation. The beautiful part here is because Rust Analyzer knows from the trait definition above what those methods are, we can just select either one of them, press Enter and we're going to get part of that autocomplete. We're going to get the exact method signature from above because that's what it must be. What is up to us for any given type is the actual body of the method. How is this going to work? And this can vary for every single type that chooses to implement the Accommodation trait. So here let's start with our 'get_description' method. I'm going to use the format! macro to create and return a heap String. We need to return a String from this method. It is mandated on line #4. And so here I can provide a string. Let me inject the hotel's name here and say that hotel's name is the pinnacle of luxury. And then I'm going to interpolate 'self.name' here. Here I am reaching into the 'name' field of the Hotel struct so I can reach into the instance, pull out whatever fields I want to. It doesn't matter as long as I return a final String. I am honoring the trait's requirements for the 'get_description' method. So here we can see it says you should be returning a String. The reason it doesn't see that is because we do not need a semicolon here. Now we are properly returning a String. We need one more method. We need 'book'. So I'm just going to write out book. Press Enter to autocomplete. But if you want to write it out it's going to be the exact same signature we have here. And this is the beauty. We can store our reservations in our given type, in whatever structure we want. Here we're storing a HashMap. In the next lesson, we're going to create a separate type that uses something totally different to store its reservations. But the 'book' method, as mandated by the Accommodation trait, doesn't care how we're storing it. It just says: "I need a 'book' method. You're going to get a mutable reference to the instance. You figure out how you're going to store it. You figure out the concrete implementation details for a specific type." I just need this method to be available. I just need this contract to be honored. So what I'm going to do is use my 'reservations' field and the HashMap to store the user's name and the nights they're staying, so I can access my instance with 'self'. On my Hotel struct, I'm going to have my 'reservations' field, which is a HashMap. On a HashMap, I have an 'insert' method which mutates the HashMap. Since I am mutating the HashMap that is a field, I am also inherently mutating the Hotel struct instance, which is why this needs to be mutable, and that's why I defined it as such in the trait. And so the 'insert' method for a HashMap takes two arguments: the key and the value to form a pair. So I'm going to take my 'name' parameter from above. I'm going to again call 'to_string' on it to get a heap allocated String. Then I'm going to pass in 'nights' as my value, and we're going to write that as a key-value pair to my 'reservations' HashMap, which is a field inside my Hotel struct. So now I have an actual implementation of the Accommodation trait for one type in my program, which is Hotel. We are honoring the contract above. In the very next lesson, we're going to declare a second totally different type in Rust that's also going to honor Accommodation, but choose to implement these methods in a totally different manner.

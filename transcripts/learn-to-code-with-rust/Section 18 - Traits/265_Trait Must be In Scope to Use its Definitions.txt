# Trait Must be In Scope to Use its Definitions

In this lesson, I want to cover an important technical requirement when it comes to traits. So if you want to invoke a method that is available because a type implements a trait, that trait must be available within the scope of the current file. That trait must be defined, in other words, within the current namespace or module, and this is true for any methods required by a trait and for any type of trait, whether it be one of our own or something from Rust. So here's a very simple example. I'm going to declare two integers, a and b, and they'll both be i32s and I'll declare that type explicitly right here. So let's assign a value of 5. And below I'll declare a 'b' variable assigned to a value of 10. And as we know, if we want to add these two numbers together we can use the addition operator, the plus sign ( + ). But if you want to invoke a method there is an 'add' method available on an i32. So here I can take some. Take my first value of 'a', call the 'add' method, and provide in 'b' to get the sum. And you'll notice we're going to have a compiler violation. Let me run the code and you're going to see method not found in i32 which is sort of interesting, right? So as it turns out, the i32 does actually support the 'add' method, but it is part of the i32 type's Implementation of a trait called Add and Rust will not allow us to invoke the 'add' method unless the Add trait is defined in this file or this module scope. So we have to make sure we have the Add trait available. The reason all of the examples in the previous lessons have worked is because we defined the trait in the exact same file, but that's a matter of coincidence. So notice here that if I add my 'use' keyword right here, and I reach into my standard library into the 'ops' submodule, which is short for operators or operations, in here I have my Add trait. It is the i32 implementation of the Add trait that defines the 'add' method. And now notice the violation goes away and I can output the value of sum. So for any method that is the result of a trait implementation, that trait must be available within the file where the code is being utilized. Now here's something interesting. Traits can mandate methods on a type, and they can also mandate associated functions as well. Remember, associated functions live on the type itself, not on an instance of the type. For example, we have the u64 type in Rust. That is a unsigned 64-bit integer, and this type has a associated function, a constructor function called from string or 'from_str'. And what it does is it accepts a string slice, like say a string slice of the value 5, and it tries to parse a unsigned integer from that string. That's literally where the function name comes from, from a string, try to create a u64. The interesting thing though, is that this 'from_str' function is the requirement of a trait called 'FromStr'. So we cannot invoke this associated function and assign it to a variable, because once again the trait is required to be in the namespace. So this message is a little bit misleading because it says no function or associated item named 'from_str' found in type u64. The u64 type actually supports this function, but only if the trait that mandates it that u64 implemented is in the scope. So once again, we can utilize our 'use' keyword right here and from the standard library reach into the 'str' submodule. And there we can pull in the from string trait, 'FromStr'. And as soon as I save that now the code will work. It's going to give us a Result but I can call the 'unwrap' method right here to show you that we're going to parse out the correct value from the Result, and that is going to be the u32 value 5 right here. But the important takeaway is, regardless of whether it is a method like 'add' or an associated function like 'from_str', these are both requirements of a trait and the trait that the type implemented to have that functionality must be defined in the file's scope. So behind the scenes, when you use a type like u64 in your code, only the core functionality of that type will be included in the final executable. So trait methods or functions are not going to be automatically included until they are invoked. And if they are invoked, in that scenario, you have to bring the trait into the file scope. And then Rust will include that functionality in the executable. And the advantage of this design is that it helps to reduce the final binary size by not including additional type functionality, unless it's actually being used in your code, right? If we're not using the 'add' method, there's no reason to support it on a i32 type. So only when we invoke the method and bring in the trait does Rust understand that we need that additional functionality, and thus it will include that at that point in the executable.

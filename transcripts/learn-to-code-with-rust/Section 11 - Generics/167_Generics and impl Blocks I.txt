# Generics and impl Blocks I

So in previous sections, when we defined methods on structs, those structs did not define any generic types. So our 'impl' blocks utilized a simple syntax. It was the 'impl' keyword, then the struct name, then a block with the method definitions. The syntax becomes a bit trickier when dealing with structs that mandate a generic type. The generic type is intrinsically part of the struct's type definition, so we have to honor that idea within our 'impl' block. So for example, if I declare 'impl' here and just 'TreasureChest' by itself and provide my curly braces, Rust will not compile. You'll see this violation here that says "missing generics for this struct". Rust needs to understand what kind of struct we are declaring methods for. The reason that Rust needs to know that is because our methods have the ability to work on the struct's data, such as the 'treasure' field. But if Rust doesn't know what type 'treasure' is, then it doesn't know what operations or methods are valid or legitimate on that type 'T', right? 'treasure' can be anything, so how can Rust know what we can do with that given field? So there are a couple options available to us. And we're going to explore them in this lesson and the next one. Here is our first option. We can provide a concrete type here within our angle brackets. For example, I can specify a String here. This is a very interesting syntax, so let me explain what it does. What this says is it's going to define the methods in this block, but only on 'TreasureChest' structs where the type of 'T' is String, right? So for example, this struct would be a sample struct on which the methods defined here would exist. In other words, any methods we define here will not exist on a 'TreasureChest' struct with any other type of 'T' besides String. So for example, if we have a 'TreasureChest' struct where 'T' is a string slice, or where 'T' is a 3-element array, these methods will not exist on those structs. These methods will only exist if the type of 'T' is String. It really is that granular. So for example, let's define a method here called 'clean_treasure'.

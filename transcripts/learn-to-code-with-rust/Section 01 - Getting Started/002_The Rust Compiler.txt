In order to understand what a compiler does, let's begin by talking about source code. Source code is the code that we developers write. If you're new to programming, the simple way to describe source code is a sequence of instructions that we'd like for the computer to execute. The Rust source code looks different from source code in a different language like Python or Java, but it's all source code. At the end of the day, it is code that is meant to be readable by humans, by developers. The problem is that the computer cannot understand the Rust source code itself. So that brings us to the compiler. The Rust compiler is a program. It's a piece of software that translates our source code into an executable program that the computer can understand and execute. That executable program is often called a binary or a binary executable, and the computer can understand the instructions in that binary. Now I have the definition of compile on the left hand side, and the computer science term derives from the regular definition, which is to produce something by assembling information collected from other sources. So you can think of the compiler like a language translator. All right. Now that brings us to syntax. Syntax describes the characters or symbols that developers use to write source code. Every detail matters to the compiler because it needs to have the source code be valid and legitimate, so that it can translate or transform or compile that source code correctly into the binary executable that the computer needs to run. All of these symbols add up to the syntax of a programming language, and the compiler needs your syntax to be correct in order for it to be able to translate the instructions into the binary executable.

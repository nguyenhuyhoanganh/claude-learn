# The cargo build Command

In the previous lesson, we used the Rust compiler, rustc, to compile a single Rust file into an executable. And then we ran that compiled program. We also have access to the cargo command line tool, which is designed to compile the complete Rust project. So at the top level of my hello_world project directory, I can build my complete cargo project with the command "cargo build". This command compiles all of the project's Rust code into the final executable. Right now, our project only has one file, but as you can imagine, most real world Rust projects will consist of many files in many directories, and those files are linked together through the code. So the cargo build command will include all of the files, as well as any library crates that the project includes. As a reminder, library crates are external dependencies that you bring into your project. They're other people's Rust code, so while the Rust compiler targets a single file, the cargo build command uses the Rust compiler to build your complete project. We can build or compile the final application in one of two modes: debug and release. By default, cargo build runs in debug mode, so what we have on screen here produced a debug mode build. Let's talk about the differences between debug and release. Debug mode is a fast, unoptimized build. The term debug refers to the process of finding and fixing errors in your code. Finding bugs. This mode of compilation is called debug because the compiler includes additional metadata in the final file to assist with finding errors in the code. So this kind of compilation is beneficial for developers. However, it results in a larger final executable, so we typically use debug mode during development, kind of like a test run for building the final program. That also includes optimizations for helping us identify bugs. Then when we're happy, we create the final program by compiling it in release mode. Release mode takes longer to compile, but it is optimized for runtime performance, so it doesn't include any of that additional debug information, which results in a smaller final executable that's generally preferred. You want your final program to be as small as possible so it runs faster, right? So it's a trade off. Debug is for developers and release is for your final released program. The cargo build command will create the final executable in this target folder. More specifically, it's going to be in target/debug. Debug reflects the mode of compilation that we just discussed. So here you'll see our actual hello_world program. So, if I wanted to, I could run it right now. On a MacBook, I'm going to use forward slashes: ./ to progress from the current directory. So .\target, then it's going to be \debug and then hello world. But you're going to have a .exe extension. But it's the same idea. It's the final compiled executable program. It's going to be placed in target/debug because this is the debug mode. All right. And that is the default mode of compilation when you run cargo build. By the way, if you want a quick shortcut for cargo build, you can also abbreviate it to just "cargo b". That does the same thing. And cargo is pretty smart. So if it knows that no code has changed, it won't actually go through the process of recompiling. So you'll notice here on our first output it said "Compiling". The second time around, it said "Finished in 0.00 seconds". And that's because it knows no code has changed, so nothing will change in the final product or the final executable.

# Comments

Next up, let's talk about comments. A comment is a written note that we developers add in our code. A more technical definition is that a comment is a line that is ignored by the Rust compiler. And that's a good thing, because comments offer us the ability to leave human readable content directly within the Rust file, within our source code. So we can use comments to provide explanations, links, metadata, diagrams, jokes, whatever your heart fancies. It's just regular text that we embed within the Rust file without any compilation problems. So we create a comment with a pair of two forward slashes like so (//). You can also use the VSCode shortcut Cmd + / on a Mac or Ctrl + / on a Windows. The advantage of this keyboard shortcut is that it's going to work across different programming languages, which may have different syntaxes for comments. And then another advantage is that we can use this shortcut repeatedly to toggle back and forth between having a comment and not having a comment. So once again, that's Cmd + / on a Mac or Ctrl + / on a windows. So we create a comment with these two forward slashes. And Rust will ignore anything after these two slashes. I have this line. In this case, line #2, completely to myself. I can do whatever I want here. It will not be treated as Rust code, so there's no technical way to make a mistake. So here, I can provide a nice description about what my program, or perhaps the line below is going to do. I can say something arbitrary like "This program calculates the best time to buy a stock". Then below, let's replace our print line. I can do something like running algorithm, and then I'll copy and paste this println! macro and we'll output some other text like "Making profit". And there is our successful Rust program. Another interesting note is that you can actually add comments to the end of a line. For example, I can add a comment right here after my semicolon like so, and say something like, "This is the key line in our program" and this code is still going to work. Because, remember, the comment begins where the two forward slashes begin. So that means Rust is still going to run this part of line #4. Then, it sees the two slashes and anything else is what it ignores. Another cool thing that comments allow us to do is to quickly enable or disable a valid line of Rust code. For example, let's say I have another println! here, something like "Losing money". This is valid Rust code. So I can run my program. And we're going to see our three pieces of text right here. But let's say I want to check what this program would look like if this line didn't exist. Of course, I can always delete it, but then we have to bring it back. If it turns out we want the line right? With comments, I can simply use that shortcut Cmd + / or Ctrl + / And this will turn the line into a comment, which means Rust will ignore it. So now I can run my program, see how it operates without actually losing the original code. Then if I want to bring it back, I can uncomment my code back in, or if I decide I want to delete it, I can. Or, if I simply want to leave the comment just for future reference, I can do that as well. Remember, as soon as Rust sees the two forward slashes, it knows that it's going to ignore anything after. So the fact that this is valid Rust code is irrelevant. Rust sees it no differently than this or this. It's just ignored content, right? So the double forward slashes is one way that we can leave comments. But there is another syntax option and it looks like this. We're going to add a single forward slash followed by an asterisk which is Shift + 8 on your keyboard. So / plus that asterisk, the star (*). And you'll notice the rust-analyzer extension will autocomplete to close it off with the inverse symbol, which is asterisk followed by forward slash (*/). The advantage of this syntax is that it enables multi-line comments, which means anything between these sets of symbols is considered a comment. So for example, now lines 8 through 13 up until the end here is considered a comment. And thus we can have larger blocks of text. So all of this will be a comment. So you can use this large space for a comment, usually for a more larger blocks of text. For example, I can provide some metadata like maybe the copyright date, right? Copyright 2024. Last updated on June 3rd. Author: Boris. It just buys us a nice big block of space to work with. These extra lines are not needed, but again, anything between the opening symbols and the closing ones are interpreted as part of this comment, and this just avoids having to write each line with two forward slashes. So once again, forward slash and then the asterisk star. And then to close the comment is the inverse the asterisk, then the forward slash. These are both comments. These are lines of text that are ignored by the compiler. You can see the only two valid lines right now are lines three and four. And that's exactly what we see in our final program. And none of these comments cause any kind of compilation errors because the compiler completely ignores them.

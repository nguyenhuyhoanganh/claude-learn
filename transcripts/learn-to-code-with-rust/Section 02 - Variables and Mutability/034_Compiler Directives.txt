# Compiler Directives

Next up, let's talk about compiler directives. A compiler directive is an annotation that we add to the code that tells the compiler how to parse the code. The word directive means an instruction or a command. So a compiler directive is an instruction to the compiler. It's metadata that we add that customizes how the compiler thinks and operates. We can apply these directives to individual lines, to functions, or even to entire Rust files. And there's many different directives available. We're going to explore just one in this lesson, but there's a whole variety of them that customize different configuration settings. So what we do is we write the directive on the line above the entity that we want to apply the directive to. For example, if I add a compiler directive above a line, it will apply that command to the following line. Similarly, if I add a compiler directive above a function, it will apply the directive to the function. So let's take a look. Here we can see our mile_race_length and two_mile_race_length variables are unused. That's why we're getting these warnings in the output. One solution to this, of course, is to use the underscore at the beginning of the variable name. An alternative solution is to give the compiler a directive. So above this line I'm going to add a line break. And we're going to begin our compiler directive with the hashtag symbol (#). That is Shift + 3 on your keyboard. And then we're going to add a pair of square brackets both opening and closing. And that's going to be these two symbols. They're to the right of the 'P' key on your keyboard. Once again, as soon as you add the opening square bracket, rust-analyzer will auto complete the closing one. All right. So hashtag and square brackets. That's the required syntax. And then in here we give our actual directive our actual command. There's many options here. But the directive we want right now is called allow. So what this directive does is it permits or allows a behavior that the compiler would otherwise raise a warning about. It allows something that the compiler would be unhappy about. So for example, the compiler is unhappy about the unused variable on the next line, on line #5. We can allow that behavior so that the compiler will no longer give us that warning. So after allow we're going to give a pair of parentheses once again opening and closing. So it's a little bit confusing because we have square brackets. And then the allow command in there.

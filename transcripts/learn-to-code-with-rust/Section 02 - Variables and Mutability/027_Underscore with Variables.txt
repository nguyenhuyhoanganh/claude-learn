So we still have a warning in our program output. A warning is something that the compiler is unhappy about, although it's not a critical error, so the program still compiles successfully. In this case, the compiler is unhappy because the fruits variable is unused. We can see the warning here as well as if we hover our mouse over the squiggly line in VSCode. So when we say unused, what that means is we're not doing anything significant with the fruits variable. We're not outputting it to the screen. We're not using it as part of a calculation. We're not using it for some kind of other variable value. We're just declaring fruits on line number 4, and then there's no further use for it. And that's what the compiler is unhappy about. Inevitably, as we proceed throughout the course, we're going to run into this warning a lot. And you should absolutely fix it in real life. But it isn't so important for the purposes of these educational videos. We're intrinsically going to have variables that happen to be unused. So if you get annoyed by this, one simple way that you can silence the warning is by starting a variable with an underscore character. You can even see this recommendation right here. It says "help: if this is intentional", which means if you want this variable to be unused, prefix it with an underscore and it shows you that syntax right here. This is a little cheat code in Rust. So, right here, I'm going to add an underscore which is Shift plus the character to the right of the 0 on my keyboard and save. And an underscore tells the Rust compiler to ignore the fact that the given variable is unused. So you can add this underscore in front of any variable name. It actually becomes part of the variable's name, right? But it's just a special symbol that the compiler can recognize to know that it should not give us a warning for the fact that variable is unused.

# Immutable and Mutable Variables

Variables are immutable by default in Rust. The word immutable means incapable of change. That is in contrast to the word mutable, which means capable of change. Variables being immutable by default means that the value assigned to the variable name cannot change over the course of the program's execution. So say I declare a variable. I'm going to call it gym_reps, and I'll set it equal to the value 10. Below, I'll use my println! macro to output a sentence like I plan to do gym reps reps. This is going to work just fine, and then I'm going to attempt to overwrite or replace my original variable value. The syntax to do so is to provide the variable name, this time without the let keyword. So just gym_reps. Then an equal sign surrounded on both sides with a space for readability and then the new value. Say I want to change this variable to now be a name that represents the value 15 instead of 10. Immediatelyl we're going to see an error in VSCode because the gym_reps variable is immutable by default. The error says cannot mutate or change immutable variable gym_reps. Let's take a look at the compiler error we see when we try to run the program. We're going to see right here as well. "cannot assign twice to immutable variable gym_reps". The compiler output will show us the first assignment right here on line number 2. And then right here, when we try to assign a new value to the existing gym_reps variable name, it's going to say "cannot assign twice to an immutable variable". Notice that Rust recommends making this binding mutable. A binding is another good term to describe a variable, because the word bind means to connect. A variable binds or connects a name with a value. So it's asking us here to make the variable mutable. When we make a variable mutable, we make it capable of changing its value over the course of the program's execution. The way we do that is when we declare the initial variable with the let keyword, we're going to add a 'mut' keyword directly after let and a space. So let comes first, then a space. Then we're going to do a new keyword called mute. Just 'mut'. It's pronounced mute and it is short for the word mutable. The 'mut' keyword allows us to reassign the value that the gym_reps variable represents. So now on line 5, we are no longer going to get an error. We're just going to get a warning because we're not using gym_reps after line number 5. It's important to note that we can update the value, but we still cannot change the type of the variable. So, in other words, since gym_reps starts out as an integer, in this case an i32, we cannot assign it to a different type like a string, right? It must stay an integer. Even though the value can change once we have a mutable variable, the type of the data cannot change. All right. So now I can copy and paste this line below and say: "I now plan to do this number of reps" and it should be updated to a value of 15. So this is actually where the term variable starts to make more sense. A variable gets its name from the fact that its value can vary. In other words, it is subject to change over the program. Rust is a pretty defensive language, and thus it requires the developer to be explicit every time we want to enable a variable to even be capable of change. So, by default, every variable with the let keyword will be immutable. We are not going to be able to change its value over the course of the program, but as soon as we add the 'mut' keyword after 'let' before the variable name. Now, we have the opportunity to change what this variable represents over the course of the program.

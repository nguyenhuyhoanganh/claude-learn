# Type Aliases

In this lesson, we'll learn about type aliases. A type alias is a nickname or alternate name that we can assign to an existing type. The benefit of a type alias is that we can provide some additional context on what that type represents. For example, let's say we're modeling a program for professional runners, and we want to represent the idea of the length of a track race. So I could declare a variable like mile_race_length right here. And I intend for this to represent the idea of the meters in the race, the length of the race. For a mile, that is 1600 meters. So you'll notice that Rust will infer the type of this variable as an i32, an integer, a whole number. And we can also explicitly annotate the type if we want. So here, I can put my colon and write out the type as an i32, but I think it would be even better to create a new type alias called Meters, because Meters would provide even more context, even more clarity on what 1600 represents. It's not just an arbitrary integer, it's a specific concept to our program called Meters. So, above the main function, I'll use a new keyword called 'type'. After 'type', I'm going to add a space and then choose my type alias name. And this should have a capital first letter. So here I'll declare my type alias called Meters. Then, I'll provide an equal sign, and on the right hand side, I'll provide a type. In this case it will be an i32. So notice that I am not assigning a value like 5. I am assigning a type like i32. So what I've done is I've created an alias or a nickname called Meters which represents an i32 type. So now, whenever I want to use an i32, or more specifically when I have a variable that represents a number that represents Meters, I can instead use this type alias of Meters instead. So here for this i32, I can remove this and provide a type of Meters. There is no difference under the hood, but now there is clarity and context for future readers of what 1600 represents. And then I also have the capacity to reuse my type variable. So here I can declare another variable like two_mile_race_length, which is also going to store a value that is of type Meters, which is an i32 and this is going to be 3200. So now readers can understand that the types of these variables are also related. They are modeling the same idea. Everything else remains the same. For example, just like any integer, I can output these variables and we'll see the exact same result. And that's because they are still i32s under the hood. We just gave that type a new nickname of Meters. So I can say something like "A one mile race is mile race length meters long, and a two mile race is a two mile race length meters long". Provide my period, provide my semicolon, and we're going to get that content. You can see the integer is still correctly interpolated within my string, but within the code for future readers, I have provided a more context and more clarity through the use of a type alias.

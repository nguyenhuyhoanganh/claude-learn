So let's take a moment to review everything that we learned in this section of the course. First up: variables. A variable is a name for a value in your program. It's a placeholder or a stand in for some value. We declare a variable with the 'let' keyword followed by a variable name of our choosing in snake_case format, then an equal sign, and then the value that that variable will represent. Now Rust and the compiler will infer a variable's type from its initial value, from that assignment. We can also explicitly annotate the data type with a colon, and then the type itself. And the type is the kind of data or the category of data that that variable is representing. For example, an integer has an i32 type, a floating point value, or a decimal point number, in other words, has a type of f64. So there are different data types in Rust. And we declare that a variable is of a specific type. But again, the compiler can infer what that type is from the initial assignment. Once we have our variable, we are welcome to dynamically inject it into a string, and that is called interpolation. We use the curly braces inside our string, inside our double quotes. In order to inject some dynamic content. We can then either write the variable name inside the curly braces, or pass them in as an argument to the println! macro. That is the sequential inputs that we pass after the first string that we provide to the println! macro. Now, Rust is also going to assign a numeric position to each argument that you provide after the string to println! But remember that count starts from 0. And that's going to be a very common pattern that we're going to see throughout various operations in Rust. So, if you have a string with two curly braces, and then you provide two inputs after the string, the first one will be assigned a position of 0, and the second one will be assigned a position of 1. We can reference those numeric values directly inside curly braces. And the advantage there is that we can reuse a value. We can re-inject a dynamic value more than once without having to provide it multiple times in that input list. We can instead just reuse its position number. All right. So, Rust variables are immutable by default. Immutable means incapable of change. So an immutable variable cannot change its value. In order to make a variable mutable, we add the 'mut' keyword, 'm u t' after the 'let' keyword that declares the variable. Now the variable's value can change over the program's execution. It's important to note that a mutable variable can change its value, but not its type. So, for example, if the variable began as an integer, you can assign another integer to it once it is mutable, but you cannot assign a different data type, such as a string or a floating-point value. So the value can change, but not the data type of the value. We also talked about constants. A constant is a hard coded, immutable value that is known at compile time. The advantage of constants over plain immutable variables is that constants can be declared at the file level, and then reused across multiple functions. Constants require an explicit type annotation. That's the same syntax of a colon after the constant name, and then the data type, and then the equal sign, and then the initial value. And that's all going to be embedded into the final executable, because it is a value that is known at compile time. All right. Variable shadowing. Variable shadowing is when we redeclare an existing variable with the let keyword. So it's only variable shadowing if the variable has been declared previously. And then we once again use the let keyword with the same variable name. And this technique is common when transforming a value to the same representation, but in a different data type. So for example, converting a string to a number is a common use case for variable shadowing, because otherwise you would have to come up with a different variable name for each step of the process, even though the value fundamentally represents the same idea, it's just transforming from one type to another. So when we reuse the let keyword with an existing variable name, this new declaration overshadows the previous one, kind of takes precedence, which also invalidates the previous variable declaration. And with variable shadowing, we now have the ability to switch to a different type if we want to do so. We also learned about scopes. A scope is the boundary or region in which a name in the program is valid. When I use the word valid, I mean capable of being used. Scopes are closely connected to the idea of blocks, and a block is the technical word for the area that you create with a pair of curly braces. So, for example, when you declare a function like the main function, we have a pair of curly braces which creates a block which intrinsically also creates a scope. It's a dedicated area. You can think of it like an isolated playground or a separate execution environment, and there can be many different execution environments within a given file. So for example, we saw that we could create a nested block within the main function using our curly braces. And that created its own little sandbox, its own little separate environment. And we saw that, for example, variables declared within any given scope only lasted as long as that scope was valid. So a variable that we declared within the nested block in main was not available in main. After that nested block concluded, because it was the end of the scope, the variable will not last past the boundary or the region in which it is declared, and that is its scope, which is connected to its block, the area between the opening and closing curly brace.

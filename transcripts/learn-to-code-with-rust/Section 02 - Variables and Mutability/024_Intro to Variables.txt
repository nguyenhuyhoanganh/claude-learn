# Intro to Variables

Welcome to the next section of the course. In this section, we'll cover variables and mutability. A variable is a name assigned to a value in our program. You can think of a variable like a placeholder or a stand-in for a value. Any time we want to use that value, we can instead write the variable name and use it as a replacement for the value. Variables have several benefits. First, the variable serves as a identifier that provides context on what the value represents. Secondly, variables enable reuse. I don't have to keep writing the same value down when I can instead refer to it by its variable name. For example, if I simply write the value 50 right here. There's immediately two problems. Number #1, another developer doesn't know what this value represents in our program. What is 50? What does this integer represent? Secondly, I cannot reuse this value of 50 after this line. So let's say this number represents a count. More specifically, a count of apples. In my garden, we can declare a variable called apples and make apples a name or a placeholder for this value of 50. So let me show you that syntax. We declare a variable with the let keyword, let then a space, and then we choose our variable name. So this time around I'll choose apples. The variable name is up to us. It's the name or a description that we want to give to the value. The variable name should follow what's called snake_case formatting. snake_case means we write the name in lowercase, and we separate every two words with an underscore. The reason it's called snake_case is because it visually resembles a snake when you look at it from a distance. So, for example, if I wanted to call this variable apples in garden, I would write it like this all lowercase and separating every two words with an underscore. So here an underscore between apples and in and another underscore between in and garden. Let's just stick with apples for now. Afterwards, I'll provide an equal sign usually after a space for readability. So space equal sign, then another space for readability. And then the value that apples will represent. So here I'm going to write 50. So usually we surround both sides of the equal sign with a space for readability. So it's easier to parse this line. We also need to add a semicolon at the end of this line to terminate this statement. You can think of a semicolon like a period at the end of a sentence. It tells Rust we're done expressing our thought or our command. In this case, this is called a variable assignment. We are assigning a value to a variable, assigning a value to a corresponding name, and that represents its own thought, its own command. So it needs to conclude with a semicolon. So you probably noticed this thing pop up right here, this i32 that appears next to apples. This is actually a feature of the rust-analyzer VSCode extension. So this i32 is not part of our source code right now. It's more of a visual guide to help us. And what the i32 refers to is the inferred data type of the variable. This is the type of data the Rust is deducing that the variable is representing. In this case, the "i" stands for integer, which is a whole number. That's one example of a type. An integer is a kind of data. It's a category of data. So whenever we assign an initial value to a variable, Rust will assume or infer what the type of the variable will be. It can be a number. It can be a floating point number. It can be a piece of text. Right. It can be a currency or a date. These are all real world data types. And Rust is similarly assuming or inferring what "apples" is storing. The kind of data that it is storing as far as the 32. We'll discuss that in greater depth in the next section of the course, but it refers to the amount of memory that this integer will occupy on your computer when this program runs. So this is Rust telling us "Hey, you declared this apples variable, but you're not utilizing it for anything. What's the point of it? Why does it need to exist?" So this is Rust trying to help us. rust-analyzer will also show us squiggly lines for errors, and I believe those will be highlighted with a red squiggly line. And the difference between a warning and an error is a warning is just something to watch out for, while an error is something that will cause the compiler to be unable to build the program. So an error is more serious because it means the program isn't working at all. While a warning simply means here's something that you can fix or optimize, all right? Another important point to remember is that Rust will evaluate the right hand side of an equal sign first, before it assigns the variable to the value. For example, I'll declare another variable once again with the let keyword, and I'll call this variable oranges. This can be a count of the oranges in my garden. On the right hand side of an equal sign, I'll add a mathematical expression. We haven't yet talked about math in rust, but we use the familiar symbols that we learned about in grade school math. For example, addition is done with the plus sign, and subtraction is done with the minus sign. So I'll add two arbitrary numbers here. I'll do something like 14 + 6. And the convention is once again to add a space before and after the plus sign, just for readability. And once again I need to add a semicolon at the end. So again, Rust is going to evaluate the right hand side of the equal sign first. So it's going to add 14 + 6 to arrive at a sum of 20. So the oranges variable will be a name representing the value 20. In our program, our code can use variables just like regular values. For example say I wanted a third variable that represented how many total fruits I had in my garden. It's important to note here that we are not adding text together. We are not adding the text apples plus the text oranges together. Apples and oranges are variables. They are placeholders and stand-ins for values. apples is a name for the value 50. oranges is a name for the value 20. So on line number 4, Rust gets the corresponding appropriate values for these variables, 50 and 20, adds them together because the right hand side is evaluated first.

# Constants

In this lesson, we'll learn about constants. A constant is similar to a variable. It is a name that we assign to a value. However, a constant can never change its value throughout the program. We cannot use the mut keyword with constants. The compiler will prevent it. So constants are permanently immutable. That's why they're called constant. The first question that you have is probably: What is the difference, then, between a constant versus an immutable variable? And there are two differences. The first is that variables are limited to a function scope, while constants can be declared at any scope, including at the file level. This allows them to be reused across multiple functions. We talked about scope in the previous lesson. We saw that variables, their scope will end when the function that they are declared within concludes. With constants, we can declare them outside of any function at the file level, and then have access to that name within any function in that file. The second important difference is that the constant's value must be known at compile time. A variable's value is defined at runtime when the program runs. A constant's value must be known when the Rust compiler actually builds your program. For example, you can't use a constant to store something like user input. The program will not have that value until we run the Rust program, the executable, and collect the user input. Now, we may still want that user input to be immutable in the sense that it's a value that we do not want to change throughout the program, but the key point is that we do not know it in advance, and thus it must exist as a variable. A constant is for values that you know in advance at compile time, and usually they represent those hard coded values that are going to be repeated many times throughout the program. Let's take a look at a few examples in this lesson. So in order to declare a constant we're going to use a new keyword called 'const'. And I can use it directly within main. That's totally fine. But as I mentioned, the advantage of constants is that we can use them at the file level. So here I'm going to use the const keyword to declare a constant followed by a space and then its name. Now Rust's convention for constant names is to use all capital letters with underscores in between subsequent words. So I'll call my constant TAX_RATE. Let's say that I'm writing some kind of accounting program, and a tax rate that I know in advance is perhaps the perfect example of something that I know is going to stay the same throughout the entire program, and something that I know in advance, and something that perhaps multiple functions will want to rely on. That's what makes it a great candidate to be directly written as a constant. That way I don't have to repeat it and redeclare a variable for it within every function that wants to reuse this value. Okay, now when declaring constants, we must manually provide the type and the actual value of the constant. What is this thing? What kind of data is this constant representing? With a variable, Rust can infer the data type from the initial assignment. With a constant, we actually have to explicitly write the the type, even though we're about to assign an initial value, and that value will never change. It is a requirement technically for constants to have an explicit type annotation. So I want this constant to be a decimal point number. So I'm going to add a type of float 64 which is f64.

# The if let Construct

We'll often encounter a scenario where we only care about executing some conditional code if we have one specific enum variant. The disadvantage of the 'match' keyword is that it is exhaustive. It has to cover every possible variant. So if we have ten variants and we want some code to run, but only for one of those variants being met, the 'match' keyword can be a bit excessive. It forces us to cover every possible option, including those options that represent dead end code. So granted, we could simplify that solution with something like the underscore, the kind of catch all symbol, but it's still not ideal because then we're writing code for the underscore that is still not intended to run. So we can solve for this problem of wanting to match against exactly one variant by using a construct called 'if let'. We've seen both of these keywords before individually. Now they're combined. The 'let' keyword declares a variable, and the 'if' keyword evaluates an if statement to see if an associated block of code should be executed. If we have a true, then we execute the block, and if we have a false, we do not. So, as you might guess, the 'if let' keywords in combination allows us to both define a variable and conditionally execute a block of code if a condition is met. And the 'if let' is usually going to be paired with an enum variant. So let's begin this lesson by deleting our 'impl' block. We no longer need it, and we can clean up anything in 'main' if you have it. And then I'm going to add one more variant to my enum of 'Milk' And that is going to be 'NonDairy'. And all I want to do here is to have a struct variant. So I'll declare my curly braces and I'll add one field of 'kind' set to a String. And this is just so we cover every possible scenario, every kind of way that we can store associated data. So let's begin with the simplest example in the body of main. I'll declare a 'my_beverage' variable. And I will assign it to a variant of 'Whole'. And let's assume that this data will arrive dynamically. Right now it's hard coded, but let's say it will come from something like user input. So we cannot predict it in advance and say we want some conditional code to run. If 'my_beverage' is storing the 'Whole' milk variant and not any other variant. So here's what the syntax is going to look like. We're going to begin with 'if' and then 'let'. Then on the left hand side of an equal sign ( = ), we're going to provide the hard coded enum variant that we want to compare against. So in this case I want to compare against the 'Whole' variant. So I'm going to write it out here. So the value that you're comparing against must always come first. So this is not the dynamic, unpredictable value like 'my_beverage'. This is the hard coded specific variant that you want to be matched or met in order to run some conditional code. Then you provide a single equal sign ( = ) and then the dynamic value to compare against the 'Whole' variant. So here I'll do something like 'my_beverage' and then provide my curly braces. So you might be asking where is the actual variable declaration happening with the 'let' keyword. This just looks like a regular if statement. Well, that declaration will occur when you have a variant with associated data. So for example, let's now change this to compare to a 'Lowfat' variant. So it's still an if statement, but it's made a little bit more powerful by combining it with let. So you get both a conditional block to be executed potentially, as well as a dynamic variable declared for the existence of that block. And that variable's value will come from the variant's data. And the syntax supports both a tuple variant and the struct variant.

# Defining Methods on Enums

Just like with structs, we can define methods on our enums. We do so with the 'impl' keyword followed by the enum name, and then a block within the block. We define our methods which will belong to the instances of the enum, and we can also define associated functions. All right. So let's start with a simple example. And we'll work to transition our 'wash_laundry' function to instead be a method that we can invoke directly on any enum instance. So after the declaration of the enum, I'm going to add the 'impl' keyword, which is short for implement. We are implementing methods for the given type, and after 'impl' I'll provide my enum name 'LaundryCycle' and then provide a block inside. Just like with structs, I'm going to use the regular function declaration syntax. So 'fn' and I'll declare a method called 'wash_laundry'. Every enum instance, every LaundryCycle enum instance will now have access to a 'wash_laundry' method. Inside the parentheses, I can declare my parameters, and you may recall that the first parameter in any method is going to be 'self', and that is going to represent the instance itself in some form. Just like with structs, our methods can choose to take ownership over the enum, or borrow it or take a reference to it, either mutably or immutably. So you may recall you can use this shortcut right here, &self, which represents an immutable borrow, an immutable reference. This is a shortcut for writing out 'self' and declaring the type to be a borrow of a LaundryCycle instance. Those two options are the same, and you may also recall the capital 'S 'Self' keyword, which refers to the type that we are implementing for. So this syntax is also valid. Capital 'S' 'Self' here will represent 'LaundryCycle'. It's whatever type we are using for 'impl'. So this syntax is also the exact same result. They're all representing immutable borrows of the instance itself, so that the 'wash_laundry' method does not take ownership and consume the 'LaundryCycle' instance, right? If we took ownership with 'self', we would then have to make sure to return the enum instance in order to preserve it, right? In this case, I just want 'wash_laundry' to output this helpful text.

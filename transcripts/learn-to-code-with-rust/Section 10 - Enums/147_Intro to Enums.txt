# Intro to Enums

Welcome to the next section of the course, which is entitled enums. An enum is a type that represents a set of possible values. Each possible value is called a variant. The word enum comes from the word "enumerate", which means to mention one by one. An enum is useful when a type represents a value from a limited collection of possible values. There's lots of examples of enums in the real world. For example, the days of the week can be represented as an enum with 7 possible variants, 7 possible days of the week. The seasons of the year can be represented as an enum with 4 possible variants. The countries of the world can be represented as an enum with 170 or so options. We could model a season as a string, but that isn't necessarily the best type, because a string can be any piece of text whatsoever. The 4 seasons of the year, in comparison, is a limited set of 4 concrete values. It's not any arbitrary string value, it's one of 4 possibilities. So an enum allows us to define a type that represents that set of finite limited options. So to declare an enum, we're going to begin with the 'enum' keyword. And I'll declare this outside of main so that my enum is available throughout the entire file. So we begin with our keyword of enum, then a space and the name. The name is written in PascalCase. PascalCase means we capitalize the first letter of every word. Let's say that we are modeling a deck of playing cards and want to represent a playing card suit, so I'll declare a card suit name here. Very much like with a struct, we are declaring the name of the enum here, and then I'll declare a pair of curly braces. Inside here, I'm going to declare my variants, separating each one with a comma. That is the technical requirement and then a line break for readability. The variants are also written in PascalCase, capitalizing the first letter of every word if there are multiple words. And since these are variants, we do not need to declare quotes around them. So to clarify, these are not strings, they are variants belonging to the enum. So we're going to write one variant per line and separate each with a comma. So for example there are 4 possible card suits: Hearts, Diamonds, Spades, and Clubs. So I'll begin with Hearts, then a comma and a line break. My next one is Diamonds. Then a comma and a line break Spades and then Clubs. An enum by default does not implement either the Display or Debug trait. So there would be no way for us to print out a string version of an enum instance. However, just like with a struct, we can derive a Debug trait implementation by using the 'derive' attribute. So above my declaration I'll use my hashtag ( # ) and my square bracket syntax. My attribute or my directive is 'derive', and I specifically want to derive the Debug trait implementation. So now I can reference an actual concrete enum instance using the format specifier and the question mark to get a string representation. I want to also point out that this enum that we've declared is just like a struct definition. There is no instance yet. We've just declared a blueprint. This is a set of 4 possible values, 4 possible variants. So here within main, let's now actually create an instance or a concrete value from our 'CardSuit' enum type. So I'll declare a variable of 'first_card' And what we do is we first begin by referencing the top level enum. That is 'CardSuit'. And that by itself is not enough because we need a specific variant. So what we do afterwards is we use this double colon ( :: ) syntax and then we write the specific variant. Let's arbitrarily choose Hearts here. You'll notice that that double colon syntax is identical to the syntax for accessing an associated function inside a struct, which sort of makes sense because both of those ideas serve as the namespace for some kind of internal information. We are accessing a variant of Hearts, and you can think of that as an option that symbolically lives inside the enum or inside the enum's namespace, so to speak, just like an associated function lives inside a struct. So the name Hearts is not going to be legitimate in our program. We need the enum prefix so Rust knows where Hearts is coming from. We are more than welcome to declare an explicit type, as always, and you'll notice that type is not Hearts. The type of this variable is the enum, which is 'CardSuit' like so, and similarly we can declare another variable. Let's call this one 'second_card' and I can choose a totally different variant. So on the right hand side we once again provide the full enum name: 'CardSuit'. Then double colon and then one of those 4 possible variants or options. Let's do Spades this time around. All right. The same usual principles apply as far as mutability and things like ownership. So for example, if I declare 'second_card' to be mutable, I can reassign the 'second_card' variable or its name to a different value, but that value must be of the same type. What is the type of 'second_card'? It is a 'CardSuit' enum. That means we can reassign 'second_card' to be any one of these 4 variants, but we cannot assign it to be anything else. Obviously not a string or a Boolean or a float, but also not a variant from any other enum. 'CardSuit' is a specific enum. It is a specific category of 4 options, and once this variable's type is declared, it must stay that type. So for example, here I can take 'second_card' and I can reassign it to be a 'CardSuit' variant. Let's say this time around we're going to go with Clubs. And there we have it. So enums are owned values just like structs and strings. So for example if we assign an enum variable to another variable, the usual principles of ownership will apply. If we pass an enum into a function as a parameter, the parameter will take ownership. If we store an enum inside a larger type like an array, a tuple, or a struct, then that parent type will become the owner of the value. It's the same principles that we've seen with heap data like strings before. It's now just applying to this new type of data that we have. So I just want to show you a couple quick examples. So for example here I can declare an arbitrary struct called 'Card'. And I can create two fields inside this 'Card' blueprint. Let's say a card will have a rank that can be a String. And then I can declare a 'suit' field whose type will be a 'CardSuit' enum. So we can absolutely use an enum like any other type in Rust. For example, it can be the value of a variable. It can be the value of a field inside a struct, right? One thing I forgot to do, of course, is simply output the value of an enum. Let's try that right here. So here I'm going to println! And we did derive a Debug implementation right here. So I can provide my colon question mark syntax ( :? ) and provide 'second_card' This is going to print the Debug representation of my 'second_card' variable, and you can see the Debug representation is simply the variant name without the actual top level enum. So Clubs right here is that Debug representation. Here's a couple more examples. If I, for example, declare a 'card_suits' array, let's say, with square brackets. We can populate this with multiple variants from the same enum, because that array will then be consisting of the same type, right? Remember the type of the elements inside an array must be consistent. So if we, for example, have a Hearts variant in here we can see the array is storing 'CardSuit' elements. And thus any follow up elements must also come from the same enum, from the same collection of 4 possible variants. So for example here I can do something like Clubs. Once again, the 'card_suits' array becomes the owner of these two enum variants. These two concrete enum instances the exact same way that a variable does. Same principle will apply to something like tuples. Here I am declaring a two element tuple consisting of the Hearts variant and the Spades variant. So if, for example, we were to try to assign one of these index positions to a variable, that variable would attempt to take ownership over the element from the array or from the tuple. And we saw that we encountered some problems with that before when dealing with things like strings. Basically the exact same principles of ownership continue to apply. Key takeaway here though, is really this content right here. An enum is just a finite set of possible values. 'CardSuit' is a collection that can be one of 4 things: Hearts, Diamonds, Spades, and Clubs. And certain real world constructs are best modeled by this kind of design as a collection type, but one that only permits one of several possible finite limited values.

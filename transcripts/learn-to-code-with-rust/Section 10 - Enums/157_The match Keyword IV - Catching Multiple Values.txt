# The match Keyword IV - Catching Multiple Values

We can match against multiple values in a single match arm. There's actually a couple of ways to accomplish this and we'll discuss them in this lesson. Let's begin by declaring a new enum called 'OnlineOrderStatus'. Its variants will reflect the different stages that an online order goes through, so we can add 'Ordered'. We can add 'Packed'. We can add 'Shipped' and then finally 'Delivered'. Let's add the 'impl' keyword afterwards, followed by the name of my enum. 'OnlineOrderStatus'. Then a pair of curly braces. And in here we can define a method. Let's call our method 'check'. And once again, it will accept an immutable reference to the enum instance, which I can represent with ampersand self ( &self ). And in the body I'll once again use my 'match' keyword in combination with 'self'. And I just want this method to relay to the user the status of their shipment. Let's say for the sake of our business, I want to tell the user, first up, if their order has been delivered. So for example, I can target 'OnlineOrderStatus' and target the 'Delivered' variant within the enum. And if it is the case that that is what 'self' is, I can output something like "Your item has been delivered". All right. Now let's say for the other three variants that I don't care about which one it is, I want to communicate the exact same consistent message to the user. So as a reminder, we can add this special character of an underscore within a match statement. This underscore is an arm. It is a pattern. But it is called a catch-all because it will catch all possible variants. It will match on anything. It is guaranteed to form a match. That is why it is critical that you add this option as the very last one, and that is because if you accidentally place it at the very top, like here, Rust will analyze from top to bottom, and thus it's always going to match on this one and thus never have a chance to get to 'Delivered' here. That is exactly the warning we're getting here. Unreachable pattern. There's no way that we can actually match on this arm because it will never be reached. So this underscore, which matches everything, must always come last. And here I can put a message like println! "Your item is not there yet". All right. And that will cover all three of our other variants. So for example here in my main function, I can create a simple variant like 'Delivered' and call the 'check' method on that with parentheses. And we're going to get "Your item has been delivered". And if I choose any one of my three other options such as 'Ordered', I'm going to get "Your item is not there yet". Right. Same thing with something like 'Shipped'. We're going to get "Your item is not there yet". Another thing we can do whenever we want to execute the same block of code for multiple variants is to match multiple variants within a single 'match' arm, and we could do so with the vertical pipe symbol. For example, here I can begin by providing my 'Ordered' variant, and I can of course provide my block here. That is totally fine, but what I can also do is add a vertical pipe ( | ) afterwards. And usually I'm going to surround both sides of that pipe with a space for readability. You can think of this as an either/or. So I'm saying either 'Ordered' or whatever is on the right hand side. If either one of those match run this corresponding block. So here I can add something like 'OnlineOrderStatus' and target something like 'Packed'. So matching on either one of these two will cause this block to run. And if it's been 'Ordered' or 'Packed', I can output something like "Your item is being prepped for shipment". All right, so now I can provide something like 'Ordered' here. It will match on this arm now. So no longer this last one but this one. And it's going to output. "Your item is being prepped for shipment". And if I update this to be the 'Packed' variant, we're also going to get the exact same message. So let's come back to our first example. I'll delete this match arm and we can use the underscore to match all possible cases. Another thing we can do is provide a name here. You can almost think of this like a variable name that is going to capture whatever the enum variant is. The advantage of this is rather than simply providing an underscore, we're going to be able to capture the variant itself. We're going to be able to know what it is. In this scenario, we have no way of knowing which one of the other three variants we are hitting right, whether it be 'Ordered', 'Packed', or 'Shipped'. We're going to match on those three, but we're not going to know which one specifically we have. If I provide a name here, like say 'other_status', this name is entirely up to us. This, very much like the underscore, will match all possible cases, but now we're going to have 'other_status' as the name of that given variant, and I can use it directly here within my string. So for example I'm going to try to interpolate it here. It's not going to work yet because we don't have Debug formatting yet. But I can say "Your item is" and interpolate 'other_status' here. This is not going to work because 'OnlineOrderStatus', which is what 'other_status' represents, basically what 'self' represents as well if you think about it but it doesn't implement Display or Debug. So if I want Debug, I can add this syntax. But our enum currently doesn't implement Debug either. So we can quickly fix that by adding my 'derive' attribute up top. And that should do it. So now if for example I have 'Packed', we're not going to match on 'Delivered', we are going to match on this because it's a catch all. But now 'other_status' will be the value of 'Packed'. And I'm going to interpolate it directly within my string with the Debug formatting. So I'm going to get "Your item is packed". If I switch this to something like 'Shipped'. Same rules apply. When we invoke the 'check' method, we're going to compare the instance, this one right here, with these variants. These 'Shipped' variant is not going to match on the delivered variant, but it is going to match on this catch all, in which case 'other_status' will be equal to 'Shipped'. And we're going to see the Debug representation of that variant which is 'Shipped' right here. All right. So that is how we can catch multiple values within a single match arm.

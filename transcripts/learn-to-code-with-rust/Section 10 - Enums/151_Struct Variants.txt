So there are thus three kinds of enum variants that we can declare syntactically. And they actually mirror the three kinds of structs. It's like a 1 to 1 mapping. For example, a variant without data like 'Cash' is parallel to the idea of a unit-like struct. It's a struct that stores no data, right? Similarly, a tuple variant like 'CreditCard' or 'DebitCard' stores data sequentially, so it is equivalent to a tuple-like struct because the data is stored by position or order. And finally, a struct variant like PayPal with named data is parallel or similar to a named field struct, because data is stored by fields, by name. So a lot of these different types, whether it be tuples or structs or enums, have these similar syntaxes because it's the same idea of choosing the right container that's going to store other data inside of it.

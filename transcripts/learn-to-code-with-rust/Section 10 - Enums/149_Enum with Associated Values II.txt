# Enum with Associated Values II

One advantage of associated values is that different enum variants can store different data. They can have different amounts of data of different types. So let's say that our PayPal variant requires different credentials from DebitCard and CreditCard. Maybe DebitCard and CreditCard will store an account number in our system, while the PayPal variant will store an email address and password instead. That's two pieces of data. Let's say both represented as Strings, so we can have a different collection of data belonging to a PayPal variant. So here I'm going to say we need two Strings. We're going to do a String type. Then, I'll provide a comma and a space and require another String value that will be stored as an associated value related to the PayPal variant type. It's the exact same syntax as declaring a tuple type declaration. We separate every two types with a comma and then a space for readability.

Combining an enum variant with associated data is so common that Rust supports a shortcut that pretty much emulates this scenario. What we can do is we can have each enum variant store one or more pieces of data. So when defining an enum variant, we can declare a parentheses after any variant that we want, and then define the associated pieces of data that that variant will store. And this basically eliminates the need for something like a tuple. For example, after the CreditCard variant, I'm going to add a pair of parentheses. You can almost think of this like a tuple of data that is associated with the CreditCard variant. So let's say we want one piece of associated data: the account number, a String like this. So here I'll declare the type of that data. In this case, capital S 'String' for a heap allocated String. So this variant syntax is called tuple variants because it's basically a variant that holds an associated tuple of data. There are in fact different types of variants that we can store within an enum. Currently, as our code is written, the CreditCard variant will store one piece of associated data a String, while DebitCard and PayPal will store nothing at all. And that's totally fine. The variants do not have to store the the same data, right? They can store whatever they want. And with this tuple variant syntax we declare that sequential list of associated data within parentheses. We are not limited to one piece of data, and we are not limited to a String type. We can, for example, have our CreditCard variant store three pieces of data: say a String, as well as an i32 as well as a bool. So the syntax looks exactly like how we would declare the types of a tuple. Within the parentheses, we declare the sequential order of the elements, but not the actual concrete values, just the respective types. So a CreditCard will have 3 associated pieces of data that must be a String, then an integer, then a bool in that order. Behind the scenes, each enum variant becomes a function that constructs an instance of that enum variant and then accepts those respective values.

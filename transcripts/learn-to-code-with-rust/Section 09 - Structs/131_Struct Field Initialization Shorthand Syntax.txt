# Struct Field Initialization Shorthand Syntax

In this lesson, I want to show you a shortcut that we can use to simplify the creation of a struct instance. It's a common practice to give our function parameters the same names as our struct fields. That's exactly what we did in the previous lesson. When this is the case, we can use a shorthand syntax for creating our structs. So if a parameter name or a variable name matches a struct field name, we can just write the field name once without any colon like so, and Rust will automatically connect it to the corresponding name that it locates. So Rust says: I have a 'name' field in this 'Coffee' instance, I'm going to look for a 'name' name. It finds it right here in the parameter list, and it automatically associates the 'name' argument with the 'name' field. Similarly, here I can simplify this to just be precise, we must have some 'name' in our program, whether it be a parameter or a variable that matches the field name. So if this was called 'my_price', this would no longer be valid code. Rust would not be able to associate them together, but if the parameter name matches the field name, Rust can automatically create that connection. So here I can simplify this to 'is_hot' and now it's a lot cleaner. That is why whenever you have functions that are going to be creating instances of structs, it's very common to name your parameters the exact same way as your fields. #1) because it simplifies the syntax, but #2) because why would you give them different names? Now you're giving two different names for the same concept. It's a lot easier if you just refer to it with the same terminology in your parameters and in your field. So this is an example with parameters, but the same rules apply to variables. So for example, here in the body of my main function, let's declare three variables: 'name', 'price' and 'is_ hot'. So here I can do 'name' and do a `String::from("Latte")`. This will overshadow this variable right here. But that's not a problem. Then I can declare a 'price' variable set to 3.99 and an 'is_hot' variable set to false. Then down below I can declare a 'latte' variable and create a 'Coffee' instance in line. Once again, I'm going to provide just my fields without any colon syntax, and it's going to be 'name', 'price' and 'is_hot'. And once again this syntax is going to be valid. Rust is going to look for some name in the scope that matches your field. So for example, for 'price', Rust is going to see that there is a 'price' variable and associate 3.99 as the value for the 'price' field. This just goes to show you that the value can come from a variable, or it can come from a parameter. It just needs to be some name in the program that matches the field name, so that Rust can make the association between the two. And that offers us a nice syntactical shortcut that reduces the total amount of code that we write.

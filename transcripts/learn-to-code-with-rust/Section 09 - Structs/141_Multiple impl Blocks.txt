# Multiple impl Blocks

In the previous lessons, we defined our methods and our associated function within a single implementation block. This block belonging to this 'impl' keyword. As it turns out, a struct can define multiple implementation blocks. If we do so, Rust will merge or combine all of the blocks' contents into a single type definition. There is no inherent advantage right now to a multi-block syntax, but it will prove helpful for later concepts in the course. In fact, certain concepts in Rust will require multiple implementation blocks from a technical perspective. So in this lesson I just want to show you the syntax and the validity of it. So what we can do is split up our existing code. I'm going to move our constructor function into a new implementation block and keep all of our methods in this one. The syntax looks the exact same. We're going to use the 'impl' keyword to implement some kind of functionality for something. That functionality can be methods, can be associated functions, etc.. What we want to implement functionality for is our 'TaylorSwiftSong' struct. Then, our curly braces. The exact same syntax as below. And I'm just going to cut and paste this constructor function into here. And this is just an arbitrary decision. I can choose to move this method into here as well. The split doesn't matter. The key takeaway is now we have two separate implementation blocks and we can have as many as we want. Once again, Rust will see that the implementation blocks target the same type. And it's going to merge all of this content together as if it were one. So here I can show you we are using our associated function which is defined in our first implementation block. And here we're using our method which is defined in our second implementation block. And the code continues to run as expected. In other words, nothing has changed. Nothing has broken. But that is the point. Nothing has broken despite the fact that we have multiple blocks for the same type. This is totally valid syntax in Rust. And furthermore, as I mentioned, it will be required for understanding later concepts that we'll explore a little bit later in the course.

# Create a Struct Instance

In the previous lesson, we defined a 'Coffee' struct type. What we see here is a blueprint without an actual concrete value. When we create a concrete value from a struct, we call that an instance. The instance is the realized value, and we can create as many instances of the type as we want. So let's create a sample 'Coffee' value, a sample 'Coffee' instance. I'll begin by defining a variable. I'm going to call it 'mocha'. And on the right hand side of the equal sign, I'll write my struct name: 'Coffee'. Then provide a pair of curly braces, just like in the definition above. In order to create a 'Coffee' instance, we must provide all three fields and the correct data values for each field. So if we do not provide enough fields or too many fields, or there's a mismatch in field types between what the definition said and what we provide, then the compiler will not compile. We can provide these fields in whatever order we want. That is the benefit of a struct. Order is irrelevant. The pieces of data are connected to names, right? 'price', 'name', 'is_hot'. Our field names. There's no concept of order. Order does not matter. So we can define these fields however we want. So I'm going to start with 'name' here. And the syntax is the same as above. We'll provide a colon but on the right hand side instead of a type we provide a concrete value. So we need a String here. So I'll do 'String::from' and let's call this coffee. A "Mocha" coffee. Then I'll provide a comma to separate my fields, a line break for readability and then provide the next field. So our price of this sample coffee can be 4.99. These are all arbitrary values. And then finally for 'is_hot', I can give a Boolean of true. Provide my semicolon. And there you have it. We have a valid 'Coffee' instance made from the 'Coffee' struct type. Once again, if there's any mismatch in types, for example, if I provide 5 here, we're going to see "mismatched types". Rust expected a 'bool'. And what it uses as the source of truth is this definition. This is what a 'Coffee' in our program must live up to. It must have these three fields, and must have these three types for these fields. If there's any violation, the program does not compile. Similarly, if I omit a field, if I try to create a 'Coffee' without a price, we're also going to get a program that does not compile: "missing structure fields: price" right? Missing 'price' field. in the initializer of 'Coffee'. We are trying to initialize a 'coffee' instance; we're missing 'price'. All right, so Rust is holding us responsible for living up to the standard defined by the type. All right. So that is how you create an instance of a struct.

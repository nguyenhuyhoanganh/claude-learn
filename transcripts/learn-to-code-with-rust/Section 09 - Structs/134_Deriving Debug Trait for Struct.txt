# Deriving Debug Trait for Struct

Earlier in the course, we introduced traits. A trait is a contract that mandates that a type support one or more methods. A trait is like a promise that the type makes, that it will support certain functionality, and any type can choose to opt in to implementing whatever traits it wants. We introduced two traits that deal with converting a type into a string representation, and they were the Display trait and the Debug trait. When a type implements the Display trait, it promises that it can produce itself as a more human friendly, readable string. When a type implements the comparable Debug trait, it promises that it can represent itself as a more technical string that is helpful for developers. So there are types that implement the Display trait but not Debug, and vice versa. There are types that implement both traits and neither of those two. For example, here on the screen, I've defined a 'values' array with two string slices. An array does not implement the Display trait, and whenever we use the curly braces inside a string to interpolate, we are relying on the Display trait implementation, on the Display trait string for that type. An array does not implement the Display trait, so we're not going to be able to have this code compile. It's going to tell us this type. An array of string slices does not implement the Display trait. However, an array does implement the Debug trait. So if I comment out that line and execute the code below, we're going to see both the Debug representation as well as the pretty-printed Debug representation, which is the exact same, but just aesthetically a little bit more pleasing. All right. And that as a reminder, is the colon ( : ) syntax. That is the format specifier followed by the question mark ( ? ) for the Debug trait representation. And then for the pretty-printed version, you add the hashtag ( # ) in front of the question mark ( ? ). Now, what about structs? Well, by default, a struct that we define does not implement either the Display tray or the Debug trait. So if I try replacing this code with my 'mocha' struct from above, you're going to see all three of these lines are going to lead to compiler violations. So the struct does not support any of those traits. Luckily, Rust offers us an easy way to derive a Debug trait representation for any one of our structs. The word 'derive' means to infer or deduce to figure out. In other words, what we can do is add an attribute above our struct definition that will ask Rust to create a default Debug implementation, and that default string representation is just going to include the struct name, as well as all of its fields and their corresponding values. It's a reasonable default that the Rust team chose for the standard, if you will, or fallback Debug trait implementation for any given struct. We can define our own Debug implementation and we'll talk about that later in the course. But this is just a reasonable standard because it just requires one line and is super easy to add. All right.

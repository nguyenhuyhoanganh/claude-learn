# Unit-Like Structs

Next up, let's talk about the third type of struct available in Rust, which is a unit-like struct. As a reminder, a unit is a tuple that holds no values. We declare it with an empty pair of parentheses. In fact, this is both the value and the type. If I assign this unit tuple to a variable like 'empty', we can see both the type and the actual value look the same. It's a tuple that has nothing within it. Well, we can similarly define a struct that holds no fields, and those are called unit-like structs. Now a struct without any fields, without any data initially may sound pointless, but we are still able to define methods on these structs and sometimes they can be advantageous in certain design patterns. I don't want to obsess too much over it. I think it's pretty rare to run into unit like structs, but they do have their use cases. And I want to introduce you to the syntax in case you run into them. I just want to make sure you don't get confused. So here's what a unit-like struct looks like. We use the 'struct' keyword. Then we provide a name. I'm going to call this 'Empty'. And then simply a semicolon. So we don't provide any fields. We don't provide any values like in a tuple struct. It literally is just this. This is a unit-like struct, a struct without any data. All right. And then when we instantiate it ...for example, here is my variable called 'my_empty_struct', I literally just write the struct name like so. 'Empty'. So there is no pair of curly braces like for a named field struct. There is no pair of parentheses like for a tuple struct. It literally is just this. And this is a valid instance of a unit-like struct. All right. There are again some scenarios where Rust developers use this for now. Don't worry too much about it, but realize you can see code declared like this and you are welcome to in an 'impl' block still define functionality and behavior through methods on this type, even though again, it technically has no data to work with.

# Define a Struct

Welcome to the next section of the course, which is entitled structs. A struct, which is short for the word structure, is a container for related pieces of data. If you've worked with object-oriented programming languages before, a struct is comparable to an object. We use structs to represent complex data types that can store multiple pieces of information. Now, earlier in the course, we introduced tuples. We introduced them as data structures that can store multiple values in order, including data of different types. Both the advantage and the disadvantage of tuples is that the elements are stored in order. Many times, we don't care about the order, but rather about collecting multiple pieces of data together in a single type. So say we're trying to model a coffee, and in our program, a coffee should have a name, a price and the idea of being served hot or cold. So the coffee's name could be stored as a string. The coffee's price could be stored as a float, and whether the coffee is hot can be stored as a Boolean. So I can collect these three pieces of information in a tuple like you see on the screen, but it's not quite a perfect solution. The first problem is that these values provide no context on what they represent. If this was your first day on the job, and I did not give you the explanation that I just gave you, would you know what true here represents or what 5.99 represents? There's no context. The second issue is that the order of these values in the tuple is arbitrary. It doesn't really matter whether the coffee's price is stored at index 1 or index 2. We can move any of these tuple values around and still retain the same idea of what a coffee is. So what we really care about is storing these three pieces of data together. We don't necessarily need order. We just need them contained together in a single type. And a struct offers a much better way to model a concept like this. Rust actually has three kinds of structs: named field, tuple-like, and unit-like. Most of the time you'll be working with named field structs, so that's what we'll explore first. So a struct can store multiple pieces of data of different types, and each piece of data has an associated name. Each piece of data is called a field or a member of the struct, and the field has a corresponding value. You can think of a field as a variable living inside the struct. It's a name for a corresponding value. The order of these fields is irrelevant because we reference struct fields not by any order, but by their names. So instead of this tuple here, let's define a 'Coffee' struct. It's important to note that what we are about to define is a blueprint similar to a class in an object- oriented language. That means we are defining a template or a schematic for what a 'Coffee' struct looks like. We will not have a concrete 'Coffee' value in our program yet, just the 'Coffee' type. So as a quick reminder, we can say that an i32 can be described as the type, while the number 5 can be described as a concrete value of the i32 type. So what we're about to define is the 'Coffee' type, just like an i32. It's a blueprint for an eventual real piece of data, but we're not going to have the concrete realization of that piece of data just yet. So I'm going to begin with a new keyword here, which is 'struct'. Then I'll follow it up with a space and the struct name, which will be 'Coffee'. For the struct name, we use 'PascalCase'. PascalCase means we capitalize the first letter of every word. For example, if I wanted to call my struct 'CoffeeDrink', I would write it like this. Capitalizing the 'C' and the 'D', the first letter of every word. For now, let's just stick with 'Coffee' and after my name I'll do a space and then provide a pair of curly braces. It's entirely up to us to define what we want a 'Coffee' to consist of. A 'Coffee' can hold one piece of information, or 5 or 500. We need to tell Rust what the pieces of information are, as well as their corresponding data types. Rust doesn't care or know about what a coffee is, so we're going to define it however we'd like. A coffee can vary from one program to another. It depends on what data we need to store. So for our 'Coffee', we need three pieces of information: name, price and whether or not the coffee is hot. So I'll add a line break and I'm going to define my struct fields. Again a field is a piece of information that will live within the struct. The struct in fact will be the owner of the field, and the field is going to be the owner of its value. We're going to talk more about that a little bit later. So let's write the fields out for each field. We're going to write its name, a colon, and then its type. For example, I'll begin with 'price'. 'price' is the name of a field or a member that I want to live within my struct. Then I'll add a colon and then a space for readability. And then I'll provide my type. In this case it'll be a float 64 ( f64 ). Notice once again that I'm not providing a concrete value like 5.99. I'm just providing the data type of the field. So after thi,s I'll add a comma to separate my fields and then a line break. For readability, we need to separate every two fields with a comma. It's similar to how we use a comma in a tuple, or in a function argument list to distinguish between multiple values. So we'll declare our next field on the next line. Let's do 'name'. Once again colon. And then the type after a space will be 'String'. Then I'll add one more comma to separate this from our next field, which will be 'is_hot' and 'is_hot' is going to be a Boolean and that type is just 'bool' -- "b o o l". Notice that for 'is_hot', I've used snake_case formatting. snake_case means that we place an underscore between every two subsequent words. So that means an underscore between 'is' and 'hot', right? The struct name is PascalCase. That's the community convention, but the field names use snake_case which means underscores. All right. You'll notice that when I save, the formatter will add a comma after the last field. And that's totally valid. So that's all there is to it. We've declared a 'Coffee' struct. Another way that we can describe it is we've added a new type to Rust called 'Coffee'. You can think of 'Coffee' as no different than an i32 or a String or a Boolean. It's now a new type that Rust can work with within the main function. So to reiterate, this 'Coffee' struct right here represents a blueprint. It is a definition for an eventual type. It is not a concrete value yet. It is just a type from which we can create a concrete value. And we'll see how to do that in the very next lesson.

# The Display Trait

In this lesson, we'll get a quick introduction to traits in Rust, starting with the isplay trait. Now, traits are a complicated topic that we'll cover in greater depth later on in the course. Right now, I just want to give you a basic gist of what they are at a very high level. So let's first begin by talking about contracts in the real world. I'm talking about things like legal contracts. A contract is a document that people sign that states their obligations, what they promise to honor or uphold. Now, I'd like you to imagine a non-specific contract with the following requirement. "You promise to arrive at 9 a.m. at a location". That is a general, high level, non-specific contract that many different types of situations can honor. For example, a college student can promise to arrive at class at 9 a.m. a software engineer, can promise to arrive at work at 9 a.m. a flight can promise to arrive at an airport at 9 a.m.. A package can promise to arrive at a house at 9 a.m.. These situations here are different, but they are all honoring the same promise. They are all upholding that same contract. It's a very similar idea to traits in Rust. A trait is like a contract in Rust that requires that a type supports one or more methods. When I use the word supports, I mean that that type must have those methods literally available. So for example, a trait might say: "You need to define a method called read and a method called writ"e. And a type can say: "Okay, I'm going to honor this trait, this contract's requirements and indeed support a method called read and a method called write". The advantage of traits is that they establish consistency between different types. So methods that represent the same fundamental behavior can have the same name across different types. When a type opts into honoring a trait's requirements, in other words, when it says: "I'm going to live up to the promise of having these required methods", when it honors the traits requirements, we say the type "implements" the trait. That is the technical jargon. Now, the beautiful part is that the types themselves can vary in their implementation logic. The definition of a 'read' method or a 'write' method can vary between multiple different types, but they're still implementing the same trait. They are still honoring the exact same contract, much like the college student and the package from the previous slide. So a type is not obligated to implement any trait. It's its choice to opt in to implementing a trait. The developer who is defining a data type gets to choose what traits it implements, which also means which behaviors it promises to support. A type can choose to implement one trait but not another. A type can choose to implement multiple traits. There are hundreds of different traits available in Rust, and every type that we've encountered so far has implemented some traits, but not others. In other programming languages, traits are sometimes called interfaces or protocols. It's a very similar idea, just different terminology across different languages. So let's introduce you to a sample trait that is built into the Rust language and it is called Display. The Display trait from a behavior perspective requires that a type can be represented as a user-friendly, readable string. In other words, that it is displayable. That's where the name display comes from. Now, from a more technical perspective, the Display trait mandates or requires the existence of a 'format' method on a given type that returns that string representation of that type. Now, here's a little surprise. We've actually been using this trait indirectly throughout the entire course. Any time we use the curly brace interpolation syntax ( { } ) in a string, we're actually relying on that 'format' method. Behind the scenes, when the Rust compiler sees those curly braces, it invokes a method called 'format' on the type, and that 'format' method tells Rust how to display that type as a string. And the way that Rust knows that a type implements the 'format' method is because it knows that a type has chosen to implement the Display trait. So, for example, integers, floats, and booleans all implement the Display trait, so we are able to interpolate them within those curly braces. And Russ knows these different types all implement the same 'format' method which it can call, and thus get the string representation of that type to embed or interpolate within the string. So now the consistent method called 'format' is enforced by all of these different types, choosing to implement the same Display trait. Now here's the bad news. Not all types implement Display, because for many complex types, it's not always clear how a complex type should be represented as a piece of text. With a number, it's pretty simple. If the number is 5, it makes sense that the string or text-based representation of that should probably be a string with the number 5. Same thing with a boolean. Same thing with a float. But as we get into more complex types in Rust that, for example, may involve lots of dimensions or lots of layers or many different pieces of data. It's not as easy to figure out the right way, so to speak, to model that data type from the computer's perspective into a human readable string. So for that reason, not all types implement the Display trait. One example is the array type from the previous lesson. Any common person out there would understand the number 5, right? But an array is a technical data type that only programmers are familiar with. So just because it might make sense to us to see it in the text editor as a pair of square brackets and a bunch of comma-separated elements, that doesn't mean that that is a reasonable, human friendly string representation of that data type as a piece of text to the user who is going to be using our program. So for that reason, the Rust development team did not implement the Display trait for the array. So as we'll come to see in VSCode in just a moment, if we try to interpolate an array into our string, it's actually not going to work precisely because it does not implement the Display trait. So let's take a look at that now in our text editor. So here we are back in VSCode. As you can see on lines 4 through 6, we are using the curly brace interpolation syntax to output these values. These are all different types and i32, a f64, and a bool. But because they all implement the Display trait, they all support a 'format' method which Rust is invoking behind the scenes every time we use the curly braces. The 'format' method is giving Rust that string representation of the given data type or the value. And that's exactly what's being printed. Let's take a look at what happens if we try to use the exact same syntax with our 'seasons' array. An array does not implement the Display trait. So we're going to get a compiler error. Notice here it says this type. "This array of a 4-element array of strings does not implement Display". You can ignore this little prefix right here. That's just a qualifier. Here is the core trait name of display. Display is not implemented for the array type. Therefore, there's no way for it to be represented as a human readable string and the program will not compile. The compiler error here will give us the exact same message. Display is not implemented. All right. So not all types are going to implement the Display trait or any other trait for that matter. Now, how are we going to print out the value of the 'seasons' array? Well, as it turns out, there is a complementary trait called Debug that we're going to introduce in the next lesson that does just that. And Debug will operate the exact same way as the Display trait. The most important thing to understand at this point is that a trait is just like a contract in the real world. It's a requirement that a type implement one or more methods. That's the technical definition. But on a more broader level, it's a requirement that a type can support a given behavior, that it supports a given action. Right. In this case, the Display trait requires that a type be displayable and the trait definition is just the contract. Then, any given type can opt in to implementing one or more traits, which means it promises that it can support that behavior. In this case, the number five or the type i32, by implementing the Display trait, promises that it is displayable as a human readable string. An array does not implement the same trait, so it does not make that promise, and thus we cannot directly use this syntax. Once again, we're going to see how we can solve this problem in the very next lesson.

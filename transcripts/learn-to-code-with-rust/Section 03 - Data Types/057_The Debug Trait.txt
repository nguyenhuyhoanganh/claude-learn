# The Debug Trait

Now that we have a better understanding of traits, let's introduce another trait called Debug. The Rust documentation states that the goal of Debug is to format a given type into a programmer-facing string for the purposes of debugging, so the two traits are very similar. While Display is intended for common values that we likely want to show or display to the end user, the Debug trait is intended more for developers, for Rust programmers to be able to print out a value as a string to figure out what's going on in their program. It's a little bit of nuance, but the two are very similar. So consider a type like our array. This is a type that programmers use every day, but something that your everyday person probably doesn't understand, right? A person who's going to be running your compiled executable knows what a number is, but they probably won't know what an array is. So the Rust team thus chose not to implement the Display trait for arrays. We saw that with 'seasons' in the last lesson. However, array types do implement the Debug trait, and that will allow us to output a string version of the array to the screen. The Debug trait behind the scenes actually similarly mandates its own 'format' method that represents the type's data as a string, but it is a different 'format' method, and different types opt into implementing either Display or Debug or both or neither. So once again, Display is meant for the user, while Debug is meant for the programmer. So let's explore it here.

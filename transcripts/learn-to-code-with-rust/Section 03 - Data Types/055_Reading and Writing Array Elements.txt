As we learned in the previous lesson, Rust assigns each element within an array a position in line. Now, as you may recall from way back in the course when we talked about positional arguments to the println! macro, we mentioned that programming languages start counting from 0. Human beings usually start counting from 1. Programming languages usually start counting from 0. So here I have a four element array of string slices representing the four seasons. This array has a length of 4. Now the technical term we use to refer to each element's order in line is called the index position, and it starts counting from 0. For example, the first element here of "Spring" has an index position of 0. The second element of "Summer" has index position one. The third element of "Fall" has index position two. And finally the fourth element of "Winter" has index position three. So you'll notice the final index position within the array is always going to be one less than the length. And the reason for that is because the length starts counting from one while the index starts counting from 0. Right. So if we were counting the length or the number of elements within this array, it would be one, two, three, four. When it comes to the index, that reflects the order that each element has been assigned in line, and there will be no duplicate index positions. Each element is given its own unique order in line.

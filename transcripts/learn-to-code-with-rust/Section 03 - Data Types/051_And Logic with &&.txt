# And Logic with &&

In the real world, there are situations where multiple independent conditions must be met in order for something to be able to happen. In complementary programmer terms, we often want to combine two or more Booleans representing two independent conditions to arrive at a final computed Boolean. For example, let's say that I'm trying to catch a flight to a city and I want to make a certain event on time. And there are two separate requirements that must be met in order for me to arrive on time. The first one is that I need to have purchased my plane ticket, and the second one is that my plane must be running on time. These are independent conditions, independent criteria, and I can model both of them as separate Booleans. For example, I'll declare my first variable of purchased_ticket and let's set that to true. So I've purchased my plane ticket and then let's declare another variable called plane_on_time. And let's set that to true. And finally let's declare a third variable called making_event, and I want this to be dependent on the two Booleans above. If I have both purchased my ticket and my plane is on time, then I will be making my event. So to apply that logic, we're going to use an operator called the and operator. And that operator is two ampersand symbols in a row ( && ). That is Shift + 7 on your keyboard. We surround both sides of this operator with a Boolean. So on the left hand side, I'm going to add my first Boolean represented by 'purchased_ticket'. And on the right hand side, I'll add my other Boolean which is plane_on_time. So this performs AND logic. So what this means is the value on the left must be true and the value on the right must be true. And if that is the case, this operator (&&) will evaluate to a true as well. For example, here I can output some text like: "It is {} that I will arrive as expected". And I'm going to interpolate the value of my making_event variable. And you can see it is true that I will arrive as expected. This AND operator (&&) evaluated to true because this and this were both true. Now, if either one of these Booleans is false, or if both of them are false, then the final evaluation of the AND operator will be false as well, right? Because it is AND logic. Condition A must be met and condition B must be met. So for example, if I have not purchased my ticket and my plane is on time, I am not going to be making my event. So this is going to evaluate to false. Similarly, if I have purchased my plane ticket but my plane is not on time, then I am not making the event. So, in this case, this boolean is false. So the final evaluation of the AND operator will be false as well. And finally, if I have neither purchased my ticket nor my plane is not on time, then once again making_event will evaluate to false. So this AND operator is only going to give you a true if this is true and this is true. Behind the scenes, Rust is also using a feature called short circuit evaluation. What that means is Rust is first going to look at this Boolean. And if the first condition is false, Rust will actually not even worry about evaluating the second. And that is because logically if this one is false, there is no way the complete AND expression can evaluate to a true. Because if this one is false, it doesn't matter whether the second one is true or false. The entire evaluation must be a false. So Rust effectively short circuits, which means it stops evaluating early. If it sees a false followed by a AND operator, it just evaluates to a false automatically. And we don't have to worry about that day to day. But it just goes to show all of these micro-optimizations that are built into the language to help speed things up ever so slightly behind the scenes. So that is an introduction to the AND operator.

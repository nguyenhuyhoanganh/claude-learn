# The Array Type

Earlier in this section, we introduced the idea of scalar types versus compound types. A scalar type holds a single value. Integers, floats, Booleans, characters. They're all examples of scalar types. If we have a variable with one of these types, it will contain one value. In comparison, a compound type is a type that is a collection of one or more values. The word compound literally means "made up of multiple existing parts", so a compound type is capable of holding multiple values within it. The first example of a compound type that we'll introduce is the array. An array is a fixed size collection of homogeneous data. The word homogeneous means the data is of the same type. So an array will store either all integers or all floats or all booleans. The data must be the same. An array stores a sequence of those values in order, so you can think of an array like a box that contains multiple items within it, and it also assigns each one of those items a position in line,a numeric order. The technical term that we use to describe the values within an array is elements. So we can say something like. This array consists of five elements. An array is a fixed-size data type, which means the array is always going to stay the same size throughout the program. It's not going to grow in size or shrink in size. It will always contain the same number of elements. So let's take a look at the syntax. I'll begin by declaring a variable called numbers. And on the right hand side we'll declare an array using a pair of square brackets. I actually like this syntax a lot because it reminds me of a literal box, right? It's an opening bracket, square bracket. Inside, we're going to write our sequential elements, which can be of any type as long as it is a consistent type. And I'm going to separate every two elements with a comma and a space. The comma is a technical requirement while the space is just for readability. So I'm going to populate this array with 6 numeric elements. So I'll start with 4, then a comma and a space. And then my next value in line. So I'll do 8, I'll do 15, I'll do 16, I'll do 23, and 42. So it's important to note that this is a container for 6 elements in order. So the order that we declared these from left to right is the way that Rust is keeping track of them sequentially, positionally in order. 4 is first, then 8, then 15, then 16, and so on. You'll notice the type inference right here is a little bit interesting and a little bit different. We have the pair of square brackets which is indicative of this array type. And then there's actually two values inside here separated by a semicolon. As you might guess, the first one here reflects the type of the elements themselves. What kind of data is this array holding? It is storing i32s, 32 bit integers. The second value after the semicolon is what's called the length of the array, which is how many elements are within it. This is an array with 6 32-bit integers within it. As always, we are welcome to annotate this type explicitly. We do not have to do so, but let's practice. So once again colon and a space. Then a pair of square brackets. This is not us declaring the array. This is us declaring the type. First up is going to be the type of the elements within the array, which in this case is an i32. But I could also write this as an i8, for example. And then I'm going to provide a semicolon and a space for readability. And then the length of the array: how many elements, how many integers. And I'll provide 6. And that should do it. Now this is a distinct type in and of itself. So, for example, if I say I'm going to have 6 elements and I remove one right here, this is no longer valid because we now have an array with a length of five. "Found an array with 5 elements". "Expected an array with a fixed size of 6". Remember an array is a fixed size type. That means Rust needs to know its size, exactly how many elements it's going to contain, which is also called its length. Now, because Rust knows the size of the array at compile time, as well as the data that it's going to store, that enables the array to be stored on the stack at runtime. There is no unpredictable data here. We know exactly what the array is going to contain. So if I promise an array with 6 integers, I need to bring back my sixth integer. And there we have it. Here's one more example of an array. I can declare an array called apples, and let's populate this one with strings or string slices or string literals. You can use whatever term you want. You'll notice before I provide any data, the inference will say unknown because it doesn't know what the type is of the elements within the array until I give it a sample element, right? So here I can do a apple flavor like Granny Smith. This array will hold strings for various apple types. I'll do a McIntosh and I'll do a Red Delicious. So this array and its type is going to be an array of three string slices. All right. Now, as always, these types including these compound types are going to have methods in Rust. And one example of a method that I can show you immediately is called 'length'. And as you might guess, this method will return the length of the array, which is a count of its elements. So I can take 'apples' right here. And the length method is abbreviated 'l e n', but the syntax is the same. So a dot the method name and parentheses to invoke. And this will tell us that the length of the apples array is 3. All right. Another important thing to note is that the compiler will prohibit any array declaration if it is empty, and it does not have a declared type. And that's because Rust is not going to know the size of the array or what it's going to contain, and thus it will complain and not compile. So, for example, if I declare an array called currency_rates and I set it equal to an empty array, and I do not provide a manual type, Rust has no clue what this array should contain. Is it going to contain floats or Booleans or strings? It doesn't know. And it needs to know that for the sake of figuring out the memory requirements at compile time. So this code will not work. You'll notice if I save, it's going to say: "Type annotations needed here". "Type must be known at this point". The reason we did not need type annotations in this example and the first one, even though we provided it here, is because once we give an element into the array, once it actually stores something, Rust can infer or deduce the elements being stored, but it cannot figure it out with an empty array. And thus we're going to have a compiler error. Right. So the way we fix this is, if we know what our array is going to store, we obviously populate a value. Like if we know this is going to be a float array, that should do it. And if we want an empty array for some reason, we do need to provide the type here. So once again: colon, square brackets. Let's say hypothetically this array is going to store floats. So I'll provide an f64 to represent 64-bit floats, then a semicolon. and then the number of elements which in this case is literally 0. An array can be a compound type that stores nothing at all. Right. You can have a box in the real world that happens to be empty. It's the same idea. That box just has the capacity to store multiple values if needed. But you can see, in this final example, the code will now compile just fine. All right. So that is a quick introduction to an array. An array is a compound data type. It is a fixed size collection of homogeneous data in order.

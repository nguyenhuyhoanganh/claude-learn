# Floating Point Types

So next up, let's talk about Rust's floating point types. A floating-point type or a float represents a decimal number, a number with a fractional component. Rust has two floating point types, a 32 bit float and a 64 bit float, and those two types are equivalent to the float and double type from many other languages like C and Java. Floating points are signed. That means the same single type supports both positive and negative values. There is no unsigned float type like there is for integers. So let's begin by declaring a variable called 'pi', and I will set it equal to the value of pi, which is 3.14159. So by default, as soon as I add that dot for the decimal point, Rust will infer this to be a floating point number, more specifically, a float 64. This is a float 64, so it occupies 64 bits or 8 bytes of memory. And this is a reasonable default float type. Unless you're working with an application where memory is severely constrained. I would use a 32 bit float a f32 only if you absolutely want to reduce memory. The float 64. The 64-bit version should be just fine most of the time, which is why the Rust team made it the default inferred type. The 64 bit float 64. type, f64, provides about 15 to 17 digits of precision. That refers to the accuracy in the number of digits after the decimal point after the period. In comparison, the 32 bit float 32 type, the f32, only provides about 6 to 7 digits of precision, and that's because it has less memory to work with. It's important to note that there can be rounding errors in representing decimal values, even with larger floating point types like float 64s. And this is a computer architecture problem, not anything specific to the Rust language. Floating point numbers use a finite number of bits in memory to store the digits, and thus they can eventually run out of bits to store all of the details of the numbers. So let me show you that in action. Let's expand our pi variable to hold a lot more digits. So here to the very end, I'll keep adding on to pi. I'll add 26535897932384. So there's a lot more than 15 digits here. And if I print line and say something like "The current value of pi is" and then I'll interpolate pi, you can see that Rust is going to start rounding 793. So right around here is where we start losing the precision. And you can see those last couple digits, 2384, are not being represented here. If I change the type by annotating this to be a 32 bit float, a f32, then I'm going to get even less precision. So notice here I only get about 7 or so digits. So once again it's all about tradeoffs. We use less memory for a 32 bit float, for a f32, but we lose precision. We lose accuracy. Floating point values support methods just like other types, but we must explicitly provide the variable's type to actually get those float methods to work. Once again, I'll provide my dynamic content in curly braces, and one sample method we have is floor, which rounds the float down to the closest whole number. So the syntax is the same as any other method. We'll provide our value of pi, then a dot, and then our method name which is 'floor'. And then we invoke it with a pair of parentheses and it accepts no arguments. So floor you can think of that as going down right. The floor is below you. It's going to round to the closest whole number. Round down that is. So that becomes 3. This 3, this return value, is still technically a float 64 value. It's just being displayed without the decimal component. So there is a complementary method to floor called ceiling. And that is going to be abbreviated 'ceil'. You can think of the floor as being below you and the ceiling as being above you. So the ceiling method rounds up to the next whole number. So for us that's going to be 4. Rounding down from 3.14 gets us to three. Rounding up from 3.14 to the ceiling is going to give us 4. And finally one more example. There is a round method that rounds to the closest integer. In this case 3.14 is closer to 3 than it is to 4. So we're going to round down. But if we add a value above 3.5, that would round up to 4. So these are just three sample methods on a float. It's not important to memorize all of these methods. It's more important to understand what they accomplish. Methods are functions that live on a value. There are behaviors that we can ask an integer to do for us, functionalities that we can ask an integer, or a string, or a float to perform. And the syntax is the exact same. We just provide the value or the variable that refers to it, then a dot, then the method name with a pair of parentheses, and then any arguments if the method accepts them.

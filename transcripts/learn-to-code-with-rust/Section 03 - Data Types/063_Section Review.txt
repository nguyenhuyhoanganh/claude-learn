A trait is a contract that requires that a type supports one or more methods. Another way to think about it is a trait enforces that a type supports some kind of behavior, that it is capable of performing something or doing something for us. The advantage of traits is that they establish consistency between different types. Our types can represent totally different things or ideas, but they may support a shared interface in the sense that we can have a common method that can exist on both of them that has some amount of predictability and that is the advantage. For example, there may be multiple types that are capable of being copied. Well, it would be terrible if the method to create a copy of a value was different across 5 different types. Maybe on one it would be called "copy", on another it might be called "create_a_copy", on another it might be "clone" or "duplicate". That creates inconsistency which makes our types feel further apart. Now with traits, we can enforce some amount of consistency because the type is ultimately responsible for the implementation, but it is living up to some basic, consistent standard. That contract called the trait. So every type can choose to opt in to implementing a trait and thus supporting its required methods. A type can implement multiple traits or opt out of implementing any trait at all. A trait can also be implemented by multiple types. That is the whole point and advantage. So we explored two traits that are built into Rust, which are Debug and Display. And both of these deal with converting a value into an appropriate string representation of that value. So the Display trait mandates that a type can represent itself as a user-friendly, user-facing string. So for example, if we have an integer like 13, the Display trait is implemented by the i32 type. So not all types are going to implement the Display trait. For example, an array and a tuple do not implement Display, but they do implement Debug. The Debug trait is very similar and mandates that a type can represent itself as a string, but this string is more like a developer-friendly string that exists for the benefit of debugging. A range is a type that represents a sequence or an interval of consecutive values values in a row or in order.

# The dbg! Macro

In this lesson, we'll learn another macro and this one is called dbg!, which is short for debug. We've seen one macro before and that is println! which we have above. Like all macros in rust, the dbg! macro ends with an exclamation point ( ! ). That is your visual indicator that it is a macro. Behind the scenes, Rust replaces the macro code during compilation with valid function calls. So technically speaking, a macro is not exactly a function, but it looks and works just like a function, so we can effectively treat the two as one and the same. The Rust documentation states that the dbg! macro exists to print and return the value of a given expression for quick and dirty debugging, so this macro exists for the benefit of the developer, not the end user. It's a bit confusing because there is the Debug trait. And then there is the dbg! macro. The Debug trait is just the generic contract, while a macro is an actual helper command. It does something right. It performs some action behind the scenes. What this dbg! macro does is it uses the Debug trait's 'format' method to output several helpful details about the content that we pass in here. So at the end of the day, much like println!, it is going to output some text to the screen, but it's going to provide a lot more helpful details about the line of code that we add in here. So let me show you a quick example. Let's provide a basic mathematical expression like 2 + 2. And then let's run this file. We're going to see the output from dbg! right here. And notice what it includes. It's going to begin with the actual file name. So you know where the dbg! macro was used. And in larger Rust projects that consist of multiple files and folders, this can be helpful. It's also going to show us the line number. In this case: line #9. And then this 5 represents the number of spaces into the line. So basically it's telling you where it located the use of the dbg! macro. Then it's going to print out the exact code that you wrote. In this case: 2 + 2. Then an equal sign and then the resulting value or calculation of the expression. So it's helpful because within your output you can see both what you wrote and then what the result of that code was. The argument that we pass to the dbg! macro must implement the Debug trait so that Rust can print out its technical string representation, which is a part of this complete output. So if you want another option to printing out a value instead of using println!, you can instead use the dbg! macro. Sometimes it's a little bit cleaner. For example, here I can simply provide 'seasons' and once again 'seasons' does not implement the Display trait, but it does implement the Debug trait. So we're going to get the pretty-printed version. Notice once again we get the file, the line number, the actual code we wrote which was 'seasons'. Then always this equal sign, and then the pretty-printed Debug version of our 'seasons' array. So it's sometimes a little bit cleaner because it avoids the need for the curly braces and the format specifier and the question mark or hashtag. So it's a quick way that you can just add a macro to the code. Of course, dbg! is also a lot less characters to write than println! So if you really quickly want to print a value out in Debug format to see what it is, this is great for that. Typically you don't leave any dbg! macros in your final code because it's strictly for development. It's strictly to benefit you, the developer, as you are observing values as they move throughout the program. So typically you use dbg! to output a value, then you delete dbg! once you have a better understanding of what a value is at a given point in your program.

# The usize and isize Types

All of the integer types that we previously introduced use a fixed, consistent amount of memory. For example, an i32 uses 32 bits or 4 bytes of memory regardless of what computer or architecture the code is running on. Now, there are two special integer types in Rust called usize and isize. As you might guess, usize is for unsigned values and isize is for regular signed values. usize and isize are aliases for an existing integer type, so they are not different or unique types. Rather, they are nicknames for another existing Rust type. But what that is will vary depending on the architecture of the operating system that the Rust code is being run on. In other words, it varies depending on what kind of computer is running the program. For example, the usize unsigned integer is equivalent to a u32 on a 32-bit system, but it is also equivalent to a u64 on a 64-bit system. If your computer is 64-bit, then it has more room for memory, so Rust will utilize a u64 any time we write a usize. So, for example, if I write a variable called days, I can write the type as usize and what that will be will vary depending on what computer is running the program. So for example, if I assign this to be something like 55, once again on a 32 bit computer, this will be a u32 and on a 64 bit computer this will be a u64. Same principle applies to the isize type. If I declare this as isize and give it a value like -15,000, this will be an i32 on a 32 bit system or an i64 on a 64 bit system. The advantage there is that we can write one bit of code that is reusable or applicable across different systems, while doing its best to minimize the memory consumption on each respective system. So hopefully that makes sense. These are not different types. They are nicknames for built in types, but what that type is will vary depending on the computer.

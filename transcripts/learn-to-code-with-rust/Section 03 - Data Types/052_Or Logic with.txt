# Or Logic with ||

In the previous lesson, we introduced the AND operator, which is two ampersands (&&) in a row. The complementary logical operator to that is the OR operator, and it performs either/or logic. It's declared with two vertical pipe symbols ( || ), and those look like this. For me, the key for the vertical pipes is three keys over from the 'P' key on my keyboard. So here is the or operator ( |\ ). Just like with AND, we provide the OR operator with two Boolean operands. So, for example, true or false. And what this operator does is it validates that at least one of the Boolean is true. Both of the Boolean do not need to be true. Only one needs to be true for the entire evaluation to evaluate to a true. It is either/or. Either one can be true or both, but at least one has to be true to get a final true evaluation. So, for example, let's say I am modeling a website where a user pays a price to get access to a premium feature. Maybe they are purchasing a course, or maybe they are buying a subscription. So I can declare a variable here. Let's call it user_has_paid_for_subscription and I'll assign it to an initial value of true. And let's say there's another way that the user can see the premium content on the site. And that is if they are a designated admin. An admin or administrator is a special person who has been given permission to use all of the features of the site. So for example, here I can declare a variable called user_is_admin and set that to true as well. So, some users may be admins who have not paid for a subscription. Some users may have paid for a subscription but are not admins, and some users may be both, but I only care if at least one of these two criteria is met to enable access to this premium feature. So for that I can use the OR operator. For example, here I'll declare my third variable, which is user_can_see_premium_experience, and I'll provide my two Booleans which are represented by the variables above. So user_has_paid_for_subscription. Then my OR operator ( || ). The two vertical pipes. Then, my other Boolean which is user_is_admin. So now at least one has to be true. Either./or. So here I can println! and say something like "Can this user see my site?". And I'll interpolate the value of user_can_see_premium experience. So we start with a situation where we have two trues. Rust only cares about just one being true. So this is sufficient. If I have a user who has paid for a subscription but is not an admin, the OR operator is still going to evaluate to true, because at least one of these two booleans is true. Similarly, if the user has not paid for a subscription but they are an admin, the OR operator will still return true because at least one of these two has been true. So the entire thing is valid, right? Either/or. The AND operator is stricter because it requires two independent conditions to be met. This one mandates that at least one of two independent conditions has been met. So the only way that the OR operator will give you a false is if neither condition is met. So here I'll do two falses. And now we're going to see this user is not going to see my site. All right. So similarly, as with the AND operator, Rust uses short circuit evaluation in this scenario as well. If we get a true here for the very first Boolean on the left hand side, that is enough for the entire OR expression to evaluate to true as well. It doesn't matter if the second Boolean is true or false, if the first one is true by itself. So therefore, if Rust sees a true, it will stop evaluation here and not even bother with the right hand side. If the first Boolean is false, then this OR operation could still result in either final value: true or false. So at that point, Rust will evaluate the right hand side. All right. And in these two lessons we saw examples with just two independent conditions. But it's important to note that we are not just limited to two. So we can combine the AND operator with multiple conditions. We can do, for example, the AND operator or the OR operator with another condition. So this is saying: "either this thing or this thing or this thing". And similarly, if I replace these with the AND operator, this is requiring that three separate, independent conditions be met. So we're just merging all of that logic together to get one final evaluation.

# The Tuple Type

Next up, let's talk about the tuple type. Like an array, tuple is a collection type that can contain multiple elements, each of which is assigned an indexa position reflecting its order in line. The difference between the two data types is that a tuple supports different types for its values. An array is homogeneous, which means all of its elements must be of the same type. A tuple does not have that requirement, so it can store elements of different types. We create a tuple with a pair of parentheses, both opening and closing. Inside the parentheses, we declare our tuple elements separating every two with a comma and a space for readability. For example, let's say that we are trying to model an employee at a company and an employee will have three pieces of data: a name, an age, and a department. So what I'll do here is inside my tuple, I'll declare those respective pieces of data separated by commas. So for my employee, I'll pick a name of "Molly" declared as a string, and then to separate it from my second element, which is still inside the tuple, I'll add my comma right here, then a space for readability. Let's say Molly is 32 years old, and then I'll add one more comma and a space. And let's say she works in the Department of Marketing. So this is my three element tuple. I'm going to assign this to a variable called employee. And as you can see, Rust will infer the type of employee to be a tuple. You can see the parentheses here. But then it's also going to infer the types of these specific elements based on their positions. We first have a string followed by an integer, followed by another string. I know so far we also have not talked about what this special syntax is in front of the str, the ampersand ( & ). Let's not worry too much about that right now. I promise we're going to dive into it in much greater detail later on in the course. But the key takeaway here is our tuple can support elements of different types. If I wanted to add a boolean here and a float after that, that's totally fine. You can see the inference is adjusting to account for those new elements that are totally of different types. All right. So just like with arrays, Rust assigns each tuple element an index position starting from 0. So Molly, the very first element, has index 0. 32, the second element, has index 1. And "Marketing", the third and final element, has index 2. In order to be able to access these elements, instead of using square brackets like we do with arrays, we instead use simply a dot. For example, here I'll declare a 'name' variable, and on the right hand side I'll reference my 'employee' tuple. Then, I'll put a dot and then the numeric value of the index whose element I want to extract. So if I want my "Molly" string, I'll provide .0 And that is it. So I can take similarly my 'age' element out. So I'll create an 'age' variable assigned to 'employee.1'. That will target index position 1. And similarly I can extract 'department' and that can be employee.2 And here I can print out all of those values. Name is name, age is age, and department is department. And we'll see right here. There they are extracted from their respective positions in the tuple. The tuple does not implement the Display trait very much like an array, but it does implement the Debug trait. So right here, I can println! and I can similarly write employee. This will not work because this is the Display trait representation, but I can add my format specifier and a question mark. And that will give us the Debug string version, the Debug trait implementation. And you can see that technical string representation looks very similar to our actual code. This is how Rust prints it out for the benefits of debugging. And once again we can apply pretty-printing with hashtag question mark ( # ? ). Very much like with arrays, this will break up the tuple elements one per line, but it's a very similar idea. Now this syntax right here is so common. There's actually a shortcut to accomplish the same result. And I want to show you that next. So I'm going to keep this line right here, I'm going to comment out these three lines. And I'm going to try to accomplish everything we did here but in a single line. So I'll begin with the let keyword, because we're going to be declaring variables, not just one variable but several. And what I'm going to do is provide a pair of parentheses. And in here I'm going to declare a variable name for each one of my tuple elements. Since I have a tuple with three elements, n other words, a tuple with a length of 3, I need 3 variable names in these parentheses, separated by commas. So just like above, I'm going to write name, then a comma and a space, then age, comma and a space, then department. And then I'll provide my equal sign. And then the employee tuple on the right hand side. So we haven't seen this syntax before but it operates as you might expect. It takes the respective elements of the tuple based on their position and assigns them sequentially to the 3 variables we have here. You can even see the inference pop up. 'name' is a string, 'age' is an integer, and so on. Because Rust simply assigns these 3 elements sequentially to their 3 respective variables.

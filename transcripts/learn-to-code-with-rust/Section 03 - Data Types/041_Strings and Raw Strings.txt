# Strings and Raw Strings

So let's kick this lesson off with a quick review of strings. A string is a piece of text. It is a collection of characters in sequence. When we wrote our first code for the course, which was "Hello World", we created a string. We declare a string with a pair of double quotes, and then we write our text content between the double quotes. So this right here is a string. We can pass a string to the println! macro to output that string or that text to the screen. Now, Rust actually has different types of strings. So it's important to note that the strings that we've used so far are technically called string literals. This is an example of a string literal. String literals are strings whose values or whose text the compiler knows at compile time. And that's because we write these strings directly within our source code. Rust knows them in advance. That will sometimes be the case, but it won't always be the case. For example, we may have a program where we ask the user to provide some text input, like their name. In that scenario, we're not going to know the exact string that we'll have to work with until the program runs. And furthermore, in that example, the user's input can vary each time the program runs. That's a more dynamic string that is unpredictable in advance. But any time that we know the actual hardcoded value and we declare it with double quotes in our code, Rust knows the value at compilation time. And for those kinds of strings declared like so, these are called string literals. Within a string, we can include what are called special characters. Special characters will not be interpreted literally. Rather, Rust will understand that those special characters represent something special to render to inject within the string. For example, say I have a string here. I'm going to start with "Dear Emily". And what I'm going to add here is a \n And you'll notice here that the editor shows me a slightly different color here. This is an example of a special character. So this represents a line break. The 'n' is actually short for new line. Or you can think of it as next line. So Rust is not literally going to print out the characters \n. Rather, it understands that this is a special character. It means force a line break. So, for example, if I write: "How have you been?" You'll notice in the output ,when we run the program, here is "Dear Emily". Then the \n will force a line break, and the remainder of the text will pick up on the next line and then println! itself forces a line break at the end of this whole output. And that's why we start the next output from the Terminal afterwards. So this is an example of a special character. Here's another one. Another special character we have is \t which is short for Tab, T for tab. And it forces a tab character just like on your keyboard. So this is a bit of indentation. So for example, if I write "Once upon a time" here and we run this program, you'll notice that text will be indented. Here is our tab from the \t. It's going to push that text to the right. There may come a scenario where you want to include a double quote as a character within your string, but if you use a double quote, Rust will think you are terminating or ending the original string. So for example, here on the next line, I'll once again use my println! macro and say I want to say "Juliet said". And then I want to actually have a quote in the middle of my sentence, so I can begin with something like my quote character right here. But unfortunately, Rust is going to think that this first quote is going to be terminating the string that begins right here. So we need an alternate syntax that tells Rust we're not ending the string. We just literally want to render a double quote. So as you might have guessed from these special characters here, these special characters are going to start with a backslash. And in this situation, if we do \", that escapes the character, which basically means it tells Rust: "Don't treat this double quote as the end of the string. Treat it like a regular character". So now, Rust will literally render a double quote within our text so I can say something like "I love you, Romeo". If I try to place another quote here to end my quote, once again we run into an error. So once again, I'll provide a backslash to escape this quote. Escape basically means have it avoid doing its regular Rust behavior. We escape the default, escape the standard. So now Rust understands that these are quotes to be printed. And now we're going to see the actual double quotes directly in our output. So one more example to show you and that is backslashes. We have to escape backslashes in a string with their own backslash symbol, and that is to avoid conflicts with Rust's special characters. All right, so say that I'm trying to model a file path on a Windows computer. On Windows, the directories are separated with a backslash symbol. For example, say I have a folder on my computer that is "My Documents\new\videos". So it's a hierarchy that is three directories deep. So say I have a variable like file_path. I'm trying to open a file in a given directory. And I'm going to try to represent it as a string. So on a Windows computer, I can write something like the "C:\My Documents\" "new\videos" But notice we're running into all kinds of problems here. The problem is that Rust is interpreting some of these special characters as special characters. Right. So here we literally mean \new to indicate our folder and directory. But Rust thinks we're trying to render a newline character. Right. The same one we saw on line 2. So when we have a backslash we once again need to escape it. Just like the double quote on the line above to tell Rust "This isn't a backslash that is part of a special character. This is just a literal backslash that we want to render within the string". So as you might guess, we use a backslash to escape a backslash. So right here, before each backslash, I'll add another one. And that is how Rust knows to treat it literally. So if I go to my println! and I provide the value of file_path right here, let's just interpolate it directly. We're going to see the final output is only going to include one backslash at each folder location because only one was needed. The other backslash in front of it was the one that escaped it that told Rust to treat that backslash character literally. Now, this syntax can be a little bit annoying due to just the confusing aspect of it. So another option that Rust offers us in this situation is using something called a raw string. A raw string is one in which Rust will automatically ignore all special characters, so it will treat every character literally. So, for example, a \n character will not be treated as a new line. It will just be treated as literally \n. Similarly, a \t character will not be treated as a tab in a raw string. It will be treated as literally \t. So this can help us solve the problem here by avoiding all the additional slashes. It's called a raw string because Rust interprets the raw text, the core text, without any modification. So what we do is we place a lowercase character 'r' before the start of the double quote. That is short for raw, and that tells Rust: "Treat every character literally". So we can remove every extra backslash here and here and here and get the exact same result. Rust interprets the string literally as a raw string as a piece of raw text, so we get the exact same result. So if you find that you are accidentally having to escape a lot of characters and you want to treat the string literally and take every character as is, then you can do a raw string with the lowercase 'r'. All right. So that is a quick review of what strings are as well as some of these special characters that we can add to them.

# The map Method II

Once we have an iterator, we can chain the 'map' method or other adapter methods in sequence to generate more iterators. In other words, we can use one iterator to create the next one to create the next one, and so on. It's just a pipeline of sequential transformations to apply. So here I have an array of three strings: Jimmy, Cleveland and Boris, and say that I want to do the following. I want to lowercase each string. I then want to replace each 'i' character with two '@' signs. Then I want to take the length of each resulting string and finally return all of those lengths in a new vector. So that consists of three sequential operations, and I can accomplish this by chaining on three sequential 'map' method calls. I of course, can do the exact same logic within one closure within a single 'map' method call, but it's also advantageous to think of each transformation as an independent process, and it goes to demonstrate the syntax of applying multiple adapter methods in sequence. So here's what that's going to look like. I'll begin by declaring a variable called 'name_lengths'. And I will start by taking my 'names' array. I'm going to call the 'iter' method to borrow an iterator of references. Then, I'm going to call map on that iterator and pass in a closure. And we're going to receive each name as a ref string ( &String), as a String reference right here. Now in this scenario, we do not need to explicitly provide the closure parameter type. It's just going to work out of the box. And then what I can do this time, even without my curly braces, is take my name String ref and call the 'to_lowercase' method to create a new heap String with all of the characters in lowercase. So that is going to give me a new iterator. Still not exhausted, but with the logic of taking each string reference and creating a new heap String from it all in lowercase, I'm going to take this iterator, which supports the exact same family of methods, and call 'map' on that iterator. And here once again I will provide a different closure and this time around, since this will return an iterator of Strings. Each name that I receive here in this 'name' parameter is no longer going to be a ref string ( &String) , but rather just a regular string (String). this lowercased one one at a time. As I mentioned, the second thing I wanted to do, and this is all arbitrary, is to take that lowercase string, call the 'replace' method on it, and replace every occurrence of the lowercase I with two '@' signs. And that's just an arbitrary example. So now with formatting, it's a little bit easier to see what's happening. We are creating an iterator, creating another iterator from that and creating another iterator from that. So one more time on the next line, I'm going to call 'map'. We're still going to be getting back a 'name' parameter that is a String, because the 'replace' method is another example of a method that mutates because it needs to modify the heap String by replacing elements which may consist of replacing, for example, one character with multiple ones, and that requires a mutation. So now I'm going to get that modified heap String, or perhaps a new one. And I'm going to call the 'len' method on that. And the 'len' method is going to return a usize type. Now at this point I once again still have an iterator. It's just been produced sequentially by progressing from iterator to iterator to iterator. So finally I can call the 'collect' method. Once again, this by itself is not going to be sufficient. So one way I can solve this problem is by declaring my type right here. This will be a vector of usize elements. As a reminder, usize is just a regular unsigned integer, either u32 or u64, but it depends on the architecture of the operating system that this code is compiled on. Regardless, this is going to work, and so will providing the turbofish operator right here and specifying a vector of usize values right here. So now if I call my println! right here and provide 'name_lengths' in Debug format, that should do it. The only thing that's missing here is another closing curly brace. There we go. And now we're going to get our new vector of just the lengths. So, for example, the string of Jimmy has 5 characters, but we replaced every'i' with two '@' signs. So this became two '@'s leading to 'J @ @ m m y' And that has a length of six. And that's the value that was gathered in this 'name_lengths' vector, same logic applied everywhere here. And that just goes to show that we can chain 'map' multiple times in sequence. But as we explore more of the adapter methods throughout the next lessons, all of them are going to apply in a very similar manner. We can just take them and use them sequentially to keep building up the incremental logic, transforming one iterator to the next, one to the next one up until the point that we have the iterator and its data in the shape that we want it, and then we perform the actual exhaustion, the collection of values, the traversal with something like 'collect' with something like a for loop, or with a variety of different other approaches that we're also going to see. It's all just giving you the building blocks to stack on top of each other, to take one original collection type and transform it into a different one from that original source of data. That is the magic of iterators.

# Refactoring Payment Data Access module for Outbox pattern

Hi everyone. Let's add the Outbox repository adapters in the payment data access module. In the payment data access module, I will create an Outbox package. As I did previously, since these adapter implementations will be straightforward, I will put two implementation clauses here for this adapter implementation, and go over and explain them. Let's start with entity class OrderOutboxEntity. Here I have the same annotations that I used for the previous entities, Lombok annotations, Getter, Setter, Builder, NoArgs, and AllArgs constructors, and JPA annotations entity and table. As you see, the table name is order_outbox. The id annotation is on ID field which is the primary key for this entity. Then I have this sagaId created, and processed at times, and type, and payloads string fields. Then I have two enums, OutboxStatus and PaymentStatus. And finally I have the version integer fields. The equals and hashCode methods use the ID fields which is the field that provides uniqueness for this entity. And in the exception package, I have OrderOutboxNotFoundException class which is a run-time exception as you can see. Then in the mapper package, I have order Outbox, data access, mapper components. As you see, this is a Spring components. Here I have two methods, orderOutboxMessageToOutboxEntity, to convert order Outbox message to entity, and the second methods, orderOutboxEntityToOrderOutboxMessage, to convert an entity to an Outbox message object. As you see in both methods, I use the builder pattern, and use the builder methods in the classes itself. In the repository package, I have OrderOutboxJpaRepository, Spring Bean. As you see, this interface is annotated with repository annotation to make it a sprint managed bin in the data layer. Here I extend JpaRepository with OrderOutboxEntity, and UUID generic types 'cause the UUID is the key for the OrderOutboxEntity. I have three methods here. findByTypeAndOutboxStatus, that takes type and OutboxStatus as parameters, and return an optional list of OrderOutboxEntity. Then, I have, findByTypeAndSagaId- AndPaymentStatusAndOutboxStatus methods which type sagaId, PaymentStatus, and OutboxStatus parameters. Here I return an optional OrderOutback entity. Finally, deleteByTypeAndOutboxStatus methods takes type and OutboxStatus parameters to delete the Outbox messages. Great, let's go to do adapter package. Here I have order Outbox repository in-pull adapter implementation, which has components annotation. This class implements OrderOutboxRepository from payment application service which is in the payments domain layer. This interface is one of the output ports of the payments domain layer, as you can see here. So it needs to be implemented in one of the infrastructure modules, and so I am doing that in the data access module here. In this class, I inject two fields, OrderOutboxJpaRepository, and OrderOutboxDataAccessMapper. Then in the same methods, OrderOutboxJpaRepository same method is called, and OrderOutboxDataAccessMapper class is used to convert domain objects to entity in the parameter, and also to convert the result entity to Outbox message object as the return type is order Outbox message in this method. Then, I have findByTypeAndOutboxStatus methods with SagaType and OutboxStatus parameters. Here I call the JPA repository, findByType and OutboxStatus methods, and get a list of Outbox objects. If I cannot find any objects, I throw an OutboxNotFoundException here, and otherwise I map the entity objects to Outbox objects using order orderOutboxEntityToOrderOutboxMessage methods, and collect the results to an optional list of order Outbacks message. In the findByTypeAndSagaIdAnd- PaymentStatusAndOutboxStatus methods, I simply call OrderOutboxJpaRepository, findByTypeAndSagaId- AndPaymentStatusAndOutboxStatus methods, and get an OrderOutboxEntity objects, and then map it to Outbox objects using the DataAccessMapper methods, orderOutboxEntityToOrderOutboxMessage. Finally, in deleteByTypeAndOutboxStatus methods, I call the JpaRepository delete methods with SagaType and OutboxStatus parameters to delete the Outbox objects. Great, data access implementation changes are completed. Let's finish the Outbox pattern changes of payment service with the messaging module. I will do that in the next lecture.

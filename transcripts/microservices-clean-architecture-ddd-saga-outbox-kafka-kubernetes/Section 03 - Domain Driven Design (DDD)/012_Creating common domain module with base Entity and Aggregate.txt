# Creating common domain module with base Entity and Aggregate Root classes

Hi everyone. Let's start implementing order service domain logic. I will open IntelliJ and then open the food ordering system application that we have created in the previous lectures. As discussed, I will create required entities aggregate roots, value objects, domain events and the domain services in the domain core module. But I want to use some base classes and interfaces that will be common for any core domain logic. So at this point let first create and if Mabel module called common. I will delete this source folder because I will use this one as a base module. And then let's create a sub module called Common Domain. Let's delete the Maven compiler properties as I have set them in the base pom example file using the Maven compiler plugin. Now, I will go to base pom exam file and add this common domain module with version into the dependency management section. And then include this common domain dependency in the order domain called module because I will use some common domain objects from this common module. And I will go to Java source folder in common domain and create a base package here, called food ordering system domain. And create a sub package named Entity. In this package, I will create an abstract class named BaseEntity. Here I want to define a generic ID variable And then create a private ID field with this generic type. So I will extend this base entity for each entity and replace the generic ID with the identifier type of the entity. Let's create setter and getter for the ID fields and also overrides equals and hash methods that will use the ID fields in the implementation. These methods are important for an entity because as you can remember, each entity should have a unique ID and equals and hash methods are the contracts that are used to compare the Java objects. And I will also create another abstract class here called AggregateRoot. I want to mark the AggregateRoots of an aggregate by just extending this abstract class. So when I look at the course I will be able to tell which class is an entity and which one is the aggregate root. In the aggregate root I will simply extend the base entity to be able to reuse the getter and setter methods of ID and also the equals and hash methods. I also need to define the ID generic type as in the base entity here. So this will be simply a marker class. It is still an entity that has a unique id but I created an new class and name it as AggregateRoot. to distinguish the root object from the other entities. I will use these two classes, base entity and aggregate roots from the entity classes that I will define in the order service domain core. Also, when I implement payment and restaurant service domain core modules, I will again use these base classes in this common domain module. Alright, let's continue with value object common objects in the next lecture.

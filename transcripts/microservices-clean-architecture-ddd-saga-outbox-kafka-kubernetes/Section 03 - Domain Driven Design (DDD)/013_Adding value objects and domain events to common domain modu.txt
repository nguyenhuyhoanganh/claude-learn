As discussed, one of the advantages of using a value object is it brings context to the value. So when you look at a class, you'll understand what it holds as a value. I have mentioned another advantage of using a value object. When you have a separate class for money object, you can have some business operations inside the value object, so that you can delegate some business logic to this value object. For this purpose, I will create simple monetary calculation methods here in the Money value object. First, I will add public "isGreaterThanZero" method with as return type "boolean". Here I will check if the amount is greater than zero. First I will check if it is not null. And use "compareTo" method on amount object, which is BigDecimal. Then I will compare it with "BigDecimal.ZERO". Notice that I used compareTo method here instead of equals method on the BigDecimal object. If you use equals method, and if you have a BigDecimal with decimal points like 0.00, and you use "0" integer in the comparison, it will not return the correct result. So by using compareTo method, I will be sure that the comparison return the correct result, whether my value has decimal points or not. So it's a best practice to use compareTo methods for this type of comparisons in the BigDecimal operations. Second method I would like to add is "isGreaterThan" method, with Money parameter, and return a boolean. Here I will compare two Money objects and check if the amount of the current object is greater than the parameter amount. Then I will add public "add" method. This method will take a Money parameter and return a Money. I will simply create a new Money object, and in the constructor I will call the add method on the amount object to create a new Money object with the addition. For the BigDecimal operations like "add" and "multiply", if the operation includes monetary calculations, you need to be more cautious to care the precision and rounding operations. To do that, I will create a method here to set the scale of a BigDecimal. With scale "2". And "RoundingMode.HALF_EVEN". So with this scale method, I can add values like 10.75 or 500.80. So what does it do actually? When you set a scale, after each BigDecimal operation the result will be rounded to that scale. Because of the nature of floating point arithmetic, not all calculations will give smooth results. Some numbers in binary system simply cannot be shown exactly, as in the decimal numbers. For example, think about 1 divided by 3. This cannot be shown with an exact number using decimal point, because a repeating 3. There are also numbers in binary system with this nature. For example, if we take 7 divided by 10 in binary system. It will be 111 divided by 1010. And if I do this divide operation, I will get 0.1011001100. As you see, the "1100" part is the repeating part continuously in this result. If you would like to go into the details of this behavior and to see the possible resolutions while using fractional numbers in Java, you may check my blog post about this issue. Because of that behavior in Java, resulting value is chosen with the most accurate result using the available bits. When you keep adding numbers, the total error will keep getting bigger. To minimize the total error, I will use here HALF_EVEN rounding mode, which statistically minimizes the cumulative error. So that's why I create this setScale method object with scale "2" and with rounding mode "HALF_EVEN", and I call this method before creating the Money object with the BigDecimal value. So let's call this setScale method in the add method before constructing the Money object. Similarly, I will add a public subtract method, which will take a Money object and return a Money object again. I'll create a new Money object by subtracting the amount. Again I will set the scale of the BigDecimal before creating the Money object, by calling the setScale method. Finally, I will add a public "multiply" method, which will take an integer "multiplier" as a parameter and return a Money object. I'll create a new Money object by multiplying the amount with the multiplier. And I do not forget to call the setScale method before creating the Money object also here.

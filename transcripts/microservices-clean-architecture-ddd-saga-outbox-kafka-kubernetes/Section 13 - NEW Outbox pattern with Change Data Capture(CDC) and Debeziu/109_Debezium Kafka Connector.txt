# Debezium Kafka Connector

Hi everyone. As I mentioned in the previous lecture to implement change data capture, I will use open source Debezium platform. First, let's create a new branch. If you are on the master branch or in the Spring Boot update branch, just create a new branch using git checkout -b command and set the branch name as debezium-cdc. Since I use Docker to run Kafka, here, I will prefer to run Debezium with the Docker image and I will simply add the Debezium connector container definition to the Kafka cluster compose file. Here is the compose file updated with Debezium Docker image. I used version 2.2, an updated environment file with the Debezium version to use in the Docker compose. It uses Port 8083. There are three mandatory Kafka topics for Debezium connector as you see here for config, offset, and status. Here, I gave the topic names explicitly. And we have bootstrap service of the Kafka cluster to connect to Kafka from the connector. And I have the Debug log level here. These variables are actually enough to run and use Debezium connector. However, remember I have confluent schema registry used in my previous code. I want to keep using it with Debezium connector as well. For this purpose, I added CONNECT_SCHEMA_NAME_ADJUSTMENT_MODE as avro here. And then set key and value converters as confluent avro converter class. And also set key and value converter schema registry URL with my schema registry URL. I also used depends_on property to first start Kafka cluster and then the Debezium connector. Then I have the networks property here that allows to use common network to communicate from connector to Kafka. Now here, I also have volumes definition that maps required schema registry JAR files into the running connector container. This is required to use confluent schema registry with Debezium. As I explained in this documentation page of Debezium, we need to map the required JAR files into the Kafka/connect folder, under the running container. I downloaded these JAR files from confluent Maven Repository. Apart from downloaded JAR files, I had to add Guava, Avro, and Kafka schema converter JAR files to run the Debezium Connect 2.2 version. So the final set of JAR files to use with Debezium connector 2.2 and with Kafka version 7.2.5 are listed here. You can get Kafka schema converter from confluent repo as in the other JAR files. However, for Guava and Avro, you need to get them from central Maven repository. Note that, by default, Debezium connector uses JSON serialization. But here, I configured it to use Avro. Avro is more compact binary format and better in performance. In the end, the schema will have two objects, before and after. And the before object represents the data before doing a change. So this will be empty, if you make an insert. And after object will be the newly updated or inserted object. And we can use after object to get the newly inserted record with the outbox pattern. We will see this in action in the following lectures. Please note that there is also an option to use SMT, which means single message transform in Debezium. This will transform the JSON object to a simplified version so that instead of having before and after objects, you may have only the desired object with the fields, as you can see here. It has a JSON object with field1 and field2. I won't go into the details of this message transformation and use the basic Debezium object to show you the details in the implementation. Now let's run this Docker compose file. First, I will run zookeeper and then the Kafka cluster using Docker compose. As you can see, I have the Debezium connector container running on 8083 port. Now if I go to Postman and query the connectors' endpoints, I will see an empty result. Great, in the next lecture, I will add Postgres source connectors for the outbox tables that are used in the project. Remember that I have four outbox tables. If I checked init schema sql file of order service, there are two outbox tables in order schema, payment_outbox and restaurant_approval_outbox. Then I have one outbox table called order_outbox in the payment schema. And finally, in the init schema sql file of restaurant service, I have the order outbox table in restaurant schema. All right, I will see you in the next lecture to create the Debezium Postgres source connectors.

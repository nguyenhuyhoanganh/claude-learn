# Running multiple instances of services  with a Jmeter performance scenario

Hi everyone In this lecture, I will create a performance test using JMeter. For this test, I will run three instances for order service, payment service and restaurant service. We may also create Docker containers for these services, but for simplicity and to have more control on running the services for the load tests, I will run them inside IntelliJ. So let's create three configuration for each service. I will go to Edit Configurations in IntelliJ. Here I have three application for order service. And for the first one, I will choose VM options, and set port as 8182, and also set the consumer concurrency level to one. Remember, I have a concurrency level config property under Consumer Config. This property actually defines the number of threads that will be created in this Spring Kafka Listener as you see here in the config class. Since I have three partitions on my Kafka topics, on the consumer side, I can create three threads to consume each partition in parallel. But since I create three instances of each service, instead of having three threads in an instance of a service, I will create one thread per instance, but in total, I will have three consumer threads running in different service instances. Since all instances will share the same consumer group, in the end, three partitions will be distributed to the instances of the service so that each instance will consume a single partition of a Kafka topic. Now, for the OrderServiceApplication2, I set the port as 8182 and set concurrency level one. And also here I will set Spring Sql Init Mode to Never, because I have a schema initialization SQL as you see here in the order service resources folder. And I just want to do the initialization in a single instance. Otherwise all three instances will start creating this schema at the same time, and it will create race condition issue as all will be working at the same time. For the third service, I have the same VM parameters, but I changed the port as 8183. Similarly, I have three payment service applications here. Since I don't have a REST API, I will just set the concurrency level to one in each application instance without setting any port. And also I set the Init Mode to Never for instances two and three. And finally, for the restaurant service, I have three instances and for each of them, I set the concurrency level to one and set the SQL Init Mode to never for instances two and three. Great, I will increase the max heap of IntelliJ to be able to run all these services without an internal memory issue in IntelliJ. So I will go to Help and Change Memory Settings, and use four gigabytes instead of default two. Depending on your machine configuration, you may choose more than four gigabytes also in IntelliJ if you see a slowness. Now, I can run start-up shell script first. After checking the containers with docker ps command, let's also check the Debezium connectors through Postman. As you see, all four connectors are created. Now, I will run all instances of each service. Please note that I run only one instance for customer service as it is not included in the outbox pattern implementation. Before running the services, I will go to the payment container init data SQL file, and set this customer's credits to 50000. I will adjust the history data as well to be consistent. So 70000 credit and 20000 debit. Then I will go to Init data SQL file of restaurant service, and set this product price to 1. So I will be able to send 50000 order for this product using the customer with credit of 50000. I will use these customer and product information for the load test. All right, let's run all instances of our services. I can choose all of them and start them at the same time in the IntelliJ. Oh I got an error in the order service here. I will create a customer on customer API on port 8184. Then I will create an order using order services first instance on port 8181. Then I will create another order using the second instance, which is running on port 8182. And let's create another one using the third instance, which is running on 8183. Again, if I check the order status with tracking ID, I'll see that they are all approved. Now, I will install JMeter to run multiple concurrent order requests. For my Mac machine, I will simply use brew install jmeter command. For Windows and Linux, you can install the binary version from the JMeter download site and then run the executable inside the downloaded folder. For example, for Windows, it has a JMeter batch file to start JMeter. Now, I will start JMeter, and first create a test plan with name, "Food ordering system load test." And then create a thread group here. For now, I will choose one thread. That means one user and set ramp-up period as one, and loop count also one here. Ramp-up is the time elapses between the threads run. So if I set thread counts to 10 and set ramp-up as one, each thread will start one after another waiting one seconds in between. And loop count is the number to repeat the same tests. So I'll keep it as one here. All right, now, let's create HTTP Request Defaults, and set protocol as HTTP and server name as localhost. This will have the default values for each HTTP request that I will create. Then I will also create HTTP Header Manager, and set the content type as application JSON. Again, this will be used for each HTTP request in my test plan. Then I will create HTTP request called Create Order 1. I will set the port as 8181. As you see, I left the protocol and server name as Empty, because they will be coming from the HTTP Request Defaults. I will use POST method here and set the path as orders. As you see from Postman, I have the orders path for this API. I will also copy the JSON body and put on the body data tab of HTTP requests here in the JMeter. Then under this HTTP request, I will create a JSON extractor. I will choose main and sub samples, then I will extract order tracking ID using JSON path expression here and assign it to a variable named orderTrackingId_1. All right now, I will copy this request and paste two times. I will rename the second one and set the port as 8182. And rename the extracted order tracking ID variable. Similarly for the third request, I will set the port as 8183, and rename the order tracking ID to use underscore three. So I have three HTTP requests for three instances of order service here. Then I will create a While Controller. Under this While Controller, I will create a new HTTP request, and call it as Get Order Result 1. This will go to the order service on 8181 port, and we'll make a Get Request to the orders path with orderTrackingId_1 parameter. Remember that I extracted this order tracking ID value from the Create Order 1 request. Then here, I will create another JSON extractor, and extract order status value, and assign it to a orderStatus_1 variable. Then in the While Controller, I will use a Javascript statement, and check if this extracted order status value is not approved and not cancelled. This means that the While Loop will continue until the order service Get API returns approved, or cancelled status which are the final status values for our process. Any other values such as pending, paid for, cancelling are intermediate status values, and they indicate that the data is still being processed. So here after creating an order with a While Loop, I'm checking until the order service Get API returns approved or cancelled status values, which will indicate that the processing is finished. I will copy and paste this While Controller two times, and get the order from 8182 port for the second one, and use tracking ID 2, which was extracted in the second create order request. Then in the JSON extractor, I will use orderStatus_2, and in the While Loop, I will check the order status value to be approved or cancelled. Similarly, for the third While Loop, I will update the port as 8183 and use tracking ID three. And in the extractor, I'll get order status three. Finally, in the While Loop, I will check the value of order status three. Great, now, to see the results, I will add a Graph Result here, and also a View Results Tree item. Now, my test plan is ready. Let's run this. Remember that I only run a single thread here with a loop count 1. However, since I have three create order requests, I expect three orders to be created.

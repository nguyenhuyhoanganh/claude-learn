# Update to spring boot 2.7.5

Hi everyone. In this section, I will keep adding lectures to update the application to the latest versions. And in this first lecture, I will start updating Spring Boot version to 2.7.5. I will also update other dependencies to the latest versions here. So let's start. I will create a new branch named update-to-springboot 2.7.5. As you know, we have a base POM XML file which holds all versions in a single place. So updating the versions will be a trivial task. However, when there is a breaking change, we need to change the code as well. Luckily, from Spring Boot 2.6.7 to 2.7.5, there is no breaking change so we will need minimal changes in the application. Now I will go and update parent Spring Boot version as 2.7.5 in the base POM XML file. In this file in the property section, I will also update Maven compiler plugin version to 3.10.1, then Mockito versions is 4.8.1, Spring Kafka version is 2.9.2, Kafka Avro Serializer version to 7.2.1, and finally Avro version to 1.11.1. Let's load Maven changes. I got these latest versions from Maven repository. You may also go and check by searching the dependency in the Maven repository page. Now one thing I need to change with the latest Avro version is that when a logical type is UUID, the Avro Maven plugin will create a UUID field instead of string. In the previous version, the autogenerated fields are string as you see here. Instead of changing the codes, I will just change to Avro schema files and remove the logical type UUID definitions so that I will stick to the string fields in the autogenerated Avro models. So I will go and change customer schema file, then payment request schema file, and then payment response schema file, restaurant approval request schema file, and finally restaurant approval response schema file. For each ID type, I removed two logical type, so that the overall Maven plugin will generate string fields instead of UUID fields. Now, it is wise to check any deprecated codes with the new changes. So I will use intelligent menu item, code, and go to Analyze Code, and then Run Inspection by Name and search for Deprecated API. All right. As you see, these Kafka header definitions are deprecated. As mentioned in the documentation, I need to use received key instead of received message key and use received partition instead of received partition ID. Let's replace these ones in all projects. I will right click on the project and choose Replace in Files. Choose In Project, and replace all occurrences for these deprecated usages. First for received message key, then for received partition ID. After that, if I check the deprecated usage, I will not find anything. As a final change, now I will update the application YAML files to fix the SQL init file configuration because with the Spring Boot 2.7.5, we need to use SQL init modes and schema locations instead of data source schema and initialization modes properties. So I will change all the application YAML files to use the new SQL init properties, instead of two data source schema, and initialization mode properties. Now, I will run Maven clean install commands and see if the build is successful. As you see the build is successful. So I will go and run the Kafka cluster, and then the services to test the application with the new versions. First, I will go to the infrastructure Docker compose folders and run zookeeper Docker compose file using Docker compose commands. I will not forget to pass common YAML file to get the network name. Then I will open a terminal window and run Kafka clusters using Docker compose commands again. Finally, I will open another terminal and run in it Kafka YAML file to create the Kafka topics. All right. Now, let's run the customer service first. Then order service, then payment service, and finally I will run restaurant service. Let's create a customer using the customer's endpoint which runs on 8184 ports. I will use Postman and send a post request using the JSON body to create the customer. Great. Now, I will send a post request to order service restaurant point, which runs on 8181. For this, I will use this JSON data. As you see, I sent customer and restaurant ID, address, price and items to be ordered. First, the order is in pending status, then it should go to the paid state, and finally to be approved as you see here. To test a failure scenario, let's try to send this order two more times, and I should see a failure in the third order request because customer's credit is not enough. Remember, this customer had 500 credits which is hard codes in payment service in its data SQL file for demo purposes. All right. We have the application updated to the latest Spring Boot version. I will continue adding new lectures to this section to keep the code and the other dependencies up to date. So I will see you in the new update lectures.

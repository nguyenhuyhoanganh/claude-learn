# Update to spring boot 3.0.5

Hi everyone. In this lecture, I will update Spring Boot to the latest version, which is currently 3.0.5. I will also update the other dependencies to the latest versions and update Kafka Docker Image version. Before doing these updates, please be sure you applied the changes in the previous update video for 2.7.5 version. So let's start. I will create a new branch named update-to-spring-boot-3.0.5 based on 2.7.5 branch. Since we have base POM XML file which holds all versions in a single place, updating the versions will be easy in a single place. Now I will go and update parent Spring Boot version to 3.0.5 in the base POM XML file. In this file, in the properties section, I will also update Mockito version as 5.2.0, spring-kafka.version as 3.0.5, and kafka-avro-serializer version to 7.3.3. You can see the latest versions in the Maven repository. Now let's Load Maven Changes. Then I will do a Build. First of all, as you see the deprecated javax packages are removed in Spring Boot 3, so this should be replaced by Jakarta packages. As you see, we have used javax annotation, persistence, and validation packages. I just need to replace the javax with jakarta in all those imports. So actually replacing javax with jakarta using the IntelliJ replace all window will be enough here. Then in the Kafka producer impl, I see that the return type of KafkaProducer send method is changed from ListenableFuture to CompletableFuture, which provides more fluent way of handling the callbacks. So I cannot use ListenableFutureCallback as the parameter here anymore. First, I will change this local variable as CompletableFuture. CompletableFuture has a method called whenComplete which takes a parameter of type BiConsumer. So if I pass a BiConsumer here in the parameter, I can simply set it as a parameter to whenComplete method. As the second generic parameter of BiConsumer, I will provide a Throwable here. I will go and change the KafkaProducer interface accordingly and use BiConsumer as the parameter also there. So this BiConsumer takes SendResult and Throwable parameters and I will use them in the callback method implementation. Great, then I will go to KafkaMessageHelper class where I actually create the callback object. Here, I will change the return type to BiConsumer and return and implementation of BiConsumer, which simply gets two inputs, result and exception, and return anything. Here in the implementation, if the exception is null, I will put the code that I was using in the previous onSuccess method. If there is an exception, I will use the code in the onFailure methods as it is. Now I can delete the old ListenableFutureCallback implementation. Great, if I check the places that I use this method, they don't require any change because now I return a BiConsumer from the kafkaMessageHelper.getKafkaCallback method. And also accept a BiConsumer on the KafkaProducer send method. Similarly, in the Customer Created Event Kafka publisher class, I will use BiConsumer instead of ListenableFutureCallback. We had this extra callback method in the customer class because we used it in CQRS pattern, so it has different parameters than the generic callback method which has the outbox pattern implementation additionally. Here, I will use the similar approach and if exception is null, just run the successful code, otherwise, log an error statement. Now it is wise to check any deprecated code with the new changes. So I will go to IntelliJ menu item, Code, Analyze Code, and Run Inspection by Name, and then search for the Deprecated APIs. All Right as you see, there is no deprecated usage. That's great. Finally, I will update Kafka Docker Image version. I will go to environment file under docker-compose folder and change the Kafka version as 7.2.5. Great, now I will run Maven clean install command and see if the build is successful. As you see, the build is successful. So I will go and run the Kafka cluster and then run the services to test the application with the new version changes. First, I will go to infrastructure/docker-compose folder and run zookeeper docker-compose file using docker-compose -f common yml -f zookeeper.yml up command. Then I will open a new terminal window and run Kafka cluster using the docker-compose command. Finally, I will run init_kafka.yml to create the Kafka topics in a new terminal window. All Right, now let's run the services. First, I will run customer-service, then the order-service, and then payment-service, and finally, restaurant-service. Let's first create a customer using the customer rest endpoint using localhost 8184. I will use Postman and send a post request using the JSON Body to create the customer. I have the JSON bodies in the repository under json-files folder, as you see here. Great, now I will send a post request to the order service rest endpoint which runs on 8181 port. For this, I will use this JSON data. Here, I send customer ID and restaurant ID and also address, price, and the items information, as you see. First, I see that the order is in PENDING state, it should go to PAID state and finally, to the APPROVED state, if there is no error. Now to test a failure scenario, let's try to send this order again and again. As you see, after third order request, I got a failure because customer's credit is not enough. Since this customer had a 500 credits which is hardcoded in the payment service init-data SQL file for demo purpose, after spending all 500 credits for the same customer, I got an exception because the customer doesn't have enough credit for the payment. All right, we have the application updated to the latest Spring Boot and for the other dependencies. I will continue adding new lectures to this section to keep the code and the other dependencies up-to-date. So I will see you in the new update lectures.

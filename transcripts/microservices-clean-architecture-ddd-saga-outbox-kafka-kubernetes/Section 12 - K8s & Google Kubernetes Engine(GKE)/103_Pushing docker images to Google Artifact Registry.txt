# Pushing docker images to Google Artifact Registry

All right, let's see how to push Docker images of the microservices into Google Artifactory. To push my local Docker images to Google Artifactory I will use gcloud on my local environment. If you haven't installed it yet, please go to cloud.google.chrome, install SDK page and install gcloud locally. First, you need to download the TAR file, and then use tar -xvf commands to open it to a directory. I will open a terminal, and then I will run the install SH file under this directory as mentioned here. It'll ask to add the gcloud into path and then ask to install Python 3.7. I will accept it and continue. Finally, I will initialize gcloud using init commands. I will copy these commands and run. This will ask to log in into Google Clouds. I will say yes and log using the browser interaction. As you see it found my project, I will choose one to pick the food ordering system application that I have created in the previous lecture. I will also set the default compute zone. Remember, I have set europe-west4-a in the web console. Here I will choose the same. It is in number 14, as you see. Great, now I have gcloud installed and initialized in my local environment. It has been sure we have run these commands successfully before continue with the rest of the lecture. Now I can push my Docker images to Google Artifactory. However, first I need to tag the Docker images for Google Cloud. For this, I will run gclouds auth login, just to be sure I am locked into Google Clouds. I will again use web browser to log in. If your terminal cannot recognize gcloud commands, just close the terminal and open a new one, so that the new installation of gclouds will be effective in your machine. And I will list my application images using Docker images with greb food ordering system command, And you should see the four Docker images for each microservice in food ordering system. Remember, these four images are created with the Maven install commands using the Spring Boot Maven Plugin build image all. If you don't see the images, just run the mvn clean install command on the food ordering system-based directory, then your Docker images will be created. Now, I will use Docker tag commands to tag these images correctly for Google Artifactory. For this, I will check documentation, here in the tagging the local image section, I see that I need the location, project, repository and image. First, I will configure my local docker for europe-west4, remember that I chose europe-west4 as the region for my Artifacts Repository. So, I will run commands gcloud auth configure-docker europe-west4-docker.pkg.dev and update my config.json file for Docker with this command, as you see here, Let's write the Docker tag command. First, I will get the local Docker image name with the version for the order service from the Docker images command output. And for the location I will use europe-west4-docker.pkg dev, which is the region that I chose for that Artifact Registry. Then I will set the project name after the forward slash. You can get your default project name using gcloud config get project command. Then, I will let a forward slash and then use food-ordering-system-repository which is the name of the repository on Google Cloud Artifactory. And then I set the Docker image name with version 1.0-SNAPSHOT. With this commands, I will tag my Docker images using the Google Cloud location, project name, and repository values. Now, I will run same docker tech command for all services, for customer service, payment service, and restaurant service. And I will check Docker images command again to see if all four images are tagged correctly. Now, I will push these tagged Docker images to Google Artifactory. For this, I will run Docker push command and simply pass the tagged Docker image name. Here I push the restaurant service docker image. Similarly, I will push to other Docker images for all of the services. Now, let's go and check the Google Artifactory in web console. As you see, my Docker images are pushed to do food-ordering-system-repository artifactory. For the Docker tag and push commands, I will create an executable file to tag and push commands. I will also add gcloud auth login to the beginning of this file. For the version, I will use dollar one so it'll be the first arguments to this executable file, so that I make the version as a parameter to this file. Whenever a new version is released I can simply call this file to tag and push a new docker image using the new version as the parameter.

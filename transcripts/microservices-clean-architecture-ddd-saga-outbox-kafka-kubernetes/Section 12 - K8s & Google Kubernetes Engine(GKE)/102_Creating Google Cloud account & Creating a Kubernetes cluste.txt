# Creating Google Cloud account & Creating a Kubernetes cluster in GKE

Hi everyone. Let's start creating an account to use Google Clouds. It is possible to try Google Clouds for free for the first three months, so I will go to cloud google com and click on Get Started for free button. You will fill your information and continue with the next button. If it is the first time you set your phone in Google Services, you'll also need to validate your identity with your phone. Simply enter your phone and verify it with the code that will be sent to your phone. And then enter your name and address information and enter your payment information. Don't worry, you don't need to pay anything for the first three months and after three months, it'll be canceled automatically. So click on start my free trial button and create your Google Cloud accounts. To start using Google Cloud, first you need to create a project. So I will go to console and create a new project and name it as Food Ordering System. Remember that I run my application on local Kubernetes cluster, and now I want to use Google Kubernetes Engine to run my application. So I will click on Kubernetes engine manual item. Google Console will ask to enable Kubernetes engine API. By default, it is not enabled. So simply I need to click on enable button here to build and manage container based applications using this API. Now I will connect to terminal and use gcloud command line interface. I will simply click on this Activate Cloud Shell icon. First, I will run glcoud auth login. But actually it will tell that we are already authenticated, so I don't need to log in. However, if you use gcloud in your local machine, and run these commands remotely, you will first need to log in using this command. so I can run gcloud CLI in my local machine. And to do that, I just need to install gcloud for my operating system. By looking at this website. I will install gcloud to my local machine in the next lecture while publishing local locker images to Google Cloud Art Factory. After that, you can run gclouds unit commands on your local machine to perform several common gclouds CLI tasks such as to set your default concrete zone. Alright, I will now return to gcloud console on the web browser. Here you see that the project that I have created is already selected, food ordering system. If you have multiple projects, you also need to specify your project using gcloud's config set project command as you see here. Now I will run gcloud config set compute zone with Europe West for a commands. This will set the compute zone. These replace the zone with your other zone. Compute engine resources are hosted in multiple locations worldwide. These locations are composed of regions and zones. So you can create your projects in the zone that is closest to you. Then I will create my Kubernetes clusters using gcloud container clusters, create command. And set the name of the cluster as food ordering system cluster. It will take some time to create the cluster. It creates a three knot cluster as you see here. After the cluster is created, I will run kubectl, get nodes commands. And I will see the three knots that are created. If I refresh the webpage I will see the needly created cluster on user interface also. Here you see a connect link. It is required to connect to cluster before creating the Kubernetes ports using docker images. So I will run the corresponding commands in the gcloud console. After connecting to Kubernetes clusters, now I am ready to apply and create Kubernetes deployment. But to do that, I need to push my docker images into Google Artifact Registry. I will go to artifact registry on Google Console and enable it. I will use artifact registry instead of container registry as the artifact registry is the recommended way by Google. In the artifact registry, I will create a repository with name, food ordering system, repository. Then I will choose Docker then choose a region, and create a repository. It may give an error if you just enabled artifact registry recently. It takes some time for changes to propagate. So wait a bit and then try the Create button again. Great. I'm ready to push the docker images of my application into Google Artifact Registry. Let's do that in the next lecture.

# Running the Application on Google Kubernetes Engine - Part 1

Hi everyone. In this lecture, I will run the Kafka Cluster, Postgres and my application services in Google Kubernetes Engine. Okay, I will go to Google Console and open Shell. Here, I will simply clone the Helm charts for confluence as I did in my local repository. So I will run Git clone commands and get the CP Helm charts. Then I will check if Helm is installed with the Helm version command. As you see, it is already installed in Google Consult so I can run Helm install commands using the local directory. But please note that instead of cloning PCP Helm charts locally, you can also use helm repo add command with the Github link and then use helm repo update commands. Then you can run helm install using the remote repository as shown here in these commands. I use the local directory to make it available locally. Otherwise, in case the Github link doesn't work Helm may not install the charts. However, with this approach, I need to take care of pulling the latest versions when there is an update in the repository. That is actually good because I will be controlling the updates of this repository. So let's run Helm install commands. I will give a name, gke-confluent-kafka. Use the CP helm charts directory with version 0 6 0. If it is asked for authorization, I need to give it and then it will create the Kafka clusters. Let's check the pods using kubectl get pods commands. After some time, Kafka, Zookeeper, and Schema Registry should be in running state. Okay, now in the output of helm commands I see the Zookeeper host name here and also Bootstrap servers. I will need to use them in my application services in the Infra project because shortly I will use the files in the Infra Project to install the application services. So let's go to Infra project.

# Adding horizontal scaling to services

Hi everyone. Let's also introduce horizontal scaling to our application services. I will go to food-ordering-system-infra projects and update the application deployment, YML file. Here I add HorizontalPodAutoscaler for order service. Name it as order-deployment-hpa in default namespace and bind it to order-deployment using labels. Then I define, minimum replicas as two and maximum replicas as four, and use cpu Resource utilization as the metric for autoscaling. I set the targetsAverageUtilization to 85. With this set up, I will start with two instances of order service, and in case the CPU usage goes about 85%, Kubernetes Engine will create new instances up to four. Here instead of cpu. You may use any metric such as memory usage, request count or some custom metric. Let's add the same horizontal scaling config to payment, restaurant, and customer services. As you see, I use CPU utilization with 85% for horizontal scaling for each service. Now, one thing to fix here is to disable data source initialization because with multiple instances, each instance will try to initialize database resources and I will get errors at startup because of that. Remember that the data initialization is set as always but it is just for demo purposes. In production environments, you will only initialize your database resources once and then reuse it. So, I will let SPRING_DATASOURCE_INITIALIZATION-MODE. environment variable with value never. So, it'll not run the schema in data initialization files. Let's add this environment variable to all services. Okay, I will not forget order service here. I will push my changes to remote GitHub repository now. Great, I will delete the application deployment using kubectl delete command, and I won't delete Kafka and also Postgres So, the database objects will still be there. Then I will pull the latest changes for application deployment. It includes the horizontal scaling and also initialization mode set to never for data source. Then I will run kubectl, apply command again. As you see this time, the horizontal scaling resources are also created. If I check the kubectl get pods command, I will now see that multiple instances of the services are created. According to horizontal scaling configuration, I expect two instances for each service. With kubectl get all commands, I still see a single LoadBalancer external IP for each service. However, when I call this IP from outside of Kubernetes, the LoadBalancer will now send my request to one of the available instances distributing the logs among the instances. I will follow the order service logs for both pods.

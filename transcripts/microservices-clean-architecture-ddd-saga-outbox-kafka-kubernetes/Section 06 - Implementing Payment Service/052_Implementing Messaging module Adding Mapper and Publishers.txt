# Implementing Messaging module: Adding Mapper and Publishers

Hi everyone. In this lecture I will complete the payment messaging module. It will be another infrastructure module to implement messaging. In this messaging module I will use generic Kafka modules to implement the adapters for the publisher output parts of payments domain layer. Also, here I will create the Kafka listener implementations to be used by the domain layer. Let's go to POM XML file and set the required dependencies. In this module, I need the payment application service dependency, which is in the domain layer, and halt the output parts, since I will implement those output parts with adapters. Here I need to have a dependency to this module. I will also add Kafka producer, consumer, and model dependencies because to implement messaging, I will use Kafka here. And I will create base package, com food ordering system, payment service messaging, and then create three sub packages, listener Kafka, publisher Kafka, and mapper. Let's first create payment messaging data mapper class and mark this its component annotation. I will inject and use this data mapper class to convert domain and messaging objects. Here, I will have four methods. First one is payment completed event to payment response Avro model. It will create a payment response Avro model object from the payment completed events. As you see, I set the ID with a random UUID, and then set the SAGA ID as empty string. I will fill this value when I implement the SAGA pattern in the next section. Then I set the remaining fields simply by reading from the payment completed events and setting on the payment response Avro model object. Then I will create payment canceled events to payment response Avro model methods. This time, I will create a payment response Avro model object from the payment canceled event. It is almost the same codes with your previous methods, as you see here. Similarly, I will create payment failed events to payment response Avro model, and convert a payment failed event to an Avro model. And I will have payment request Avro model to payment request methods to create a payment request object from the payment request Avro model objects. These methods will create a payment request from the Kafka Avro object to send data to the domain layer on payment service. As you see, I set the ID, SAGA ID, customer and order ID, and then price createdAt and payments order status fields. For each method, I have used the builder pattern in the data micro class as you see here. And these builder patterns are implemented in the data classes. Great. Then I will go to the publisher package. Here, I will create three publishers for each type of payment events. First one is payment completed Kafka message publisher. As usual, I will add component annotation to create a Spring-managed bean from this class. Then I will add SLF4J annotation to create a lock variable. Then, I will implement payment completed message publisher interface from the domain layer of payment service and implement the publish method. Remember, this payment completed message publisher interface is the output port, and I implemented with an adapter here in the messaging module. I will add data mapper fields and then Kafka producer fields with string key and payment response Avro model as the value. This Kafka producer is the interface defined in the Kafka producer module. Then, I will add another final field here, payment service config data. I will use this config data to read the Kafka topic names. Now, I will create a constructor with these fields and inject them using constructor injection. In the published methods I will get the order ID from the payment completed event. And then log info message. And I will convert the events to a payment response Avro model object. And then I will call Kafka producer send methods. I will get the payment response topic name from the payment service config data. As the key for the Kafka records I will send order ID and as the value, I will send payment response Avro model object. Finally, I will need to create a Kafka callback method and send it here. Callback methods will be called when the Kafka producer gets a response from Kafka cluster. Remember that Kafka producer send methods is a synchronous methods. That's why I need a callback method here, as I will not get a response immediately. For the Kafka callback methods, actually, I can reuse the generic methods that I created in the order messaging module. So, let's rename this helper class and then move it to the Kafka producer module. Then, I can use it from order messaging module. I will change the publisher classes and use the Kafka message helper from the Kafka producer module. Then, I will use the same Kafka message Helper class in the payment messaging module. I will inject a Helper and then call to get Kafka callback methods. As I mentioned, I will make this system more resilient with SAGA outbox patterns. But for now, I just log messages in the callback methods here. I will just rename the Avro model and Avro model name to make them more generic, as I use these methods for both request and response models. Okay, in the publish methods, I will finally log an info message and also use a try/catch statement to log an error message in case the Kafka producer send operation has failed. And I will create a similar publisher class, payment canceled Kafka message publisher, which is almost the same, so I will copy it from the payment completed publisher and change implemented interface to payment canceled message publisher. I will also change the log message and the payment completed event to payment canceled event in the mapper methods. As you see, this is almost the same codes but I will not try to generalize it. Instead, I will keep each publisher separate to keep the possibility of changing them separately for different reasons. Then, again, I will copy the payment completed Kafka message publisher and create the publisher for payment failed event. I will use payment failed message publisher interface here. And also I will change the log message and change the mapper methods to use the payment failed event. All right. Publisher implementations are completed.

# Application module: Adding Web Controller

Hi everyone. In this section I will complete the order service with all components and modules. Let's start with order application module which will include a REST API. I will first go to Palm XML file of order application module and add springwood starter web dependency. This dependency will bring the required libraries to implement the REST API. I will also add springwood starter validation to implement the data validations. As you see, I already have order application service dependency to use the input parts of the domain layer in this REST API. Let's create a package home food ordering system order service application. And create two sub packages REST and exception handle. In the REST package, I will create order controller and annotate this glass with REST controller annotation which will simplify the creation of REST API. I will also use request mapping annotation and use mapping orders with application via the API V one plus Jason response type to indicate that this is a Jason API. Let's also add SLF 4G annotation to add a log variable automatically. In this controller, I want to forward the client request to do domain layer. And as you remember, to communicate with domain layer I have to use application service interface which is the input part in Hexagon Architecture terms. I have already a dependency to order application service module as you can see here. So I will create a field order application service and inject it using constructive injection. When the application runs with all components this order application service will be injected using the implementation class, which is in the order application service module, as you can see here. It is the order application service input class. I will first create create order methods with return type response entity with generic type create order response. I will use create order commands as the parameter here. To mark this parameter as the request buddy of to rest request, I will use request buddy annotation here also. I will mark these methods with post mapping annotation so this methods will serve to a HTTP post request. Here I will log an inform message and then call create order methods on order application service. This will return create order response object. I will log an inform message with the tracking ID. And return HTTP 200 response using response entity okay methods with a response object. As the second methods, I will let get order by tracking ID. With return type response entity with generic type, track order response. For parameter I will use tracking ID with UUID type and mark this parameter as the part variable. I will mark this method with get mapping annotation and use part variable tracking ID. So this method will serve to nhttp get request with URI orders/trackingid and this part variable tracking ID will be replaced with the ID that client will send. In the implementation of these methods, I will call order application service, track order methods and pass a track order query object creating it with the tracking ID. This will return a track order response object and I will log an info message and simply return the response entity with okay status quotes and with the response object. Okay, these two methods are written considering the happy flow. What will happen when there is an error in the client requests or when there is a server error? To handle error conditions, I will use a global exception handler using spring controller advice. Let's continue with that in the next lecture.

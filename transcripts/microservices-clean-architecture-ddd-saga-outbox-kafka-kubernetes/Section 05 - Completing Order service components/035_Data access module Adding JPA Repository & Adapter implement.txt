# Data access module: Adding JPA Repository & Adapter implementation

Now, I will create the JPA repository in the repository package. I will name this OrderJpaRepository, and extend JPA repository interface. For the generic types, I will use OrderEntity and UUID, So the entity class is OrderEntity, and the identifier is of type UUID, as you see here in the OrderEntity. I will annotate this interface with repository annotation, and with this annotation, Spring will create a JPA repository proxy class and will delegate the method calls to this proxy to complete the database operations. Here, I will add findBy TrackingId methods and return optional orderEntity and pass trackingId as the parameter. Now, I will create orderDataAccessMapper class in the mapper package. I will mark this class with component annotation. Then, I will create mapper methods to create entity objects from domain objects, and create domain objects from entity objects. So let's start creating the mapper methods, and the first one is OrderToOrderEntity. These methods will return OrderEntity and take an order domain object as parameter. I will use the builder pattern on the OrderEntity and set the id, customerId, restaurantId, and trackingId fields. For the address fields, I will create a private method here, DeliveryAddressToAddressEntity, and return an OrderAddressEntity from the StreetAddress domain object. Here, I will create OrderAddressEntity and set the ID, street, postal code, and city from the street address value object. Then, I will set price fields to entity, getting the amount fields from the money value object, and then I will set the items. And for this one, again, I will create a private method, OrderItemsToOrderItemEntities, and return list of OrderItemEntity objects from list of OrderItem objects. I will map the orderItem to OrderItemEntity, and set the fields: id, productId, price, quantity, and subtotal, And collect the results to a list of OrderItemEntity. Next, I will set orderStatus, and then I will set the failure messages for this. For simplicity, I want to create a single string field with delimiter from the list of string FailureMessages, so I will use string join methods and use a comma as the delimiter. Let's move this comma to a constant field in the order domain object so we can reuse it. And if the failure message list is null, I will set an empty string here. Now I create OrderEntity object using the build methods, and after this I will send the OrderEntity object to the orderAddress entity, and also to each order item in the OrderEntity object. All right. Now, I will create orderEntityToOrder methods. to convert an orderEntity to an order domain object. I will use order builder and set id, customerId, and restaurantId. As you see, I created the value objects for the ID fields. Then, I will set deliver address. And for this, I will create another private method, addressEntityToDeliveryAddress, and create a street address object from the orderAddress entity. Here, I set ID, street, postal codes, and city. Then I set price, creating a money value object. And then I will set items, and for this, I will create one more private method here, orderItemEntitiesToOrderItems. Here, I will create a list of order items from the list of order item entities. I will create the value objects for OrderItemId, products, and price. Then, I set quantity and the subtotal. I will complete OrderEntity to order methods, setting the trackingId and orderStatus. And finally, I will set the failure messages. For this, I will create a list from the string fail messages. To create the list, I will split the failure messages string using the failure message delimiter, which is comma. The split methods will return a string array, so I will use arrays as list methods here to create an ArrayList from the string array. As you see, I wrap the response of arrays as list methods using a new array list constructor because arrays as list methods creates an unmodifiable list, so I cannot add or remove elements from that list. When I wrap it with array list constructor, it'll return a modifiable list so that I can modify this list in the business logic methods. All right, let's complete the order data access with the adapter implementation. I will go to adapter package and create order repository input class and implement OrderRepository interface from the domain layer. As you see, this is an output port defined in the order domain service. Now, I will add component annotation to this adapter, so it'll be a Spring-managed pin. Then, I will add orderJpaRepository and orderDataAccessMapper fields, and inject them using constructor injection. Internally, I will use orderJpaRepository to complete database operations, So in this save method, I will call orderJpaRepository save methods, and for the parameter, I will call orderDataAccessMapper, orderToOrderEntity methods and pass the order to return an orderEntity. Finally, I will call orderDataAccessMapper orderEntityToOrder methods to pass the orderEntity as the parameter, so that I will return that domain object as the response, in the end, from this methods. Finally, in the findBy trackingId methods, I will call orderJpaRepository findBy trackingiD methods, and past the trackingiD as the parameter, and map the optional results to an optional order using the orderDataAccessMapper orderEntityToOrder methods.

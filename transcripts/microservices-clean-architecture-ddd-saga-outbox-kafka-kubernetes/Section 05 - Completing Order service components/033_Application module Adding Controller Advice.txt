# Application module: Adding Controller Advice

Hi everyone. In this lecture I will create a spring controller device to handle error conditions. So let's create order global exception handler class in the exception handler package and mark this class with controller advice annotation. I will also add Slf4j annotation here to use a log variable in the methods of this class. Here I will create overloaded methods with same name handle exception. In Java method overloading is having multiple methods with same name but with different parameters. So let's create the first methods with all domain exception parameter. For the return type I want to use a Java object with error codes and message. So I will create an error DTO class with string code and message fields. In this class, I will use data builder and all arcs constructor long bulk annotation. Now I return this in the handle exception methods. For these methods I will use three annotations. First one is response status. I will use bad request HTTP status here. So this methods will produce an HTTP response bad request. Then I will use exception handle annotation and set the value as order domain exception. So these methods will be called when this exception is strong. Remember that order domain exception is the exception strong from the order domain layer. Finally, I will add response by the annotation here. So the return type of this methods will be wrapped as an HTTP response. All right, so here I will log an error message and return error DTO with bad request HTTP status, and with the exception message which comes from the order domain layer. Now I will copy and past this methods and this time change the exception type and the parameters to order not found exception. Also, I've changed the response status to not found. So basically these new methods will return 404 HTTP status code, which indicates that the resource is not found. The resource is an order in this case. All right, in this exception order, I catched the order domain layer errors. As you remember, there are also data validation checks on the order domain service and also there could be some internal server errors during the request. Now, for these type of errors I want to create a generic exception handler because these type of errors can occur in the other microservices like in payment and restaurant service and propagated to the order service. For this purpose, I will create a new module named common application in the common module. Here first, I will add spring boot starter web and spring boot starter validation dependencies. Then I will create com food ordering system application handle package. First of all, I will still use the error DTO for the exception response and to make this error DTO a common class, I will move it from the order application module to the common application module. Now, to use this error DTO, I will let the common application dependency to do all the replication. But first I will add to dependency with diversion to the base palm XML file. Now I can add common application into order application palm XML file. Then I will fix the import statements in the order global exception handle class. Then in the the common application module I will create a global exception handle class again with controller advice and Slf4j annotations. Here I will create a new handle exception methods with generic exception class and with internal server error HTTP status. So I will add response status annotation with internal server error and add exception handler with exception class. Then I will add response by the annotation to create an HTTP response for the return type of these methods. Here I will log to error message and then set the code as internal server error. As an error message I use unexpected error because the real reason shouldn't matter for the clients for the internal server errors. Also, it is not correct to share the internal error messages for security reasons. Besides I already locked the message so it can be investigated by looking at the locks. I will add the second method here. This time I will use validation exception. So these methods will be called when there is a validation exception. The HTTP status will be bad request because data validations are a result of a bad request, and here I will extract the validation error messages. So please note that this validation exception can occur when you use valid annotations as in the application service. And when you have this spring validation annotations like this not null or max land annotations. In case the spring validation annotations fail, a validation exception will be thrown and I will catch them here in this method. In this method let's first create an order DTO object and then check if the exception is of type constraint violation exception. Constraint violation exceptions are the exceptions that comes from my validation annotations. I will create a method, extract violations from exception and past the exception to these methods and return a string with the combined validations as a string. In this method, I will get constrained violations and map them to get the exception messages. Finally, I will collect the messages to a string and combine them using a double dash. Then I will log an error message using the violation string and the exception. I will assign the error DTO using the violation string with bad request HTTP status. In case the exception is not a constraint violation exception, I will just get the exception message, log an error and assign the error DTO with exception message and with bad request HTTP status. Finally, I will return to error DTO. Right now to use this generic global exception handler in the older application exception handler. I will simply extend this class in the older global exception handle class. So this generic exception handler can be used from any rest API module. All right, we have finished the application module and implemented the rest API. Remember, this application module uses the input port of order domain, which is order application service.

# Messaging module: Adding Listener implementations

Hi everyone. Now I will continue with listener implementations. Let's go to listener Kafka package and create PaymentResponseKafkaListener class. Here first, I will implement KafkaConsumer interface from KafkaConsumer module and use PaymentResponseAvroModel as the generic type. So here I will consume PaymentResponseAvroModel as the data. Then I will mark this class as component and at SLF4J annotation to create a log variable. Then I will inject two fields, PaymentResponseMessageListener and MessagingDataMapper. PaymentResponseMessageListener is one of two input parts in the domain layer, and it has the adapter implementation in the order replication service module. Here, I just need to listen Kafka messages and trigger that adapter implementation. In the receive method, I will use Kafka annotation, which is supreme good annotation to create a KafkaConsumer from a simple Java method. Here I will set the ID as kafka-consumer-config.payment-consumer-group-id and set the topic name as order-service.payment-response-topic-name. The ID and topic name will come from the application configuration and I will set them in the next lecture while implementing the last order service module, which is the order container. Now, in the receive method parameters, I will use payload annotation for the PaymentResponseAvroModel message list, and then use header annotations for key partition and offset values. These annotations will map the parameters to the correct value coming from the Kafka. I will log an info message. For each message, I will check if the response has completed, failed, or canceled payment status. In case of a completed response, I will log a message and then call PaymentResponseMessageListener paymentCompleted method, and convert the PaymentResponseAvroModel to a payment response object to pass in the parameter. For this, I need to add a new method to do order messaging data mapper class. PaymentResponseAvroModel to PaymentResponse. Here I will create a PaymentResponse object from the PaymentResponseAvroModel using the builder of PaymentResponse. If the status is failed or canceled, I will log a message and call PaymentResponseMessageListener PaymentCanceled method. And I will use PaymentResponseAvroModel to PaymentResponse method in the mapper class to create a PaymentResponse object from the PaymentResponseAvroModel. As you see, the PaymentResponseMessageListener implementation is empty for now. I will implement it while completing the SAGA pattern in the coming sections. It is in the input parts of order application service and it needs to be implemented in the order domain layer. Then it will be called from this KafkaListener class. Now I will create the RestaurantApprovalResponseKafkaListener class and implement KafkaConsumer with generic type RestaurantApprovalResponseAvroModel. I will use component and SLF4J annotations and then inject two fields, RestaurantApprovalResponseMessageListener and MessagingDataMapper. As in the payment response listeners, here RestaurantApprovalResponseMessageListener is one of the input parts of the order domain layer and is implemented in the order application service with an adapter. On the receive method, I will use the same KafkaListener annotation and set ID and topic name with kafka-consumer-config.restaurant-approval-consumer-group-id and order-service.restaurant-approval-response-topic-name. I will use payloads and header annotations in the parameters the same way as I explained in the PaymentResponseKafkaListener. And I will log an info message. For each message, I will check if the restaurant response status is approved or rejected. In case it is approved, I will call RestaurantApprovalResponseMessageListener orderApproved method. And to get the restaurant approval response model object, here I will create a new method in the order messaging data mapper ApprovalResponseAvroModel to approvalResponse. Here I will use the builder of RestaurantApprovalResponse to set the AvroResponse fields into this new object. In case the response status is in rejected state, I will log an info message with order ID. I can also add the failure messages to the logs here. And then I will call RestaurantApprovalResponseMessageListener orderRejected method. As the parameter, I will pass RestaurantApprovalResponseModel by creating it with the MessagingDataMapper method. Again, I will complete the implementation class of listener in the SAGA section. Now, I have two things to fix in the Kafka listener implementations. First of all, the keys should be string, not long, because I use order ID as key, but send UUID, so I need to use a string key in Kafka to represent this UUID. So let's change the keys parameter and use list of string in the PaymentResponseKafkaListener. Then I will update the KafkaConsumer interface, as well. The second change I need to make here is in the RestaurantApprovalResponseKafkaListener. I need to change the topics placeholder to use order-service as a prefix instead of restaurant-service because I will use a prefix named order-service in the order config, as you will see in the coming sections. After doing these changes, let's build the project to be sure there is no compiled error. All right, I have completed the messaging components and used Kafka for the implementation. Here please note that since we externalize the messaging implementation, if you want, you can easily change the implementation from Kafka to another messaging solution. Now, in the next lecture, I will finish order service with the last module order container, which will include the Springboard main class and the application configuration. So I will see you in the next lecture.

Hi everyone. Let's continue implementing the data access adapter in classes which will implement the output parts of the domain layer. I will first go to Palm XML file and add springboard starter data JPA and PostgreSQL dependencies next to the order application service. As you see, the version of the PostgreSQL comes from the spring boot dependency, It is 42 31, so I don't need to define the version in the base palm XML file. It's already coming as a spring boot dependency. Now I will create the base package, home food ordering system, orders service, data access then create the three sub packages for each type of aggregates that I have used in the domain layer, order, customer and restaurant. I will create four sub packages in each of these packages. So, in order package I will create adapter, entity, mapper and repository. Let's copy and paste them under customer and restaurant packages also. First, I will create the JPA entities to be used in repository. In order entity package I will create order entity class and to annotate its entity JPA annotation to mark this class as a JPA entity. I will use table annotation also and give the table name as orders. I will use getter, setter, builders, NoArgs constructor and AllArgs constructor annotations. These are Lombok annotations to create getter and setter methods to create a builders and also create constructors without any parameter and with all parameters. Note that NoArgs constructor is required because spring will need the NoArgs constructor to create a prox object from this class. And AllArgs constructor is required to use the builder pattern, which builder annotation. So, that's why I used these construct annotations here. Now I will create fields and start with UUID id fields and use ID annotation to mark this fields as the primary key of this entity. Then I will create customer id, restaurant id and tracking id with UUID type. Then I will create big decimal price and then order status fields. For order status. I will use order status, value object and then I will create failure messages with string type. Then I will create an address field with order address entity and use one to one annotation using mapped by order and cascade type all. Let's create this order, address entity class. I will put the same annotations here. So, let's get them from the order entity and I will just replace the table name as order underscore address. I will create the primary key fields id and then add order fields using order entity class. I will use one to one annotation again, using cascade all and use join column annotation with order id. As you see, I used order fields, which is the name that I set on mapped by property of the annotation of one to one in the order entity. Using these one to one annotations on order entity and order others entity, I create the relation between the two tables and I said for any key fields as order underscore id. So, in the order id table I will have a column order underscore id. Since I used Cascades type all when I delete an order or the orders they will also be deleted, then I will complete order others with string postal code and city fields. I will also add equals and hashtags methods using the primary key id fields. Let's return to the order entity and add a list of order item entity using items fields. This time I will use one to many annotation and use mapped by order and use cascade type all. So, let's create order item entity. I will use the same annotations from the order entity classes and set the table name as order underscore items. I will create long id fields and create order entity order field. For this order entity, I will use many to one annotation with cascades type all and I will use join column annotation with order underscore ID column. Now I will put ID annotation on both ID and order ID fields 'cause I can only provide uniqueness of this entity with ID and order ID fields together. The long ID fields will only provide a unique item in a specific order. So, for this multi column primary key, I will create a new class, order item entity ID and use getter, setter, builders NoArgs constructor and AllArgs constructor annotations. Then I will implement serializable interface 'cause identifier class should be able to serialized when persisting the entity. Here I will repeat the id in order fields. Then I will let equals and hash code methods to this ID class. Now I will return to the order item entity class. Here I need to add ID class annotation and use the order item entity ID class here. So, this ID class annotation is required to use an ID class in an entity with multi column primary key. Then I will add the remaining fields for the order item entity. UUID, product id, big decimal price, integer quantity and big decimal sub total. I will create hash codes and equals methods using ID and order fields because my primary key consist of these two fields. Finally, in the order entity I will create, hash codes and equals methods using the ID field as it is a primary key and it's a unique UUID fields before finishing entity implementation. In this order, entity class, update the order status with enumerated annotation with Enum type string. You will see that I will create an Enum type in the Postgres database for this field and this annotation will allow me to use the Java Enum type in this field.

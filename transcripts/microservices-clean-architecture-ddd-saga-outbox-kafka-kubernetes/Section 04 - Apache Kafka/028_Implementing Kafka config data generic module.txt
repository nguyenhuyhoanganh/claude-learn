# Implementing Kafka config data generic module

Hi everyone. In this lecture, I will create a generic Kafka producer and consumer modules to use them from the microservices. So let's go to the infrastructure module and create a sub-module, Kafka. I will delete the source folder around the Kafka module. Then I will create four Maven sub-modules. Kafka producer. Kafka consumer. Kafka model. And Kafka config data. As you see, I choose the Kafka module as the parent for all of those sub-modules. First, I will go to Pom XML file of Kafka module and be sure that the packaging is Pom because this will be the base Pom for the sub Kafka modules. Then I will add Confluent repository with a repositories section because I want to use Kafka Avro Serializer dependency from the Confluent library, which is not in Maven central repository. So I need to use Confluent repository for that. I will create a dependency management section here and define the dependencies with versions in this base Pom XML file. So the sub-modules will be able to use these dependencies without setting the versions. Here I define Spring Kafka dependency with version 2.8.2. I'll also add Kafka Avro serializer dependency from Confluent with latest version 7.0.1. Finally, I will add Avro dependency with 1.11.0 version. For Kafka Avro serializer, I will add some exclusions 'cause I don't want to add these dependencies that comes with Kafka Avro serializer. I will also update the parent artifact for Kafka. Instead of using the base Pom XML file with the relative path, I will simply use the infrastructure as the parent, which is the direct parent of Kafka module. Now I will go to base Pom XML file. In the dependeny management section, I will define Kafka producer, Kafka consumer, Kafka model, and Kafka config data local dependencies with the project version. Also, I will create the Spring Kafka, Kafka Avro Serializer, and other versions here in the properties section. And then I will use them from the Kafka module Pom XML file. Let's start with Kafka config data module. In this module, I will create a Java classes that will hold the configuration data. This configuration data will be used to connect to Kafka cluster and to configure Kafka producer and consumer. I will first go to Pom XML file and only add Spring boot starter dependency. And let's create a package, com food ordering system kafka config data. And here, I will put three classes, Kafka config data, Kafka producer config data, and Kafka consumer config data. You can download these classes from the resources section of this lecture. In the Kafka config data, I have Data Configuration and ConfigurationProperties annotations. Data annotation is a Lombok annotation to add Getter Setter ToString, equals, and hashCode methods. Configuration is a marker annotation to mark this class as a Spring bean and to be loaded and injected when necessary. And finally, ConfigurationProperties is an annotation to map the configuration values from the application configuration file, like from an application yaml file, to the fields defined in this class. And this prefix kafka-config is the base configuration value that will be used to map the config data from. So basically I will have an application yaml file, and I create the order container module in the coming sections, which will include a Spring boot main class. And I will have a section in the configuration with kafka-config with these fields. Here I have bootstrap servers, schema registry url, and partition and replication factor numbers. In the Kafka producer config data class, I have the same annotations, but this time I have kafka-producer-config prefix for configuration data. And I have the producer related config data fields here. These are serializer classes, compression type, acknowledgements, batch size, Linger ms, request timeout, and retry count. I will explain these fields while setting the values for these fields in the application configuration when implementing the order container module in the coming sections. Finally, here I have the Kafka consumer config data class with kafka-consumer-config prefix. I have consumer related configuration properties here. Those are key and value deserializers, auto offset reset, specific Avro reader, batch listener, auto startup, concurrency level, timeout values for session, heartbeat, max poll, and poll intervals. And also I have max poll records and max fetch bytes fields. Again, I will give explanations for those fields with the values, when setting the configuration data in the order container module. Great. Let's continue with Kafka model module in the next lecture.

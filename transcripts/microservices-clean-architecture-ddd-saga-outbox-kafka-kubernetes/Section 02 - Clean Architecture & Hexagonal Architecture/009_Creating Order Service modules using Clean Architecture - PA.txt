# Creating Order Service modules using Clean Architecture - PART 2

Hi everyone. In this lecture I will set the dependencies between the order-service submodules. Let's start with order-domain-core. Which dependencies should I add here? Yes, that was a trap question. I should not add any dependency in the core domain because it should be the most independent and stable component, including the business logic. So, let's go to the order-application-service. For this one, again, I should not add any outside dependency. However, I will add the order-domain-core dependency here to be able to call the core logic from the application service. Then I add this readout.version and try Maven Reload. As you see, I get an error that the version is unknown for this dependency. So I need to define the version. However, I don't want to define it here. Instead, I want to manage all versions in the base pom.xml file. So, for this reason, I will go to the base pom.xml and add this dependency into the dependencyManagement section. And for the version I will use project.version which is 1.0-SNAPSHOT. So, why did I put this dependency in the dependencyManagement? Because when I put a dependency in the management section, it will help to define the dependency application light, with the specified version, without actually downloading it. When a submodule or service requires a dependency, it will add this dependency into its dependency section but the version will not be necessary as it is defined in the base Maven pom.xml file. As you see, if I click on Maven Reload again, I will not see the error. So, it would be a good idea to define all the modules with project.version in the dependencyManagement of base pom.xml file because I will need to include all these local dependencies from each other. So, I will define all of them here in the base pom.xml file. First, order-application-service. I will again use project.version properly so that I don't need to repeat the hard-coded version. Then, I will define order-application module with project.version, then order-dataaccess, and finally order-messaging. Do you think I need to put order-container also here? No. I don't need to put that here because order containers will not be used by other modules. It will simply have a dependency to all modules to create a single, runnable JAR file and run it as a microservice and also create a Docker image to use it later in cloud deployment. All right, let's continue setting the relations between modules. I was in order-application-service and I put a dependency to order-domain-core. Then I will go to data access module. As mentioned during the architectural design, this will have the adapters for the output ports of domain layer. So, it will implement the interfaces from the domain layer and it should have dependency to order-application-service. Next one is order-messaging. As you can imagine, this one will also have a dependency to order-application-service because it should implement the messaging interfaces from the domain layer. Next, I will go to order-application module. This one again, will need to import to the application service from the domain layer. Remember, that this will be the initial contact point from the clients and it should pass the request into the domain layer. So, it should have a dependency to order-application-service. Finally, order-container, will have a dependency to all modules, to get to all dependencies, and create a single runnable JAR file that will run the order microservice. So, here I will have order-domain-core, order-application-service, then order-application, dataaccess, and messaging dependencies. Let's once run mvn clean install command to see there is no issue with dependencies. Great! Now I want to visualize the module dependencies so that we can double check if we set them correctly. I will use depgraph-maven-plugin. I can use it as a single command but, to run this single maven command, first, please go and install graphviz on your machine which is a graph visualization software. The Maven plugin will use this plugin under the hood. Please download and install this according to the installation steps mentioned on graphviz.org's download page. After that, simply run this Maven command with the depgraph Maven plugin. Use aggregate call and create an image. I put this command in the resources of this lecture. You can download. As you see, I set the plugin in the commands and gave the group ID of my project which is com food-ordering-system. This will create an image in the target folder, and if I click on that, I can see that the dependencies are set correctly. As you see, all arrows are towards the domain logic module. Specifically, we have dependency to order-application-service from all other modules and have a dependency to domain-core from the application-service. And the important parts here is that the domain-core is the most independent component in this picture. All right. Great job so far.

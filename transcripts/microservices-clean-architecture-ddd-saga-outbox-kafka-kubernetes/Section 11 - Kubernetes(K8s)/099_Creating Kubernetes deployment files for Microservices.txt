# Creating Kubernetes deployment files for Microservices

Hi everyone. Let's continue running the services on the local Kubernetes cluster. Remember, in each microservice, I already added the spring-boot-maven-plugin with build image goal. Thanks to this plugin. When I run Maven clean install command, it'll create the Docker images with these specified names in the POM XML files. As you see, I have the Docker image names here using project groupId and project version. Let's run Maven install command and create these Docker images in local Docker registry. After successful build, I will use Docker images command to see the newly created Docker images. Now that I have the Docker images, I can create Kubernetes deployment files. To deploy these images on local Kubernetes cluster, I will go and create a new YMAL file, application deployment local. In the food-ordering-system-infra project, I will create all four services deployment in the single file. Let's start with the order service. I will set the apiVersion as apps/v1 which is the correct version for a deployment. And here, the kind is Deployment. And then, under metadata property, I will set name as order-deployment. Use default namespace. And also, sets up label as order-deployment. As I mentioned, the default namespace is the one that I will use for Kafka cluster and for the other services. Here, the label is used to link the deployments to container spec and to service definition. I will continue adding a spec with a selector with matchLabel, order deployment. So, this spec is linked to the order-deployment. Then I will create the template definition with order-deployment label as metadata. And then, I will add the containers spec with name order-service and with Docker image definition of the order-service. I will get the Docker image name in the project version from the Docker images command output. For the environment variable, I will set the data source URL Kafka config bootstrap servers and also the schema registry URL. For data source URL, I will set SPRING_DATASOURCE_URL with underscores, and point it to host occur internal, which actually connects to the host of the Docker, which is the localhost for my laptop. So, I will connect from Kubernetes ports to the Postgres running on my machine. Please note that I will also run Postgres on Kubernetes using its Docker image in the next lecture, so that it will be easy to deploy everything on Google Kubernetes engine. I will use local-confluent-kafka-cp-kafka-headless 9892 for the Bootstrap servers as it was mentioned in the response of to uninstall commands for Kafka cluster. And I use local-confluent-kafka-cp-schema-registry at port 8081. Again, this is the default hostname created using the hand shots. Note that when I deploy these application to Google Cloud, I will use these environment variables to update the values for Bootstrap servers and schema registry. Then, I will add resource limits for this port. 500 millicpu limit... and 200 millicpu requests. So this part will request 200 millicpu at startup, however, it can go up to 500 millicpu. I can also add memory limits here. 1024Mi as the limit and 256Mi as the requested memory. Here in this page, you can check about the details of the meaning of these limits. A mebibytes and megabytes are often used synonymously, however, mebibytes is introduced to give a more precise measurement unit and leave the megabyte as a rough calculation using the 1,000,000 bytes instead of having the exact value. Okay, I have completed the deployment definition for order microservice. Next, I will create a service definition with apiVersion v1. For metadata, I will set the name as order-service and set the default namespace. Then, I will set label app order-service. Then, I will set a selector spec for order-deployment, so that I will bind this service definition to the order deployment. And then I will set the ports which name order-service port, protocol, TCP, and port, 8181. For the type, I will use LoadBalancer. And leave the loadBalancerIP as empty. So here, instead of setting a node port, I use a load balancer which will allow me to create multiple instances and Kubernetes will do the load balancing to my instances automatically. It is not that I will be able to access to this order service using localhost because Kubernetes on Docker desktop uses localhost as the default machine name. Now I will create similar deployment and service definitions for the other services. I will put that definitions and go over them. As you see for payment service, I just have the payment prefix for the deployment's name and for container name. Here, I have the Docker image definition for payment service. I use the same environment variables for data source, Kafka Bootstrap servers and schema registry. I will only change the schema name to payment. I have the same resource limits. And in the payment service, I have the payment-deployment label to make the binding from service to deployment. And for the port, I have 8182 this time for the payment service. Again, I set the type as LoadBalancer, to create a load balancer for multiple instances of this payment service. For restaurant service, again, I have this similar config. I set the correct Docker image and use 8183 as the port and I use restaurant schema for data source. Finally, for customer service, I have the customer service Docker image and I use 8184 as the port with the LoadBalancer. And I use customer schema for the data source connection string. Here, I have some mistakes on order service. I need to set the Postgres hostname to host.docker.internal because as mentioned, I will connect to Postgres that is running on my host machine and the current database should be Postgres. Also, I have a typo in Bootstrap servers environment variable, this should end with a S. Please note that you may find this deployment YAML file in the resources section of this lecture. Now, I will deploy the services in the Kubernetes cluster. I will do that in the next lecture.

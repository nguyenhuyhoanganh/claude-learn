# Deploying Postgres to local Kubernetes using Postgres docker image

Hi everyone. In this lecture, I will run Postgres in Kubernetes using the Postgres docker image. After doing this, I will have all required components of my application on Kubernetes, and in the next section I will be ready to deploy the application to Google Kubernetes engine. Now I will go to Food Ordering System Infra Project and create a new Kubernetes deployment file, Postgres deployment. In this file, I will have both deployment and service definitions for Postgres. First, I will put the deployment definition here and explain it. This will be a similar file to the application deployment. Here I have a deployment kind and the metadata is set using Postgres dash deployment name and with the default name space as was in the application deployment file. Then I have a selector and template definition, and in the container spec I have the latest Postgres stocker image and in the environment variables, I set the default password as admin. Then I have this service definition. Again, this is very similar to the services in the application deployment file. I have named Postgres service and type load balancer with port 54 32, and I use Labels app to bind this service to Postgres deployment. Now, I will simply run Cube CTL, apply commands for this Postgres deployment file. Then I will open a new terminal and go to Helm package to run Kafka cluster using Helm install commands. Let's wait until all Kafka cluster ports are running. Then I will run my application services but first I will update the data source you are at and use Postgres service as the host name so that they will use the Postgres running in Kubernetes. Now I can run cube CTR apply commands for application deployment file. Let's check the logs of one of the services. I will look into the order service logs. As you see, it started successfully. So that means it can connect to the Postgres in Kubernetes. Now in Postman, first I will create the customer, and then I will create an order. Let's check the tracking ID in the gate API. As you see, first it is paid and then Aprils after Saga flow is completed. Great, so I use the Postgres in Kubernetes next to Kafka cluster and application services. All right, so in the next section I will start using Google Clouds and deploy my application to the Google Kubernetes engine. So I will see you in the next section.

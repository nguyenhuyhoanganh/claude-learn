# Introduction to Kubernetes and running a local Kubernetes using Docker Desktop

Hi everyone. In this section, I will make a quick introduction to Kubernetes and create and run a local Kubernetes cluster. In the coming lectures, I will deploy Kafka microservices and Postgres into Kubernetes. So at the end of this section, I will be able to run all components of food ordering system application in local Kubernetes cluster, including Kafka and Postgres. To run Kubernetes locally, I need minicube or Kind. I will use Docker Desktop, which internally uses Kinds to enable Kubernetes. With Docker Desktop enabling and running Kubernetes is quite easy. However, it is not that if you are not using Docker Desktop for personal usage with version four and a ball, you need to have a license for Docker Desktop. Here is the link to the Docker Desktop version 3.6. You can also find the link in the resources section of this lecture, so it is version three. You may use Docker Desktop to run a local Kubernetes cluster. Now I will go to Docker Desktop preferences, Kubernetes, and then check enable Kubernetes. After pressing apply button, Docker Desktop will start and configure the Kubernetes cluster for me. Please ensure that the Kubernetes manual item is shown and the context is set to Docker Desktop. Then I will open a terminal window and try a basic Kubernetes command, Kubectl get nodes. This command should return a ready status for the master nodes, which name Docker Desktop. It is not that the default host name for Docker Desktop is local host so it is also local host for Kubernetes. Kubernetes is an open source container orchestration system. It allows automating software deployment, management, and scaling. It is originally developed by Google, but currently Cloud native competing foundation, maintains the project. Let's see, some basic Kubernetes concepts. Nodes are the physical servers or virtual machines that creates a Kubernetes cluster. Pods are the smallest unit of execution in Kubernetes. They are deployable units and consist of one or more containers, which internally consist of one or more application. Controllers. In Kubernetes to deploy, manage, and scale ports, you use controllers. You will see how to create a deployment controller using a YAML file in the next lectures. Services are used to expose deployments through NodePort or LoadBalancer. A NodePort exposes the service on a static port on the node IP address. NodePorts are in the 30,000 and 32,767 range by default. So it is unlikely for a NodePort to match a service port. As you see, I use ports as 81, 81, 81, 82 and so on in the services. But when I expose them in Kubernetes I will use this NodePort range. When you expose your services, you also need to ensure external IP of your system points to the nodes and firewall rules allow access to open the node ports. You will see how to use NodePorts in Kubernetes configuration YAML file in the next lectures. If you use multiple answer Kubernetes automatically load balance the requests to your instances. Basically, I will create deployment and service definitions in the YAML format, and I will define the docker images which requires environments in the deployment part and then define container parts in the services part. In the end, I will use labels to bind the deployments and services. This will be the Kubernetes configuration file for order service and to deploy this file I will use Kubectl apply commands with minus F order deployment YAML parameter.

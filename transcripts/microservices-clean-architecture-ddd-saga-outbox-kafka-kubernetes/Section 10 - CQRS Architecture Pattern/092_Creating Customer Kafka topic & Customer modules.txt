# Creating Customer Kafka topic & Customer modules

In this lecture, I will start updating the customer service and create the modules to enable creating of a customer through a post API. In the end, I will have the same clean architecture in customer service as in the other services. So I need to have the domain layer and the infrastructure layers to implement the input and output parts that are defined in the domain layer. Now in this lecture, what I want to achieve is to create a duplicate customer table in the order service. Remember that I had the customer table in the customer service and I was using a materialized view to serve the customer information, and in the order service I was using a database call to this materialized view which is in customer service database. So for this, I had the customer schema I defined in the JPA entity definition as you see here. Instead of doing this cross database call, I will make a call to a local customer table in order service. But to do that, I need to keep this customer table up-to-date when customer table in the customer service is updated. To achieve this, I will use CQRS pattern and while updating customer information in the customer service, I will publish an event in a new Kafka topic and then (indistinct) these events from order service to insert the new customer information in the order database. Therefore, I need a new Kafka topic and for that, I will go and update the init Kafka YAML file in the infrastructure module. I will add a new statement to create a Kafka topic named customer. And to define the schema of this customer Kafka topic, I will go to Kafka model module and create a new auro schema file, customer AVSC. Here I will define the name space which is the Java package name and set the class name as customer auro model. I will keep the fields as simple and I will have UUID and three string fields for customers username, first name and last name. Now, if I run (indistinct) install commands in Kafka model module, the auro may look like it will create a customer auro model class for me. As you see, the new auro model is created for customer here. Great, now I will create the modules in the customer service. Now in the customer service application class as in the other services like in order service Spring Boot's main class, I will enable JPA repositories and entity secure annotations with the base packages properly. I will use customer package here. Remember that these annotations are necessary when you have JPA repository and entities in different modules. I will also move the application YAML in its schema and in its data SQL files. In the application YAML, I will the add Kafka topic name using customer service, customer topic name, property. Remember that Kafka topic name is customer. In the application YAML, I will let the Kafka and Kafka producer configuration as in the order service because now I will publish an event into Kafka from customer service.

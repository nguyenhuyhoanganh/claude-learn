# Updating Order Service to use local database table with CQRS pattern

Hi everyone. In this lecture I will complete the CQRS pattern by adding the Kafka consumer implementation to the order service. First, I will go to the order container module, and updates application YAML file. I will add customer topic name as customer under the order service config. Also, I will update Kafka consumer config. and add customer group ID property with customer topic consumer. Then in the int-schema.sql file, I will add a new create table statement for customers table. I will create the customers table in the order schema and use the same fields of the customer table in the customer's schema. Then I will go to the order domain core module and update the customer entity. I was only using customer ID in this class, just to check the existence of a customer, but now I will need the username, first name, and last name fields to create the customer object. I will add a new constructor with these four fields. And also I will leave the previous constructor with the customer ID property. Then I will add getter methods for the new three fields. Next, I will open all the application service module. In the DTO message package, I will create customer model class. Here, I will add the required four fields: ID, username, first name, and last name. I will add Lombok connotations, getter, builder, and all args constructor also, and I will go to the order data mapper, and add a new method, customer model to customer. Here, I will create a customer domain object from the customer model. I will simply use the constructor of customers to create objects and use customer ID value objects with UUID from string methods for the customer ID field. I will then go to ports package, and in the output ports I will update the customer repository. Now, here I will need a save methods with customer domain object parameter and return a customer object. I will use this to persist the customer object into database. I will create an input force under message listener package with interface customer message listener. I will first create a package customer and create this interface. Here, I will add customer created methods with parameter customer model. This is an input port, so, it needs to be implemented here in the domain layer. So I will create customer message listener input class, and implement customer message listener. I will use SLF4J and service annotations here. Then inject two fields: customer repository and order data mapper. In the customer created methods, I will call customer repository save methods, and for the parameter I will use order data mapper customer model to customer method to create a customer domain object from the customer model. If the returned customer object is null, I will load an error message and drop an order domain exception here. Otherwise, I will just load an info. message. Now, in the order data access module, I will update customer entity. As you see, I was using the materialized view from customers schema, but now I will use table name customers without the schema customers 'cause this new customers table is in the order local database. And I will also add username, first name, and last name fields. Next in the customer data access mapper class, I will add a new method, customer to customer entity. Here, I will create a customer entity from the customer domain object, and I will simply use customer entity builder methods and set ID, username, first name, and last name. Finally, in the customer repository input class, I will implement the new save methods from the customer repository. I will just call JPA repository save method and use data access mapper to create JPA entity from the customer domain object, and also for the returned object. I will use customer data access mapper to do the conversion from JPA entity to domain object. Finally, I will go to the order messaging module. And in the messaging data mapper class, I will add a new method, customer Avro model to customer model. Here, I will take a parameter customer Avro model and return a customer model object. I will use builders and set all fields of a customer object. Then I will create a new class, customer Kafka listeners, under the listening package. Here, I will add SLF4J and component annotations, then implement Kafka consumer interface from Kafka consumer module. I will use customer Avro model as the generic type. This is the Avro model for the new customer topic. Here, I will inject two fields: customer message listener and messaging data mapper. In the receive methods, I will add Kafka listener annotation, it's ID Kafka consumer config., customer group ID, and topics order service, customer topic name. Remember that I set these properties in the order container application, YAML file. I will add the payload and headers annotations for the parameters as I did in the previous Kafka listener implementations. In the implementation, simply, I will load an info. message and then for each message I'll call customer message listener, customer created methods. For the parameters, I will use data mapper, customer Avro model to customer model method to convert customer Avro model to a customer model object. And as you see in the message listener impl I simply persist the customer object in the order service local database using the customer repository which internally uses JPA repository to complete the persist operation. Let's also add an explicit transactional annotation to the save method To make it clear that here we persist the data into database using a transaction. As a final change, now I will go to the order application service test and update the code to set the customer ID as a parameter to the customer constructor. Great, I have completed the changes in the order service to list in the customer created events and update its local database. As you see, when you follow the clean architecture principles it is easy to update any service because you will know where to change and how to make that change. Alright, in the next lecture I will build the project, and then run customer and order service to test the results of CQRS pattern. I will see you in the next lecture.

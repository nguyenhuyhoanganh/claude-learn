It also triggers a rollback in the payment service, which is actually the related compensating operation of saga flow. Remember, first I finalized the payment, and then sent the order to restaurant to finalize. Since the restaurant is rejected this order, the payments needs to be rollbacked and compensated, and I see this rollback operation in the payment service logs. This rollback is actually triggered from the order service, which is the coordinator of this saga flow. As you see in order service, after canceling the order in local database, it persists an outbox message to send an order canceled event to the payment service. This is done in the order payment saga rollback methods in order service, which is the implementation of the compensating transaction for this saga step. And the outback message is read by the scheduler and sent to Kafka. And then payment service consumes this outback message and process the rollback of payments.

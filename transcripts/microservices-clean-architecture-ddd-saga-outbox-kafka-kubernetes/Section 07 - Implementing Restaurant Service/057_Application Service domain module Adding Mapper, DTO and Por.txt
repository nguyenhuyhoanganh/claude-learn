# Application Service domain module: Adding Mapper, DTO and Ports

All right, in the restaurant application service, first, I will go to pom.xml file and add restaurant-domain-core and common-domain dependencies. I will also add spring-validation and spring-transaction dependencies, because, as usual, I will do the validation and transaction management here in the application service. To be able to use the restaurant-domain-core and other restaurant dependencies without specifying the versions, I will go to base pom.xml file and add the four restaurant module dependencies with project.version, domain-core, application-service, dataaccess, and messaging. Then, I can use domain-core dependency without version here. I will create the base package, com.food.ordering.system.restaurant.service.domain, and then create the sub-packages, config, dto, exception, mapper, and ports. In the config package, I will create RestaurantServiceConfigData class and use @Data Lombok annotation, then use @Configuration and @ConfigurationProperties annotations. This is the similar config class that we have created before for payment and order services. I will use "restaurant-service" prefix here, and it will be the prefix that I will use in the application.yml file of restaurant container module. Here, I will have two string fields, for request and response Kafka topic names for restaurantApproval. And I will go to exception package and create RestaurantApplicationServiceException and extend DomainException from common domain. Again, this class is similar to the ones in payment and order services. Now, in the mapper package, I will create RestaurantDataMapper class. I will use @Component annotation and make this class a spring-managed pin. I will come back and write mapper methods here, as in the other mapper classes. This class will simply be my factory class that will create the domain objects from the input objects and also create the output objects from the domain objects. Let's go to dto package, and create RestaurantApprovalRequest class. I will use @Getter, @Builder, and @AllArgsConstructor annotations. As I mentioned previously, these annotations are Lombok annotations. That's how to get rid of boiler-plate Java code. Here, I have four string fields for identifier fields: id, sagaId, restaurantId, and orderId. Then, I have restaurant order status field; and for this, I will go and create a new value object with an app type in the common domain module, because I will use this class in order service, as well. I will only add PAID option here, because I only trigger restaurant approval service with a paid order, and this status will actually represent the requested order's status. Remember, for the response object, I will have order APPROVED and order REJECTED status values. Then, I also have a list of products and a price BigDecimal field, and then the Instant createdAt field here. Then, I will go to the ports package. Here, I will create input and output packages. Remember, input ports will be implemented here in the restaurant application service, and the output ports will be implemented in the infrastructure modules, like in dataaccess and messaging. In the input package, I will create message.listener package and create RestaurantApprovalRequestMessageListener interface. Here, I will add approveOrder order methods with RestaurantApprovalRequest parameter. Then, in the output package, I will create message.publisher and repository sub-packages. In message.publisher, I will create OrderApprovedMessagePublisher interface and extend DomainEventPublisher interface with OrderApprovedEvent, generic type. Then, I will create OrderRejectedMessagePublisher interface and extend DomainEventPublisher, this time with OrderRejectedEvent as the generic type. In the repository package, I will create OrderApprovalRepository interface, and add same methods with parameter OrderApproval domain-object and return the same object as the response. Then, I will create RestaurantRepository interface and create findRestaurantInformation methods. I will return an optional Restaurant domain-object here and use Restaurant domain-object as the input parameter. Now, I will start implementing the input ports here. I will do that in the next lecture.

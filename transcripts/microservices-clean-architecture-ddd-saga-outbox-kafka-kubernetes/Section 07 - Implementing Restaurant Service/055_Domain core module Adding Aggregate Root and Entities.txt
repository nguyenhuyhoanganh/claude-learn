# Domain core module: Adding Aggregate Root and Entities

Hi everyone In this section we will complete the final microservice in our application, restaurant service. As you can remember, the restaurant service will approve an order after the payment is done, so it is the final step to complete an order. If approval is completed in this service, order service will get an order approved event, and complete the order process. Please note that this implementation of restaurant service will be similar to the order service, and payment service implementations following clean and hexagonal architectures, and applying domain driven design concepts As I mentioned in the payment service If you are confident about these concepts, you may prefer to skip the restaurant service section, and continue with the next section, which is section eight, with saga pattern. You can get the source code of restaurant service in the first lecture of the section or can get it by cloning the GitHub Project, as explained in lecture five, providing the source code. I will create the restaurant service as a Maven module, under Food Ordering System. I will delete the source folder, Then let's start with creating the modules. I will create four Maven modules under restaurant service. First, I will create restaurant domain module. As you see, I choose the Maven project, and set the name, and then leave the group and artifact ID as it is. Similarly, I will create restaurant container, restaurant data access, and restaurant messaging modules. Remember that I choose to use two more sub modules under domain module for domain core and application service. So I will delete the source folder in the restaurant domain module, and create restaurant domain core Maven module. And then create the restaurant application service module under restaurant domain. As usual, I will start with the implementation of domain core, which will be the most independent module. In the Pom XML file, I will only add a dependency to do common domain. I have only this dependency in all of the core modules, and it has the common domain core classes and interfaces. Now, I will create the base package, com food ordering system restaurant service domain, and create sub packages entity, event, exception, and valueobject. Let's start with entity package. First, I will create an entity called Order Approval, and extend base entity with order approval ID generic type. So I need this order approval ID value object, and I will create it in the value object package by extending the base ID with UUID type. Here I will use public constructor. In order approval class, I will create RestaurantID, Order ID, and OrderApprovalStatus fields. Remember, these are common value objects that we have created in the common domain module. I will let add the getter methods here, then create the Builder using the inner builder plugin of IntelliJ. I will rename the generic ID with order approval ID, and then use the set ID methods in the private constructor. As I did previously, I will also rename this static builder method from new builder to builder. This approval entity will be the result of the business logic checks on the restaurant service. Then I will create a product entity. Here I will extend base entity with product ID generic type. Here I use a different product entity, than the one in the Order service. In Order service, I had only name and price, so it's a projection of a product, but here I will have more details about the product. So I will add name, price, quantity, and available fields, and then create the getter methods. Then I will create Builder using the inner Builder plugin. Again, I will replace the ID with product ID, and use setId methods to set the ID, and rename the newbuilder method to builder. I will create a method here called update with confirmed name, price, and availability. And simply update the name, price and available fields. I will call this update method from the domain service to set the value of a product from the database. Let's make this quantity field final because it can be a final field as I don't set it with any methods after creating the object. Then I will add order detail entity, with order ID generic type. Here, I will add three fields, order status, total amount, and final list of products. I will add getter methods, then I will create the builder using inner builder plugin. I will replace the ID with order ID, and use the setId method to set the ID, and then use builder for the method name for this static new builder method. Finally, I will add to aggregate root, Restaurant. I will use Restaurant ID as the ID type for the generic type here. Then I will add order approval, active, and final OrderDetail fields. Again, I will create getter methods, and then create the builder here, and use restaurant ID in the builder, and then set the ID in the private constructor. I will add validateOrder method here, with failure messages. First, I will check if the order status is paid by getting the status from the order detail field. If not, I will add a failure message here, and I will get the products from the orderDetail object, and check the availability of a product. I will update the failure message list for any product that is not available. Also, I will calculate the subtotal of an item by multiplying the product price and quantity, and in the end I will add up all the subtotals, and get a total amount using the reduce method, here as you can see. Here, I started with money zero, and use money add method to get the final total. In the end, if the total amount is not equal to the orderDetail total amount, I will add a new failure message. Then I will add another method here, constructOrderApproval. In these method, I will create an OrderApproval object using the builder. I will set a random UUID for the OrderApprovalID, then set restaurantID with getID methods. And then set the orderID getting the value from the OrderDetails object. Finally, I set the OrderApproval status using the parameter of this method. I will also add setActive method here to be able to set the restaurant as active. I also renamed the static builder method from newBuilder to builder here. Alright, aggregate roots and entities are completed. I will continue with exception, domain events, and domain service implementations in the next lecture.
